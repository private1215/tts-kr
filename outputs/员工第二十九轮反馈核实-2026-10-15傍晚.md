## 三、🔴🔴 找到「卡顿」的第二个、也是更根本的来源

### 停顿段**内部**的电平起伏（真人 vs 合成）

| | 停顿段内起伏 σ |
|---|---|
| **EL 标杆（6cdd，751 段）** | **7.26 dB** |
| **EL 标杆（8197，807 段）** | **7.30 dB** |
| **旧 VoxCPM（706 段）** | **7.35 dB** ← **与 EL 完全一致** |
| **OmniVoice + declick（709 段）** | **2.62 dB** ← **掉到 1/3** |

🔴 **真人停顿里有丰富的环境起伏（≈7.3dB），而 OmniVoice 只有 2.62dB。**
我们的停顿"太安静、太死"——听感上就是**顿、假、卡**。

### 排除了我的修复
declick 处理前后对比：
```
declick 离线处理版   σ=2.71 dB
declick 前（原始）   σ=2.69 dB
```
→ **declick 没有造成这个问题**，它是 OmniVoice 自带的。

## 四、🔴 这个发现推翻了上一轮换引擎的决定

**关键数据**：**旧引擎 VoxCPM 的停顿起伏 7.35 dB，与 EL 标杆 7.26/7.30 几乎完全一致。**

而第 26 轮换引擎时，员工给出的理由是「电子合成感」（3/3 一致），
第 27 轮换完后两人答案相反（「换之后更自然」vs「差不多」）。

现在看来：
- ✅ **换引擎修对了"硬切"**（declick 后硬切 10 → 0）
- ❌ **但换错了引擎**：VoxCPM 的停顿起伏本来就和 EL 一样，
  OmniVoice 反而丢了 2/3 → **"卡顿"的根因是换引擎带来的，不是原有的**

### 所以真正的修法不是回滚引擎，而是**给停顿补环境起伏**

在停顿处叠加低频起伏的环境声（不是恒定噪声，而是
像 EL 那样的缓慢起伏）——这正是我 `declick` 该做但没做的事：
现在填的是**恒定的 −70dB 噪声**（内部起伏 = 0），
而 EL 是 **7.3dB 起伏的环境声**。

## 五、下一步（唯一可执行方向）

🔴 **改进 declick：填充的噪声要有起伏，而不是恒定**

- 现在：恒定 −70dB 噪声 → 起伏 0dB
- 目标：模拟真实环境起伏 **7.3dB**
- 方法：填 **1/f 粉噪**（天然有低频起伏），
  或叠加极慢的正弦调制（0.5~2Hz）模拟空调/人声背景

⚠️ **风险**：起伏做过头会让停顿听起来"沙沙"，
必须对照 EL 的 7.3dB 校准，**不能超过**。
