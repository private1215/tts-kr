## 二、三条硬结论

### 1. 「250Hz −0.45dB」到平台期了，别再磨这个量级

第 2、3 题员工**全部选「差不多 / 说不清」**。0.45 dB 的宽带增益差在
人耳可辨阈以下——**既没听出变好，也没听出变坏**。

这意味着该维度已经进入「不比原状好、也不比原状差」的平台。
继续在 0.4~0.8 dB 之间微调是**无效功**，机器分再动也换不来听感。

### 2. 🔴🔴 「闷 / 感冒鼻塞」的根因**不是** 150~300Hz 能量

这是我们这轮最重要的发现：

- 该频段已从 **+3.96σ（能量过多 = 闷）** 压到 **−3.08σ（偏少 = 薄）**；
- 员工**照样选「还是闷、像感冒鼻塞」**。

低频已经减过头了，听感却一点没变 → **「闷」不在这条轴上**。
男声现在唯一超门槛的反向维度是 **平坦度 −2.61σ（频谱过平 = 过干净 = 发闷/发假）**，
这是下一轮该攻的方向。

### 3. 与 EL 标杆的差距仍在，两个位置都输

第 4 题（中段 120s）和第 5 题（开头 40s）员工都选 EL。
Σz² 23.1 是男声近期最好成绩，但**距离「直接发客户」还差一口气**。

## 三、第一题为什么失效（已修）

员工上报「B 选项没有音频」。逐层排查：文件在 ✅、路由 HTTP 200 ✅、
Range 206 ✅、响度 −27.3 dB ✅、逐秒 RMS 无静音 ✅、编码参数与 EL 切片
完全一致 ✅——**文件层面没有任何问题**。

真因在出题脚本 `deploy/mk_n21.py`：

```python
("n_ctrl1", NEW, 120.0),
("n_ctrl2", NEW, 120.0),   # 控制题：同一段放两遍
("n_new",   NEW, 120.0),   # 🔴 与控制题同素材、同起点
```

三条同源同起点、同参数编码 → **三个文件 md5 完全相同**（`3e11387a…`）。
页面上 A、B 是字节级同一个文件，而且**还跟第 2 题的 A 撞车**，
看着就是「B 没做成、直接复制了 A」。

**修法**（`deploy/mk_n21b.py`，已执行）：

1. 控制题换到**第 80 秒**（第 2/3/4 题用 120s、第 5 题用 40s），素材不再撞车；
2. ctrl1 / ctrl2 仍用同一段素材（控制题语义必须：两段一样快 → 选 C），
   但用 `-metadata title=` 让两个成品**字节不同**。

修后：`n_ctrl1=3d9ed8e2` / `n_ctrl2=46cea5b8` / `n_new=3e11387a`，三者互不相同，
LUFS 均 −26.6、mean −27.1 dB。

> 已写进出题铁规则：出题脚本跑完先 `md5sum` 自检，撞了就是废题。

## 四、本轮顺带做的一件事：底噪频谱斜率（**已证伪并回退**）

发现「底噪频谱斜率」是一条独立于电平的自由度后（RMS 不变、voiced 不动，
只改 flat），按女声陡、男声平两个方向各试了一次，**端到端双双翻车**：

| | 离线预测 | 端到端实测 |
|---|---|---|
| 男声 −1.5 dB/oct（更平） | Σz² 23.1→17.3、flat −2.61→−0.92 | Σz² **23.1→32.4**、flat 只动 0.18σ |
| 女声 −6.0 dB/oct（更陡） | flat +4.54→+0.65 | flat **+2.91σ→+3.85σ**（方向反了）、Σz² 26.2→32.2 |

男声做**受控实验**（同一篇成品只换底噪）当场露馅：旧篇说 −1.5 好、
新篇说 −3.0 好，两篇结论相反。根因是「成品减复现噪声」不成立——
线上 `roomtone._rng` 是模块级全局，状态会被之前的任务消耗，
我减掉的根本不是实际叠加的那段噪声。

**已全部回退到已验收配置**：女声 −62 dB、男声 −56 dB，两性别斜率均 −3.0（粉噪）。
接口（`slope` 参数 / `slope_for`）保留在代码里，等拿到当前链路真实的
无底噪中间产物再重做。
