# 断句碎：根因分析与可选路线（2026-09-30）

> 前三轮回归（r1~r4）把音高、语速都修好了，只剩「断句碎」没解决。
> 本地实验手段已用尽，本轮引入外部资料（官方仓库 / Issue / 论文）定位根因。

---

## 0. 一句话结论

**断句碎不是配置问题，是 AR 模型架构的固有特性 —— 停顿是"涌现"出来的，没有开关可关。**
官方 Issue 和论文都确认了这一点。所以不要再在参数上打转，
只剩两条路：**改参考音频的节奏（让模型学对）** 和 **后处理对齐（强行修）**。

---

## 1. 已排除的假设：文本前端切分

采集到的资料指出 CosyVoice 的 `split_paragraph()` 会按 `token_max_n=80` 切分，
且韩文（AC00–D7A3）不含中文字符 → 走**英文分支**（按 BPE token 数切，比中文碎）。

**但我们实测排除了这条**：

```
cosy_server.py:178   text_frontend: bool = Field(False, ...)
```

我们一直用 `text_frontend=False`，CosyVoice 的文本前端（含切分、normalize）**根本没执行**。
实测数据也对得上：1999 字只切成 7 段交给模型，而 VAD 检出 95 句 ——
**句数是模型自己产生的，不是切出来的**。

⚠️ 顺带确认一个隐患：服务器上 **`ttsfrd` 未安装**。
如果哪天把 `text_frontend` 打开，韩语会走英文 normalizer + inflect 数字拼读，
韵律大概率会更糟。**保持 `False`**。

## 2. 根因：AR 模型的停顿是涌现的，不可控

| 来源 | 结论 |
|---|---|
| CosyVoice Issue #1079（官方） | 「停顿是大模型自己推断的，**没有好的干预方式**」；官方文本切割"挺随意，很多符号都能切分，导致断句问题很大" |
| CosyVoice Issue #1176（官方） | 对异常长停顿，官方给的方案是**检测 + 重生成**，不是参数 |
| Flamed-TTS（arXiv 2510.02848） | **NAR 模型**（FastSpeech 系）时长是回归出来的，天然不产生自发停顿；**AR 模型**（CosyVoice / Qwen3-TTS 都是）"pauses emerging spontaneously"，时间多样性接近人，**也因此不可控** |

→ 这解释了为什么我们试 `max_chars`/分段字数/静音压缩/删停顿全都无效：
**在跟一个没有该开关的模型对话。**

### 韩语额外的难处
韩语韵律是 **AP（악센트구）/ IP（억양구）双层**结构，与中英文不对齐（Yoon 2004 / K-ToBI）。
论文在 300 句上交叉验证：AP 断点 F=72.8%、IP 断点 F=71.3% —— **韩语短语边界本身就难预测**。
推测我们的合成是把 **AP 边界误当成了 IP 边界**（每个 AP 后都给了 IP 级别的停顿）。
另外 CosyVoice3 论文的 CV3-Eval 里韩语 WER=4.01，韩语不是它的强项语种。

## 3. 可行路线（按性价比排序）

### 路线 A：改参考音频裁剪标准 ⭐ 推荐先试

**依据**：arXiv 2304.11976 的 Table 4 给出量化证据 —— 把 duration predictor 条件化在
**另一个说话人的参考语音**上时，生成语音的 speaking rate 会**跟随参考语音**；
节奏迁移偏好测试 HuBERT 90.7% vs x-vector 9.3%。
即：**参考音频的节奏/停顿风格确实会被克隆过去。**

**这解释了我们之前的实验结果**：
- 换高动态参考 → 男声动态修好（−28.4% → −1.4%）
- 但女声崩了（26 → 67 句）

因为换参考音频同时换了**音色、音高动态、节奏**三样东西，三者耦合。
`EL_female_dyn` 那段大概是"高动态但本身就很碎"，模型就把碎节奏学过去了。

**正确做法**：裁剪标准从"最清晰 / 最高动态"改成
**「内部无长停顿、一口气说到底的最长连续段」**（播报体的长呼吸群），
并且把"音色最优段"和"节奏最优段"**分开挑、分别评估**，不要混在一个指标里。

- 成本：低（只改选段脚本 + 重跑回归）
- 风险：低，不动生产代码逻辑

### 路线 B：后处理按原声结构对齐 ⭐⭐ 最有把握做到 1:1

**依据**：Amazon 配音论文（Sharma et al., 2021）—— 做 isochrony 等时对齐拆两步：
① 把目标句切分成 phrase，使其**复现原说话人的 speech-pause 排布**；
② 在 phrase 级别**调整语速**匹配每个源 phrase 的精确时长。
论文证明 **post-segmentation**（先整句生成再按 attention 对齐）比 pre-segmentation 更流畅。

我们还有一个天然优势：**同文本**，连翻译长度差异都没有，只剩"分段 + 逐段时长对齐"。

**落地形态**：
1. 从案例原声跑 VAD/强制对齐，拿到真实的 **phrase 边界 + 每段时长**
2. 按这个边界重切文本，作为喂给引擎的 chunk
3. 每段生成后，用 WSOLA/PSOLA 做 **≤±15%** 的时长微调贴回原声对应段
   （火山引擎工程经验：超过 15% 就开始发闷发急；我们 speed 0.9 = 10%，在安全区）
4. 段间静音按原声**实际 pause 时长**插入，而不是用模型自己的

- 成本：中（要写对齐 + 时长规整）
- 收益：同时解决"句数太多"和"句内动态不足"

### 路线 C：波形域精准删静音（补路线 B 的残留）

**依据**：IndexTTS2-PauseControl 的两遍法 ——
**「停顿的位置由标点决定（可靠），停顿的时长由模型采样决定（不可靠，CV 0.31~0.56）」**。
做法：第一遍靠标点让模型定性产生停顿；第二遍在**波形域**用能量检测找"静音核心"，
用 Needleman-Wunsch 把标记与实测停顿**全局对齐**后再逐点延长/缩短，实测平均偏差 13ms。

**这解释了我们"删短停顿反而更差"的失败原因**：
我们之前是**无对齐地全局压缩静音**，正确做法是**按位置对齐后只删"静音核心"、保留过渡**，
必要时对删除点两侧窄窗口做一次交叉淡化。

⚠️ 该仓库还给出一个否定性结论：**LLM 语义码里不存在可生成的静音码**，
不要指望往 CosyVoice/Qwen3-TTS 里注入 silence token。

## 4. 不要再试的方向（已证伪 / 官方否定）

| 方向 | 结论 |
|---|---|
| 调 `max_chars` / 分段字数 | ❌ 服务端会收敛回安全值，r4 与 r3 结果一字不差 |
| 在文本里加标记让模型少停 | ❌ 官方：停顿由 LLM 推断，无干预接口；AR 架构无 silence token |
| SSML `<break>` | ❌ CosyVoice 不支持（网传说法无源码依据）；`<|`+`|>` 只是"跳过前端"的哨兵 |
| 开 `text_frontend` | ❌ 韩语会走英文分支，且 `ttsfrd` 未装，会更糟 |
| 换高动态参考音频（女声） | ❌ 女声崩（26→67 句）；男声可用但音高掉 8% |
| **路线 A：参考音频换成"最长不间断呼吸群"** | ❌ **2026-09-30 下午证伪**，见下 |

本文第 3 节写"参考音频的节奏会被克隆"（arXiv 2304.11976 Table 4），

## 6. 已落地的解法：PBA 停顿预算对齐（`app/pba.py`）

既然生成侧控不了，就在**输出侧**做。关键差别在于：
不是删掉停顿（那样会掉句内动态、接缝生硬），而是

1. 每个停顿 × α（默认 **0.8**）；
2. 被压到 250 ms 以下的停顿被 VAD 自然合并，句数下降；
3. **丢掉的静音时间用 atempo 把整段拉回原时长** —— 总时长不变，
   发音速率被动放慢约 4%，正好对上案例原声（案例有声段 6.05 字/s，
   我们原样 6.25 字/s）。

只切静音、不动任何有声样本、**不进声码器**，因此没有音质损失。

### α 网格（两个性别同一套系数，不是分别拟合）

| α | 男句数 | 男句均 | 男静音% | 女句数 | 女句均 | 女静音% |
|---|---|---|---|---|---|---|
| 1.0（原样） | 96 | 2.34s | 13.8 | 42 | 5.60s | 5.8 |
| 0.9 | 87 | 2.65s | 11.6 | 31 | 7.71s | 4.1 |
| **0.8** | **72** | **3.29s** | 9.0 | **24** | **10.08s** | **3.0** |
| 0.7 | 54 | 4.51s | 6.5 | 15 | 16.33s | 1.8 |
| 0.6 | 43 | 5.77s | 4.7 | 10 | 24.66s | 1.1 |
| **案例原声** | **70** | **3.32s** | 11.2 | **23** | **10.60s** | **3.0** |

9 项里 8 项改善；唯一没动的是男声 `onset_f0`（−7.9%），
那是**音色克隆本身的音高偏差**，不是节奏问题，属于另一条线。

### 生产接入

- 新模块 `app/pba.py`，在 `server.py` 里**ASR 回检之后、mp3 编码之前**调用
  （CER 要量的是模型原始输出，不能被后处理污染）。
- 环境变量：`TTS_PBA_ALPHA`（默认 `0.8`，设 `1.0` 即完全关闭）、
  `TTS_PBA_MIN_CHARS`（默认 120 字以下不做）。
- 削掉的静音时间并入已有的 ffmpeg `atempo`：`atempo = speed × pba_ratio`，
  所以**成品总时长、时长预估、统计口径全部不变**。
