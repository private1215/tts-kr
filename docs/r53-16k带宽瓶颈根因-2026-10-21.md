# r53 · 16 kHz 带宽瓶颈 —— omni 成品「发闷 / 不如 EL」的根因

日期：2026-10-21　批次：z36 之后　状态：**已定位，待上线**

---

## 一、结论先行

现役 omnivoice 链路的**有效带宽只有 8 kHz**，成品贴着 44.1 kHz 的标签却只有 8 kHz 的内容。
原因是 `app/fix_chain.py` 全链路走 `load16()`（**`ffmpeg -ar 16000`**），
omni 原本 24 kHz 的输出一进链就被降采样，**8 kHz 以上永久丢失**。

这一条同时解释了三个长期现象：

| 现象 | 解释 |
|---|---|
| 员工报「发闷 / 像收音机」 | 8–12 kHz 缺失（人声齿音、气声、空气感全在这里） |
| z35/z36 盲听全选 EL | EL 是 24 kHz 真声，我们是 8 kHz 带宽 |
| 客观指标全绿却听出差 | 🔴 **所有客观指标都在 16 kHz 口径下测，这次降采样对它们完全隐形**（server.py:1474 原话） |

> server.py:1472-1474 早就把后果写死了：
> 「16k 音频压 mp3 会把音色从 **0.9331 打到 0.6903**」
> 「项目所有客观指标都在 16k 口径下测，**这个降采样在所有指标里是隐形的**」

## 三、排查过程（含被推翻的假设）

### ❌ 假设 A：高频缺失是 omni 模型 / 声码器的问题
**推翻。** omni 原始 24 kHz 输出实测 8-10k = 1.32e-3、10-12k = 2.28e-4，
**比 EL 男声还高**（EL 是 8.24e-4 / 1.10e-4，我们是其 **1.6× / 2.1×**）。模型给足了高频。

### ❌ 假设 B：mp3 编码砍掉了高频
**推翻。** 同素材同码率对照（omni 原始 24k wav，109.1 s，192k CBR）：

| 处理 | 8-10k | 10-12k |
|---|---|---|
| 原始 24k wav | 5.58e-4 | 4.29e-5 |
| 升 44.1k + mp3 192k | **5.58e-4** | **4.29e-5** |
| 保持 24k + mp3 192k | 5.57e-4 | 4.25e-5 |
| **降 16k + mp3 192k** | **1.65e-7**（掉 3380×） | 7.79e-9 |

mp3 前后小数点都一样，**libmp3lame 完全无辜**。

### ✅ 假设 C：16 kHz 降采样是杀手 —— 证实

| 路径 | 8-10k | 10-12k |
|---|---|---|
| omni 原始 24k | 1.32e-3 | 2.28e-4 |
| **v16_44（现役链路模拟）** | 1.96e-5（**÷67**） | 1.04e-8（**地板**） |
| **v24_44（候选修复）** | **1.32e-3** | **2.28e-4** |
| EL 男 merged.wav | 8.24e-4 | 1.10e-4 |

## 四、修复方向与实测收益

**方向：链路采样率 16 kHz → 24 kHz（omnivoice 原生采样率），成品 mp3 仍出 44.1 kHz。**

- 24 kHz 是 omni 的原生输出（`omni_server.py:44 SR = 24000`），**零重采样损失**
- 与 EL 标杆同口径（EL `merged.wav` 也是 24000 Hz）
- 44.1 kHz 容器保留给后续 AIR（补 11–13.5 kHz）留位置

### 音色（campplus 余弦，同人阈值 0.75，EL 上限 0.9628）

| 路径 | 音色 |
|---|---|
| 现役 16k | 0.9354 |
| **24k** | **0.9534**（+0.018） |

与 EL 上限的差距 **0.0274 → 0.0094，缩小 66%**。
⚠️ 且这个数**低估**真实收益：campplus 在 16k 口径测，恰好看不见 8–12 kHz 的损失。

### 外部印证（联网）
- 「16 kHz 采样不满足高质量 AI 语音：人声含 8–10 kHz 以上成分，超过 16 kHz 的
  8 kHz 奈奎斯特限 → **muffled**；22.05/24 kHz 才自然」
- LPCNet 论文：原版 16 kHz「does not provide satisfactory sound quality」→ 改 24 kHz
- 备选方案 BWE（AP-BWE / Vocos-BWE）是「从零合成高频」，
  项目注释明确警告「14 kHz 以上从零合成只会变成沙沙声」→ **不作为首选**
