# 听感反馈台（/feedback）

## 为什么要有这个页面

语调 / 情绪 / 停顿位置 / 重音 / 呼吸这五项**没有可靠客观指标**，只能人耳判。
但让员工"描述哪里不对"历史上反复失败——说不出、说不清、说了也没法量化成参数。

所以改成 **听选**：

- 同一题的多个选项**只差一个变量**（其余音色/语速/内容/后处理完全一致）
- 员工只做一件事：听完选一个字母
- 我们直接拿到方向，可以立刻落到配置上

页面本身不解决"还原度"，它解决的是**方向从哪来**。

## 访问方式

- 独立链接：`http://<服务器>:8000/feedback`（可直接发给员工）
- 或从主界面右上角用户名菜单 → **听感反馈**

## 数据流

```
/feedback                页面（app/ui/feedback.html）
/api/fb/items     GET    题目清单（匿名可读）
/fb-audio/<name>  GET    题干音频（匿名可读）
/api/fb/vote      POST   提交（需登录，写入 votes.jsonl）
/api/fb/votes     GET    汇总（需管理员）
```

文件位置（服务端）：

```
/mnt/tts/data/tone-ab/items.json     题目配置
/mnt/tts/data/tone-ab/*.mp3          题干音频
/mnt/tts/data/tone-ab/votes.jsonl    答案（append-only，一行一条）
```

`FB_DIR` 可用环境变量 `TTS_FB_DIR` 改。

## 怎么加新题目（不用改代码、不用重启）

1. 生成候选音频（变量唯一），拷进 `/mnt/tts/data/tone-ab/`
2. 往 `items.json` 的 `items` 数组追加一项：

```json
{
  "id": "pause_pos_20261012",
  "dim": "停顿位置",
  "title": "长句在哪里换气",
  "desc": "四个选项只有换气位置不同。",
  "ref": { "file": "xxx_ref.mp3", "label": "案例原声", "note": "只用来对比" },
  "options": [
    { "key": "A", "file": "xxx_1.mp3", "label": "选项 A" },
    { "key": "B", "file": "xxx_2.mp3", "label": "选项 B" }
  ]
}
```

3. 刷新页面即可出现（页面每次加载都拉 items.json，无缓存）

⚠️ `id` 改了就等于换了一道题，历史答案不会跟着改。同一题反复迭代请**换 id**。

## 统计口径

- 同一个人对同一题**只算最后一次**（可以反复改主意）
- 汇总按题目给出每个选项的票数和投票人
