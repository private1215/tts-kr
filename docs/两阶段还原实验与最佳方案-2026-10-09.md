目标：让本项目生成的语音尽可能接近案例语音。本轮不追求"跑更多步数"，而是先把
**数据可信度**和**验收口径**立起来——这两个不解决，任何分数提升都无法归因。

## 1. 为什么必须先修对齐

旧脚本 `tools/lora_data.py` 的切片方式是：

```
bounds = cumsum(句子字符数占比) * 音频总时长
```

这是**估算**，不是对齐。语速起伏、句间停顿、原文与音频的细微差异都会让切片里的
声音与文字错位，模型就会学到漏读、重复和错误的断句位置。

新脚本 `tools/lora_data_align.py` 改为：
`faster-whisper 词级时间戳 → difflib 对回原文 token → 逐句时间范围 → 按句打包切片`。

### 试跑中踩到并修掉的三个坑（都已写进代码注释）

| 坑 | 现象 | 修法 |
|---|---|---|
| ASR 词带标点 | 覆盖率被压到 0.70~0.82，看起来"对齐全坏" | ASR 词先过 `_keep` 再去比对 |
| 整段覆盖率闸门 | 4 分钟长音频整体覆盖率必然被少数差句拖低 → 整段丢弃 | 改为**逐句覆盖率闸门**（<0.75 丢该句，其余保留） |
| 语速口径 | 用 `len(_keep())`（=词数，韩语 2~3 词/秒）去卡 CPS 4~11 → **全部切片被误杀，产出 0 片** | 改用去空格**字符数**（韩语实测 ~5.7 字/秒） |

对比旧字符比例数据集（207 片 / 83.2 分钟）：新数据集时长约一半，因为逐句
闸门丢掉了对不上的句子、且切片更短（~12s vs ~25s）。**时长变短不是损失**——
边界可信度优先于数量。

### 2.2 与旧字符比例切片的对比（注意口径）

对旧数据集同样抽样回检：CER 中位 **0.1094**（10 条），同样零空转写。

🔴 **这两个数不能直接拿来判优劣**，原因有两条：
1. 抽样条数不同（6 vs 10）、切片长度不同（14~20s vs 22~27s），不是配对比较；
2. **CER 只检验"内容对不对"，检验不了"边界准不准"**。字符比例切片的缺陷是
   **边界漂移**——切片文字与音频起止错位，但音频里大部分词还在，CER 不会爆。

所以：新数据集的可信度来自**边界来自真实时间戳 + 逐句覆盖率闸门**，
而不是靠 CER 比旧数据低。要彻底证明旧数据有害，需另做"同一句的比例边界 vs
时间戳边界偏移量"统计（尚未做）。

🔴 **但这还只是技术验证，不能据此宣布效果提升**：

### 2.5 新增：韩语数字/金融单位标准化（P0，对应盲听第 6 项）

原 `pipeline.KO_NUMBER_UNIT` 只把 `%` 换成"퍼센트"，**数字仍是阿拉伯数字**
（`35,000원` 原样进模型），读法全靠模型临场判断 → 长数字容易加速/重复/读错。

新增 `app/konum.py`，规则写死（单测 `tools/test_konum.py` 10/10 通过）：

| 原文 | 读法 |
|---|---|
| 35,000원 / 36,400원 / 69,900원 | 삼만 오천 원 / 삼만 육천사백 원 / 육만 구천구백 원 |
| 95.38% / 72.39% | 구십오 점 삼팔 퍼센트 / 칠십이 점 삼구 퍼센트 |
| 350만 주 / 23만 1,914주 | 삼백오십만 주 / 이십삼만 천구백십사 주 |
| 10월 9일 | 시월 구일 |

**只处理带单位的数字**，裸数字（股票代码 005930、电话号码）保持原样，
避免规则化反而读错。由 `TTS_KO_NUM=1` 控制，**当前默认关闭**——
需先做同文案 A/B（开/关）确认数字准确率确实提升，再决定默认开启。

另注：案例文案本身已是口语化读法（"칠만오천팔백원"），说明案例是口播稿/转写稿，
数字模块对它们不会改动，不会污染训练数据口径。

### 2.6 新增：生产链路 adapter 注入（线上已启用，男女各一）

**关键卡点**：此前生产服务（`app/server.py` / `tts_engine.py`）**完全不支持加载
adapter**，所以无论离线验证多好，员工拿到的始终是 base 音频。

已在 `tts_engine.py` 模型加载后加入注入逻辑：
`TTS_LORA_ADAPTER=<ckpt 目录>` 才注入；注入失败自动回退 base 且不阻断服务；
不设置则行为与之前完全一致。

**按音色白名单**（必须）：adapter 注入后是**全局**的，而 align_v2 只在男声
yohan 数据上训练，直接开会让女声也带上男声风格 → 音色退化。
因此 `TTS_LORA_VOICES=yohan_male`：匹配该前缀的音色才启用 adapter，
其余音色走 `PeftModel.disable_adapter()` 回退 base。
（注意 `PeftModel.from_pretrained` 原地注入 LoRA，但必须持有返回的 wrapper
才能调用 `disable_adapter()`，所以保存了 `self._peft_model`。）

**线上状态（2026-10-09 22:4x）**：systemd drop-in
`/etc/systemd/system/qwen-tts.service.d/lora.conf`：
```
TTS_LORA_ADAPTERS=yohan_male=.../yohan_aligned/align_v2/ckpt/final,SOLA_female=.../SOLA_aligned/align_v1/ckpt/final
TTS_KO_NUM=1
```
日志确认两个 adapter 均已载入，男女声验证通过。`EL_male` / `EL_female` 等
未命中前缀的音色自动回退 base。

### 2.11 同音色开/关对照：adapter 差异**不显著**（多种子后修正结论）

终于做到的干净对照：**同一音色 `EL_male`、同一文案 799e4d（4268 字）、同一 seed 42**，
只在两次服务重启之间切换 adapter 开关。

| | base（adapter 关） | adapter（开） |
|---|---|---|
| 时长 | 516.9 s | 516.9 s |
| dur_ratio | 1.002 | 1.002 |
| 段数 | 2 | 2 |
| CER | 0.1235 | 0.1287 |
| **保真度总分** | **96.6%** | **96.14%** |

逐项（案例值 / base 偏差 / adapter 偏差）：

| 维度 | 权重 | 案例 | base | adapter |
|---|---|---|---|---|
| A 句内音高动态 | 0.10 | 9.53 | 9.05（5.04%） | 8.63（**9.45%**） |
| E 句尾多样性 | 0.12 | 37.31 | 37.74（**1.15%**） | 35.70（4.34%） |
| F 停顿熵 | 0.08 | 0.87 | 0.93（6.06%） | 0.91（4.02%） |
| tone 音色 LTAS | 0.07 | — | 10.86% | 11.50% |

**A 与 E 两个独立指标同向变差**，且这两项正是盲听反馈里"语调不对"的量化口径。
音色相似度也印证：campplus 与案例原声的余弦 base 0.8685 / adapter 0.8656，
而 base 与 adapter 两者互相似度高达 **0.9989** —— adapter 几乎没改变输出。

**为什么和离线 A/B 结论相反？** 离线测（无生产约束）base 会撞上限不停嘴
（`dur_ratio` 4.02，CER≈1），adapter 正常；而**生产链路有分块 + 语速锁定 +
异常段重试**，把 base 也约束住了 —— 这套约束此前因为根目录旧 `pipeline.py` 分叉
**从未在生产生效**，今天修复后 base 才恢复正常。也就是说：
**解决"不停嘴"的主要是生产链路约束修复，不是 LoRA。**

#### ⚠️ 结论修正（多种子后）

seed 42 只有一条时，A/E 两项同向变差，看起来像"负贡献"。补跑 seed 2026 后：

| seed | base | adapter | 差 |
|---|---|---|---|
| 42 | 96.60% | 96.14% | +0.46（base 好） |
| 2026 | 95.65% | 95.67% | −0.02（几乎相同） |
| **seed 间波动** | **0.95** | **0.47** | ← 波动本身更大 |

**adapter 与 base 的平均差约 0.22 分，小于 seed 自身波动 0.47~0.95 分 → 差异不显著。**
seed 42 那次 A/E 同向变差是单次波动的假象，不是真实效应。

逐项也印证了这点（seed 2026）：base 的 E 偏差 13.35%、adapter 17.17%，
两个方向都乱跳；而 seed 42 时 base 的 E 只有 1.15%。

🔴 **教训**：1 文案 × 1 seed 就下"好/坏"结论必然翻车。本节保留了被推翻的
原始判断，作为反面记录。

**处置决定**：既然没有证据显示 adapter 带来提升，就**不拿它当提升上线** ——
生产默认回 base，adapter 代码与训练产物保留，将来有更强证据再开。
（这与"不能把 loss 下降当效果提升"是同一条原则。）

女声可懂度明显好于男声（CER 0.038~0.052 vs 男声 0.13~0.17）。
注意 `a3d39a` 的说话人是 elara —— 与所有已训说话人都不是同一人（余弦 0.25~0.34），
它走的是 base 通道，说明**跨说话人迁移本身是稳的**。

### 2.10 🔴 更严重的问题：adapter 从没对**员工默认音色**生效过

前面所有 adapter 验证用的都是 `yohan_male` / `SOLA_female` 这两个音色名。
但 `app/server.py` 里写死了：

```python
BEST_CLONE = {"male": "EL_male", "female": "EL_female"}
```

员工只点「男 / 女」，实际拿到的是 `EL_male` / `EL_female`。而 adapter 是按
**音色名前缀**匹配的 —— `EL_male` 不以 `yohan_male` 开头 → `disable_adapter()`
→ **回落到 base**。也就是说前面几轮的成果，员工一次都没吃到。

用 campplus 说话人嵌入核验（`tools/spkchk.py` 的 embed，同人阈值 0.75）：

| A | B | 余弦 | 判定 |
|---|---|---|---|
| EL_male | yohan_male | 0.9209 | 同一人 |
| yo han | yohan_male | 0.8790 | 同一人 |
| EL_male | yo han | 0.9182 | 同一人 |
| EL_female | SOLA_female | 0.9110 | 同一人 |
| elara | 上述任意 | 0.25~0.34 | **另一人**，不能映射 |

修复：新增 `TTS_LORA_ALIAS`，先把音色名换成"同人"的规范名再匹配前缀。
别名必须由说话人嵌入核验支撑，不能靠名字猜。

```ini
Environment="TTS_LORA_ALIAS=EL_male=yohan_male,yo han=yohan_male,EL_female=SOLA_female"
```

6 个注册音色里，`elara` 没有对应 adapter（是另一个人），保持回落 base ——
这是正确行为，不是缺陷；是否给它单独训要另开一轮。

## 3. 两阶段实验协议

`tools/ab2.py` 已实现，走**生产 API**（不绕过响度/EQ/停顿/PROSO 后处理）。

### 阶段一：同文案，案例对标

- `text` = 案例原文；`voice` = 该说话人克隆音色；固定 `speed=1.0` / Korean / clone。
- **同时跑带 `case_id` 与不带两组**：
  `case_id` 会把该案例自身的后处理目标（峰值/响度/停顿/语速/PROSO）注入链路，
  所以"带 case_id"是**案例条件对标成绩**，不能当成默认生产或泛化能力。
- **多个随机种子**：历史记录 Qwen 同案例不同 seed 差约 0.95 分；只看一次或只挑
  最高分会误判。
- fidelity 只在**同文案、同长度**下可比，且必须看分项，不能只看总分。

### 阶段二：固定参考，换未见文案

- **文案不用另外造**：案例上传时本来就是「语音 + txt 文案」成对入库的，
  案例库里现成就有大量真实财经文案。`tools/mk_unseen.py` 直接从中挑出
  **没参与训练**的两类：① 该说话人的 holdout 案例（bench_case，整条不进训练集）；
  ② 同性别但不属于该说话人的其它案例。参与训练的那些案例文案只能用于阶段一，
  拿来做阶段二就是 in-sample，会虚高。
- 已生成 `/mnt/tts/diag/unseen.json`：799e4d（holdout，4268 字）、
  1a6c20（案例-男声，4046 字）、c3117b（SOLA 男声，3689 字），
  单条都是 10 分钟量级，顺带覆盖长文本回归。
- 完全复用阶段一的音色/参考音频/引擎/参数，**只换 `text`**。
- 默认**不带 `case_id`**（对新文案套别的案例目标是错配）。
- 文案必须没参与过参考音频文字稿、训练、调参、`bench_case` 拟合。
- 多条文案 × 多个 seed，报告均值与离散；**不做跨文案的 fidelity 整段排名**。

### 判定口径（与 12 项清单一致）

- **完整性/内容是闸门**：ASR 空转写、CER 超阈、时长异常 → 直接失败，
  任何声学高分都不能抵消。
- 物理指标分数**不是**听感还原百分比；最终以人工盲听为准。

## 4. "最佳方案"怎么定

取决于目标，不能一个分数走天下：

| 目标 | 以什么为准 |
|---|---|
| 尽可能贴近某条既有案例 | 阶段一的分项表现；明确是否使用 `case_id` |
| 员工换文案后仍稳定 | 阶段二的多文案 × 多 seed 结果（音色相似度、可懂度、韵律稳定性、盲听） |
| 换引擎/换模型版本 | 锁定同一参考条件与后处理口径，并核实**实际执行引擎**与是否发生 fallback |

**上线门槛**（未满足就保留 Base，不更新默认配置）：
完整性零错误 · 关键数字正确 · 盲听不退化 · 训练外克隆能力不退 · 案例方向一致。

## 6. 仍需明确的事实边界

  完整性回检、局部重生成同样必要。
- 员工仍只需选男/女，不承担参数调试或模型筛选。
