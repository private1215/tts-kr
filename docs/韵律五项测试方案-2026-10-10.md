# 语调 / 情绪 / 停顿 / 重音 / 呼吸 —— 五项怎么测（2026-10-10）

## 0. 一句话结论

**「这五项只能人工盲听」这个说法不成立。** 五项里四项可以从案例库自动提取
客观指标做回归验收；只有**「呼吸」这一项案例给不了参考** —— 因为案例本身是
ElevenLabs 生成的 TTS，**它压根不含呼吸声**。

人工盲听仍然要保留，但角色变了：不再是唯一的判据，而是**给客观指标指路**
（告诉我们应该去量什么），以及**最后一道确认**。

## 1. 凭什么说可测：三条外部依据

### 1.1 K-ToBI —— 韩语韵律有国际标注标准

Sun-Ah Jun（UCLA）建立的韩语韵律标注体系，专门针对首尔标准语：

- 两个韵律单位：**AP**（Accentual Phrase 声调短语）/ **IP**（Intonation Phrase 语调短语）
- IP 末尾由**边界音调**标记，共 8 类：`L% H% LH% HL% LHL% HLH% LHLH% HLHL% LHLHL%`
- 手册原文：**「HL% … most common in declaratives and wh-questions. It is also
  commonly used in news broadcasting.」** —— 本项目就是财经广播，这直接给出目标
- 韩语是 **edge-prominence 语言**：焦点落在短语**左边缘**，不是音节重音
- AP 首音节音调由首辅音喉部特征决定：**送气/紧音开头 → H，否则 → L**
- 标注者一致性：**IP 边界 91%、AP 边界 78%、break index ±1 内 99%**
  → 说明这套体系稳定可复现，不是玄学

### 1.2 INTERSPEECH 2024 —— 呼吸能自动检测

Yang / Koriyama / Saito（arXiv:2402.00288）：用 duration + **ZCR** + mel 谱方差
(VMS) + NA-VMS 四个声学特征，就能把呼吸声从纯静音里分出来，IoU 0.836 /
precision 0.924，**不需要训练模型**。论文同时证明：带呼吸的 TTS 自然度
MOS 3.55 > 不带 3.34。

### 1.3 울산대 研究 —— 不需要完整 K-ToBI，三类就够

把韩语韵律边界简化成「上升 / 平坦 / 下降」三类喂给 TTS，MOS 就显著提升。
所以本项目**用三类句尾音调即可**，不必做完整的音系标注。

## 2. 五项指标定义

`tools/prosody_target.py` 已实现，纯 CPU、不占 GPU。

| 项 | 指标 | 依据 |
|---|---|---|
| **语调** | 句尾边界音调 fall/flat/rise 三类占比 + 升降幅度(semitone) | K-ToBI IP boundary tone |
| **停顿** | 密度(次/分) + 时长分位 p10/p50/p90 + 长停顿占比 | K-ToBI break index |
| **重音** | 句内 F0 峰值相对位置 p50 + 句内音高动态 | 韩语 edge-prominence |
| **呼吸** | 频率(次/分) + 时长 + 占静音比 | INTERSPEECH2024 声学特征 |
| **情绪** | 句间音高/能量变异系数 + 句内动态 | arousal 声学代理 |

⚠️ **情绪是最弱的一项**：上面只是「起伏够不够」的声学代理，**不等于情绪对不对**。
它能告诉你动态范围不足，不能告诉你「该严肃的地方严肃了没有」。情绪项最终仍需人耳。

### 测量口径的几个坑（已踩过）

1. **静音阈值不能太松**：第一版用 `min_sil=0.10 + pct(db,30)+8`，跑出
   「停顿 107 次/分钟」（每 0.56 秒一次）——把音节间隙也算成停顿了，
   切出来的"句子"其实是语音碎片，导致语调分类变随机（fall 0.42 / rise 0.42
   对称分布 = 典型乱判）。改用 `pct(db,25)+6` + `min_sil=0.18` 后正常。
2. **切句要用更长的静音**：`≥0.35s` 才算句边界。短停顿只是短语内换气，
   拿它的尾端当句尾去做语调分类，量到的是句中音高，不是边界音调。
3. **句尾要掐掉最末 5%**：句末拖尾常有气声，pyin 在那段 F0 不可靠。
4. **升降阈值取 1.0 semitone**：人耳察觉阈值约 1 半音，低于此等于放大噪声。

| 语调 flat 占比 | 0.200 | 0.250 | |
| 语调 rise 占比 | **0.050** | 0.100 | 升调很少 |

## 4. 🔴 「呼吸」这项：案例给不了参考，需要拍板

诊断证据（对 2 条案例的全部静音段做特征统计）：

```
静音段 rel_db 分位: [-19.9, -18.7, -17.3, -15.5, -13.1, -10.9, -10.2]
高出底噪 6dB 以上的段数: 26 / 193
最响静音段: dur=0.200 rel_db=-9.6 flat=0.0020 zcr=0.037
```

- `rel_db` 分布**单峰连续**，没有「纯静音 / 呼吸」双峰 —— 有真实呼吸时必然双峰
- 最响的静音段 `flat=0.002`、`zcr=0.037` → **是残留信号，不是宽带气流噪声**
- 结论：**案例原声基本不含呼吸声**（ElevenLabs 是 TTS，本来就不合成呼吸）

所以「呼吸不自然」这个反馈**没有参照物**。三条路，需要选一条：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 降级** | 承认案例无呼吸，把该从验收清单降级为「停顿处不应有杂音/爆音」 | 最低，但员工的需求没被满足 |
| **B. 换参考** | 另找**真人**韩语财经播音做呼吸参考（东北朝鲜族可录；或韩语财经播客/新闻） | 中等，需要采集新素材 |
| **C. 主动合成** | 在停顿处合成呼吸（INTERSPEECH2024 已证明 MOS +0.21） | 较高，要改后处理链路 |

**建议先问清一件事：员工说「呼吸不对」，是跟案例比的，还是跟他们心里
「真人播音」的标准比的？** 如果是后者，那目标其实是「比案例更像真人」，
案例库作为参照物从一开始就够不着 —— 这时应该走 B 或 C。

## 5. 员工可执行的 ABX 盲听方案

员工懂韩语但不懂技术，给的是「感觉」。开放式评分（「打几分」）既不稳定
也定位不了问题。改用**强制选择 + 单点提问 + 时间锚点**。

### 5.1 为什么是 ABX 而不是 1~5 分

- 二选一比五档评分**省力得多**，评审不易疲劳，一致性更高
- 二选一**更敏感**：两版差距很小时，评分都给 4 分看不出差别，但强制选择
  仍能稳定的指向性
- 参考 KVoiceBench 的做法：**5 名评审 × 20 句**，三轴（自然度 / 韵律 / 发音），
  统计用 **paired Wilcoxon signed-rank** + bootstrap 95% CI，**Krippendorff's α**
  检验评审间一致性（α < 0.6 说明数据不可信，要重做）

### 5.2 具体问题设计（每个维度只问一件事）

不要问「像不像」。要问可定位的问题：

| 维度 | 给员工的问题 | 转成什么信号 |
|---|---|---|
| 语调 | 「句尾的升降对不对？有没有该降的地方反而上扬？」 | 句尾音调分类对比 |
| 停顿 | 「停顿的地方是不是该停的地方？有没有在不该停的地方断开？」 | 停顿位置分布 |
| 重音 | 「重点词的强调位置对不对？听起来是不是平铺直叙？」 | F0 峰值位置分布 |
| 情绪 | 「语气够不够坚定/有起伏？还是像念稿？」 | 句间音高/能量变异 |
| 呼吸 | 「换气的地方自不自然？有没有憋着一口气读完？」 | 呼吸/停顿的位置与频次 |

**关键动作**：每次「不对」都要员工给出**时间点**（「第 30 秒左右」）。
有了时间点就能回查客观指标，把「感觉」变成可定位的信号。

### 5.3 表单模板

```
样品 #__   评审人：____   日期：____

并排播放 A / B（顺序随机，你不知道哪个是案例原声）

Q1 两个里面，哪个更像专业财经广播？（必选一个）      A / B
Q2 你觉得主要差别在哪？（可多选）
   □ 句尾升降  □ 停顿位置  □ 强调的词  □ 语速  □ 语气起伏  □ 换气
Q3 不对的地方大概在第几秒？__________
Q4 用一句话说：________________________________
```

### 5.4 音频怎么准备

- 每对 15~25 秒，太长评审会疲劳
- **同一文案**，一版案例原声、一版本项目生成
- 顺序随机化，且**案例不能总在 A 位**（否则会形成位置偏好）
- 20 对足够；不要一开始就上 50 对，评审质量会塌

## 6. ⚠️ 朝鲜族评审：能用，但有系统性偏差

用户提到「国内东北有朝鲜族」——这是真实的母语者资源，但**不能直接用**。

### 6.1 延边朝鲜语 ≠ 首尔标准语

延边话属 **Hamgyŏng（咸镜）方言**，与首尔标准语的差异：

| 维度 | 首尔标准语 | 中国朝鲜族/延边 |
|---|---|---|
| 语调 | 起伏明显，**句尾习惯上扬** | **更平直干脆**，节奏硬朗，带东北话语感 |
| 音调系统 | 无声调，靠边界音调 | 咸镜方言**保留 pitch accent**（高低对比） |
| 头音法则 | 遵循（여자、이） | 不遵循（녀자、리） |
| 元音 | ㅔ/ㅐ 已合并 | 老一辈仍区分 |
| ㄹ | 词首读闪音（r~l 之间） | 多读成清晰的 l |
| 终结词尾 | 通用 요체 | 更常用 -ㅂ니다/-슴다 |

### 6.2 风险

如果案例是首尔标准语（ElevenLabs 韩语多为首尔标准语），那么朝鲜族评审感到的
「句尾不够上扬 / 太软」，**有可能是方言差异，不是质量问题**。照着改反而会偏离案例。

### 6.3 正确用法

1. **以案例原声为锚，不以评审者习惯为标准** —— 这正是 ABX 的价值：
   问的是「哪个更像案例/更像专业广播」，而不是「你觉得对不对」
2. **优先选熟悉首尔标准语的评审**：年轻、常看韩剧/韩国财经节目的朝鲜族，
   或有过韩国生活经历者
3. **先做校准**：正式评之前，让评审听 3 条**真实案例原声**（都是真案例），
   如果评审认为某条「不自然」，说明其标准与项目不一致，该评审的数据要慎用
4. **先澄清目标受众**：如果最终听众就是中国朝鲜族/东北市场，那延边口音
   可能恰恰是**需求而不是缺陷** —— 这决定整个优化方向，必须问清楚

## 7. 首次对比结果（同文案 799e4d，男声，EL_male）

用**同一文案 / 同一脚本口径**对比，这才可比（跨文案比逐句统计是无效的）：

| 指标 | 案例 799e4d | base | adapter | 判定 |
|---|---|---|---|---|
| 语调 fall | 0.65 | 0.65 | 0.65 | ✅ 一致 |
| 语调 rise | **0.05** | 0.10 | 0.15 | ⚠️ 偏高 2~3 倍 |
| **句尾降调幅度 (st)** | **−7.62** | −5.02 | −6.12 | 🔴 **base 差 2.6 半音** |
| **句内音高动态 (st)** | **12.81** | 10.15 | 12.04 | 🔴 **base 差 2.7 半音** |
| 停顿 (次/分) | 24.2 | 21.8 | 21.5 | 略少 |
| 停顿时长 p50 (s) | 0.415 | 0.460 | 0.480 | 略长 |
| 重音峰值位置 | 0.265 | 0.253 | 0.293 | ✅ 一致 |
| 句间能量 CV | 0.170 | 0.175 | 0.168 | ✅ 一致 |
| 呼吸 (次/分) | 0.9 | 0.1 | 0.1 | 双方都没有 |

### 结论：差距集中在两项，都是「幅度不够」

1. **句尾降调浅 2.6 个半音** —— 这就是员工说的「语调不对」的量化形态。
   案例收尾干脆下坠，base 收尾偏平 → 听起来「不像在断言，像在念」。
2. **句内音高动态少 2.7 个半音** —— 对应「平铺直叙 / 像念稿」。
3. 附带：**不该上扬的地方上扬了**（rise 5% → 10%/15%）。

有意思的一点：**adapter 在这两项上都更接近案例**（−6.12 / 12.04 vs base
−5.02 / 10.15）—— 这是 adapter 的正面证据，但它的升调比例更高（0.15）。
说明 adapter 不是没用，只是**好坏掺半**，所以总分上看不出来。

⚠️ 这是 1 文案 × 1 seed，按上一轮教训必须多 seed 复测才能下结论。

## 9. r27 上线实测：改善单项 ≠ 改善总分（又一次）

用户拍板后实现了两项改进，都用**同文案 799e4d / EL_male / 多 seed** 回归：

### 9.1 句尾定向下降 `drop_st` —— 判为负贡献，已关闭

| 配置 | seed42 | seed2026 | 均值 |
|---|---|---|---|
| base（都关） | 96.60 | 95.65 | **96.13** |
| 呼吸 + drop_st | 95.85 | 94.52 | **95.19** |

两个 seed 同向变差（−0.75 / −1.13），不是波动。

它**确实**把自己盯的指标做到了：句尾降调幅度 −5.02 → **−7.10 半音**
（案例 −7.62，基本达标）。但 fidelity 三项同时恶化：

| 维度 | base | 加 drop_st 后 |
|---|---|---|
| E 句尾多样性 | 1.15% | 4.13% ~ 16.14% |
| D 语速 CV | 0.72% | 12.52% |
| sil 静音占比 | 1.25% | 7.76% |

**根因**：降得更狠 → 句尾更统一 → 多样性下降；`drop_st` 与 `E` 大概率
此消彼长。中间加过逐句抖动（±35%）把 E 从 9.50% 救回 4.13%，但仍不划算。

🔴 **这是本项目第二次「单样本看着有效、多种子后翻车」**（第一次是 2026-10-09
的 adapter）。教训已经稳定复现：**任何韵律/音色结论都必须 ≥2 个 seed。**

### 9.2 呼吸合成（C 方案）—— 影响可忽略，保留上线

分离验证（关掉 drop_st 单独测呼吸）：

| 配置 | seed42 fidelity |
|---|---|
| base | 96.60 |
| **只开呼吸** | **96.05** |
| 呼吸 + drop_st | 95.85 |

−0.55 分落在 seed 波动 0.95 内 → 呼吸对既有验收指标基本无影响，
同时把"呼吸"从 0.1 次/分提到 **5.7 次/分**，达成 C 方案目标。
（比设定值 10 次/分低：够长的停顿不够多，被 `MIN_GAP_MS=380` 过滤掉了。）

**最终线上配置 = 呼吸开 + 句尾下降关**（`deploy/qwen-tts.service.d/r27.conf`）。

### 9.3 下一步：句尾语调该怎么改

`drop_st` 这条路走不通，说明**不能在 PSOLA 层面硬压句尾**。剩下的方向：

1. **文本侧**：确保分句正确、句末标点完整 —— 模型的句尾走向主要由文本决定
2. **参考音频侧**：换一段句尾降得更明显的 15 秒克隆源
3. **先做 ABX 盲听**：确认员工说的"语调不对"到底是"降得不够"还是
   "该降的地方没降 / 该升的地方没升"。**方向没确认就改参数，
   大概率是白改** —— 这正好是第 5 节盲听方案要解决的。
