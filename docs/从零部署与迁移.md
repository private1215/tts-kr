# 从零部署与迁移手册

> 适用：换新服务器 / 重装系统 / 想在第 2 台机器复制一套环境。
> 现网基线：Ubuntu 24.04.3 + RTX 3060 12GB + 驱动 595.91 + CUDA 13.2 + `/mnt/tts` 1.8T。
>
> **换机的结论先说**：代码本身可迁移（除了一处路径已在 2026-09-28 改成可覆盖），
> 真正不能从 git 拿到的是 **9.25G 模型权重** 和 **`data/` 目录（账号 / 历史任务 / 音色）**。
> 这两个必须单独处理，其余照本手册走即可。

---

## 0. 仓库里有什么、没什么

| 内容 | 是否在 git | 换机时怎么办 |
|---|---|---|
| 应用代码 `app/` | ✅ 在 | `git clone` |
| systemd 单元 `deploy/` | ✅ 在 | 改路径后 `daemon-reload` |
| 依赖清单 `requirements.txt`（110 包） | ✅ 在 | **不能直接照装**，见 §3 的 torch 坑 |
| 文档 `README.md` / `docs/` | ✅ 在 | — |
| **模型权重 9.25G** | ❌ 不在（`.gitignore` 排除 `models/`） | 重新下载，见 §4 |
| **venv 运行环境** | ❌ 不在 | 重建，见 §3 |
| **`data/`（users.json / jobs.json / voices/）** | ❌ 不在（含密码哈希，禁止入库） | 重新初始化 或 从旧机搬，见 §6 |
| 音频产物 `output/` | ❌ 不在 | 无需迁移 |

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| GPU | **≥ 12GB 显存** | 模型 bf16 常驻 4.17 GiB + 单任务峰值 6.97 GiB。<br>低于 12G 见 §7 |
| NVIDIA 驱动 | 需支持 CUDA 13.0（现网 595.91） | 低于此版本 `torch+cu130` 起不来 |
| 系统 | Ubuntu 24.04（其他发行版需自行换算包管理命令） | — |
| 磁盘 | ≥ 30G 可用（模型 9.25G + venv 约 6G） | 建议独立数据盘 |
| 网络 | 能访问 HuggingFace（或镜像） | 拉模型 |

## 2. 磁盘挂载（**顺序不能错**）

现网 `/etc/fstab`：

```
UUID=331399e1-b4b7-4221-baa7-ed559835b94d /mnt/tts ext4 defaults,noatime,nofail 0 2
```

`nofail` 的意思是"挂载失败也照常开机"——所以**服务必须先于数据写入、晚于挂载完成**。
`deploy/qwen-tts.service` 里已用 `RequiresMountsFor=/mnt/tts` + `After=mnt-tts.mount` 声明了依赖。

**换机时如果挂载点不叫 `/mnt/tts`**，systemd 的 mount 单元名要按转义规则改：

```
/mnt/tts      → mnt-tts.mount
/data/tts     → data-tts.mount
/srv/tts-data → srv-tts\x2ddata.mount      # 连字符要写成 \x2d
```

拿不准就用这条命令查真实单元名：

```bash
systemctl list-units --type=mount | grep -i tts
```

挂载完确认：

```bash
findmnt /mnt/tts        # 必须能看到，否则后面会把 9G 模型下到系统盘
df -h /mnt/tts
```

## 3. 建 venv —— ⚠️ 这里最容易翻车

**坑：`requirements.txt` 里写的是 `torch==2.14.0`，没有 `+cu130` 后缀。**
直接 `pip install -r requirements.txt` 会从 PyPI 拉 **CPU 版** torch，
`torch.cuda.is_available()` 返回 `False`，服务能启动但一生成就报错，而且报错信息不指向这里。

正确顺序（**先装 torch，后装其余**）：

```bash
sudo mkdir -p /mnt/tts/projects/qwen3-tts
sudo chown -R $USER:$USER /mnt/tts/projects/qwen3-tts
cd /mnt/tts/projects/qwen3-tts

python3 -m venv venv
source venv/bin/activate

# 1) torch 必须走 PyTorch 官方 CUDA 源（驱动支持 CUDA 12.x 就把 cu130 换成 cu121）
pip install torch==2.14.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu130

# 2) 再装其余依赖。torch 版本已满足，pip 不会把它覆盖回 CPU 版
pip install -r requirements.txt
```

**必须验证**（这一步别跳过）：

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
# 期望输出：2.14.0+cu130 True
# 若输出 2.14.0 False → 装成了 CPU 版，回到第 1) 步重装
```

## 4. 下载模型（9.25G，不在仓库里）

三个都要下，缺一个对应功能不可用：

| 模型 | 大小 | 用途 |
|---|---|---|
| `Qwen3-TTS-12Hz-1.7B-CustomVoice` | 4.3G | 9 个预设音色（普通模式） |
| `Qwen3-TTS-12Hz-1.7B-Base` | 4.3G | 声音克隆（clone 模式） |
| `Qwen3-TTS-Tokenizer-12Hz` | 651M | codec，两个模式都要 |

```bash
mkdir -p /mnt/tts/models && cd /mnt/tts/models
git lfs install

git clone https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice
git clone https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base
git clone https://huggingface.co/Qwen/Qwen3-TTS-Tokenizer-12Hz
```

国内访问 HuggingFace 不通时，先设镜像：

```bash
export HF_ENDPOINT=https://hf-mirror.com
```

**目录名必须与代码里的一致**（`app/server.py` 的 `MODEL_DIRS`）：

```
/mnt/tts/models/Qwen3-TTS-12Hz-1.7B-CustomVoice
/mnt/tts/models/Qwen3-TTS-12Hz-1.7B-Base
/mnt/tts/models/Qwen3-TTS-Tokenizer-12Hz
```

少一个不会崩，但 `MODEL_DIRS` 会过滤掉不存在的变体，对应模式直接不可用。
确认：`ls /mnt/tts/models` 应看到 3 个目录。

## 5. 部署代码与 systemd

```bash
cd /mnt/tts/projects/qwen3-tts
git clone https://github.com/private1215/tts-kr.git repo
cp -r repo/app repo/deploy .
# 注意不要直接把仓库当工作目录：app/ 才是运行目录，WorkingDirectory 指向它
```

改 `deploy/qwen-tts.service` 里的路径（若新机不是 `/mnt/tts/...`）：

```
Environment=TTS_BASE=<数据根>                    # ← 代码里所有路径由它派生
Environment=PATH=<项目根>/venv/bin:...
WorkingDirectory=<项目根>/app
ExecStart=<项目根>/venv/bin/python -u server.py
StandardOutput=append:<项目根>/service.log
StandardError=append:<项目根>/service.log
RequiresMountsFor=<数据根>
After=<转义后的 mount 单元名>
```

> `TTS_BASE` 是 2026-09-28 加的。旧版 `server.py` 里 `BASE = "/mnt/tts"` 是写死的，
> 换路径必须改源码；现在只改这一行环境变量即可。

安装并启动：

```bash
sudo cp deploy/qwen-tts.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now qwen-tts

sleep 45
systemctl is-active qwen-tts                     # 期望 active
tail -20 /mnt/tts/projects/qwen3-tts/service.log  # 期望看到「模型预热完成」
```

## 6. 初始化账号 / 迁移数据

### 全新环境

`server.py` 首次启动会自动建 admin，口令来源（**源码里已无硬编码口令**）：

1. 环境变量 `TTS_ADMIN_PASSWORD` 有值 → 用它（适合自动化部署）
2. 没有 → `secrets` 随机生成 12 位，**打到服务日志里**

两种情况都会强制首次登录改密。取随机口令：

```bash
grep '初始化默认管理员' /mnt/tts/projects/qwen3-tts/service.log
```

### 从旧机迁数据（想保留账号 / 历史 / 音色）

```bash
# 旧机上打包（在旧机执行）
sudo tar czf /tmp/tts-data.tgz -C /mnt/tts data

# 新机上解压（服务处于 stopped 状态时做）
sudo systemctl stop qwen-tts
sudo tar xzf /tmp/tts-data.tgz -C /mnt/tts
sudo systemctl start qwen-tts
```

`data/` 里有什么：

| 文件 | 内容 |
|---|---|
| `data/users.json` | 账号与密码哈希（**迁过去后旧口令照常可用**） |
| `data/jobs.json` | 历史任务记录 |
| `data/voices/voices.json` | 音色元数据 |
| `data/voices/*.wav` | 自动截取后的成品参考音频 |
| `data/voices/sources/*.wav` | 员工上传的原音频（较大，可按需保留） |

`output/` 里的成品音频若也要迁移，一并打包即可（只是体积大）。

## 7. 显卡不是 RTX 3060 12G 时

代码**会动态读显存**（`gpu_free_gib()`）来推算 batch，所以换成更大显存的卡无需改参数。

但有几个常量是按 12G 标定的，换小显存卡（如 8G）需要留意：

| 常量 | 位置 | 说明 |
|---|---|---|
| `SAFE_BATCH_TOKENS = 3650` | `tts_engine.py` | 单批 token 安全预算 |
| `OOM_THRESHOLD_TOKENS = 7300` | `tts_engine.py` | 实测崩溃阈值（仅日志对照） |
| `MAX_AUTO_BATCH = 8` | `tts_engine.py` | batch 上限 |

保护机制：即使参数不匹配，`_gen_batch_safe()` 捕获 OOM 后会**批量减半重试最多 3 次**，
不会真崩，只是变慢。所以 8G 卡大概率仍能跑，吞吐下降。

产能模型（`gen_seconds = 8.40 + 0.07374 × 字数`）是按 3060 实测回归的，
换卡后需重新用 `app/bench.py` 标定。

## 8b. ⚠️ 2026-10-05 新机（双卡 / Ubuntu 24.04）实测：三个必踩的坑

这次换机重装踩到的，**都是「不报错但功能是坏的」**，必须靠验收指标自己发现。

### 坑 1：torch wheel 别用国内镜像，直连反而快 65 倍

同样的 `torch-2.14.0+cu130` wheel：

| 源 | 服务器实测速度 |
|---|---|
| mirrors.aliyun.com/pytorch-wheels | ~100 KB/s（554MB 要下 1.5 小时）|
| **download.pytorch.org/whl/cu130** | **6.5 MB/s**（85 秒下完）|

装完务必 §8 第 2 条那样亲手验证 `+cu130` —— 这一步不能信 pip 的 Success 输出。

### 坑 2：双显卡时 `CUDA_VISIBLE_DEVICES` 必须写 UUID，不能写序号

**nvidia-smi 与 torch 的编号是反的**（CUDA 默认按算力 FASTEST_FIRST 排序）：

```
nvidia-smi:  index 0 = RTX 3060 (12G)   index 1 = RTX 3090 (24G)
torch:       device 0 = RTX 3090        device 1 = RTX 3060
```

写 `CUDA_VISIBLE_DEVICES=0` 会拿到 nvidia-smi 之外的另一张卡。必须用：

```bash
nvidia-smi --query-gpu=index,name,uuid --format=csv
Environment=CUDA_VISIBLE_DEVICES=GPU-94853612-464c-9177-c374-a9a82e321229
```

验证方式只有一种：`nvidia-smi` 看哪张卡有显存占用。

### 坑 3：🔴 ASR 内容回检会「静默失效」，CER 恒为 0 —— 最危险的一个

这是本次最严重的坑。**现象：所有任务 CER 都显示 0.0000 且「通过」，
日志里没有任何报错，于是「内容跑飞」一条都抓不到。**

两个成因，都在「任何异常都降级为跳过」的设计下被吞掉：

**① 模型缓存不在服务运行用户的 HOME 下**（root 跑服务，模型是 zheng 下的）

```
WARNING ASR 模型加载失败，本次及后续跳过内容回检:
        Cannot find an appropriate cached snapshot folder ... local_files_only=True
```

对策：把缓存钉死到数据盘，不再依赖 HOME——

```bash
cp -r ~/.cache/huggingface/hub /mnt/tts/models/asr/
Environment=HF_HOME=/mnt/tts/models/asr
Environment=HF_HUB_OFFLINE=1
```

**② faster-whisper ≥1.2 与 av ≥19 不兼容**（`av.container.open()` 的
`metadata_errors` 参数被移除）→ `TypeError` → 转写返回空串 → CER 记 skipped。

对策：不把文件路径交给 `transcribe`，改用 soundfile 读成 ndarray 传入
（见 `app/asr_check.py::_read_16k`）。注意传 ndarray 时 faster-whisper
**假定采样率就是 16000 且不重采样**，所以重采样必须自己做。

> ⚠️ 同理，`av` 别指望降级：`av<15` 没有预编译 wheel，会尝试从源码编译
> 并因为缺 `libavformat-dev` 等系统库而失败。

**怎么验收这三件事有没有修好**——看日志里这三行必须同时出现：

```
INFO  ASR 模型已加载: Systran/faster-whisper-small (cpu/int8)
INFO  第 1/1 块 第 1 次: CER=0.2000 通过          ← 非 0 的真值
WARNING ⚠️ ... 全部被跳过                          ← 这行必须消失
```

任务 `stats.asr_skipped` 必须为 **0**。韩语 small 模型的 CER 噪声底是
**0.2227**（见 MEMORY 第 4 节），看到 0.19~0.27 属正常；只有明显高于 0.30
才是真跑飞。**如果任何任务 CER 都恰好是 0，一定是回检坏了，不是发音完美。**
