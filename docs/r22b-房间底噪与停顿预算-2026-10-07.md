## 1. 电流声 / 瞬间停顿：根因是「数字真零」

逐 100ms 量前 8 秒（dBFS）：

```
我们 r22-6cdd25 : -128  -77  -27 ...    句中停顿 -173 -174 -158
我们 r22-8197d9 : -122  -74  -30 ...    句中停顿 -164 -163 -105
案例 6cdd25     :  -36  -19  -16 ...    句中停顿  -49  -50  -55
案例 8197d9     :  -35  -17  -13 ...    句中停顿  -51  -55  -51
```

帧电平分位数（0.05 s 帧）：

| | p5 | p25 | p75（语音） |
|---|---|---|---|
| 案例男 | −61.9 | −38.1 | −23.8 |
| 案例女 | −52.6 | −37.0 | −21.8 |
| 我们 | **−106 ~ −240** | −38.5 ~ −45.8 | −24.2 |

🔴 **我们的静音是 −160 ~ −240 dB 的数字真零**（模型输出就是零，不是"安静"），
案例是 −46 ~ −56 dB 的**房间底噪**。两个后果：

1. **瞬间停顿**：语音 −24 dB ↔ 静音 −240 dB，0.1 秒内跳 130 dB。人耳在
   "有"和"完全没有"之间硬切会觉得突兀、像卡了一下；案例是 −50 dB 的房间声，
   听感是自然的呼吸间隙。
2. **电流声**：低电平段经过 `libmp3lame` 时比特分配极少，量化噪声的相对
   失真很大；链路里的 aexciter / 空气感 EQ 在近零段做非线性处理会留下杂散
   产物，解码后就是"滋滋"的电流声。

**排除项**（都查过，别再查）：50/100 Hz 工频哼声（谱上没有尖峰）、
r22 新引入（r22 与 r20 开头完全一致）、电源/掉卡（Xid 只有 3 条且都是
Surprise Down，与音频无关，见 `docs/r22-3090掉卡根因与训练降载-2026-10-07.md`）。

### 修法：`app/roomtone.py`

粉红噪声（−3 dB/oct，6 kHz 以上再 −6 dB/oct），与案例实测底噪谱形吻合在几 dB 内。
电平取案例的 **p5 与 p10 之间**：男 **−56 dBFS**、女 **−50 dBFS**。

🔴 **叠放位置：响度归一 / 限幅之后、`libmp3lame` 之前**（陷阱 #18）。
叠在归一之前 → 闭环把多出来的能量整体缩回，等于白铺；叠在 mp3 之后 →
低电平段的量化杂散已经烤进成品，修不掉。ffmpeg 滤镜链里没有"我们要的粉红
噪声"，所以尾段拆两步：先出一份已归一/已限幅的 float wav，numpy 叠完再单独编码。

铺完实测 p5：−56.4 dBFS（案例 −52 ~ −66），✓。

## 2. 🔑 静音占比 +12.5%：唯一五例同向的系统性缺陷

`score()` 里所有偏差都取了绝对值，**看不出我们是偏高还是偏低**。新建
`tools/dump_cmp.py` 输出带符号偏差，五例一扫就清楚了：

```
维度        权重     1a6c20   00b6a4   ba24c0   8197d9   6cdd25   符号一致?
A       0.10    +11.06   -7.23   -5.48   -1.94   +2.09      混
B       0.08     +3.45   -2.10   +0.66   +2.08   +2.74      混
E       0.12    +10.85   -2.56  -11.35   -7.33  +18.44      混
D       0.08    +16.31   -5.50  +12.29   +3.82   +8.64      混
F       0.08     +0.02  -11.59   +5.32   +5.45   +9.89      混
sil     0.07     +7.77  +12.04  +17.06  +10.74  +14.75     一致 ✅
C       0.08     +2.34   +5.92   +9.45   +8.81   +5.74     一致 ✅
dur     0.10     -3.06   -0.67   -4.10   -1.12   -2.45     一致 ✅
```

**只有这三项方向一致 = 有方向、可以修。** A/B/E/D/F 五例方向乱 = 噪声，
再调只是换一批噪声（这条判断标准以后一直有效）。

### sil 的根因：多的是**条数**不是长度

```
案例 1a6c20   162 处 / 90.7 s（均值 0.560 s）
我们 1a6c20   178 处 / 94.8 s（均值 0.533 s）
```

按字数归一，我们比案例多 **11.5% 个停顿**，均值还略短。所以：

- `PBA_ALPHA`（给每条停顿乘系数）压不动 —— r15 已实测 α 收到 0.74 反而更糟；
- `mu`（给每条定均值）也压不动 —— 均值本来就对；
- **条数多了，总量就是多。**

### 修法：给条数一个预算

案例库「停顿数 / 字数」密度：男 **0.0400 条/字**、女 **0.0430 条/字**。
生成时 `预算 = 密度 × 本篇字数`，超出的**取最短的那些**压到 `FLOOR_MS`
（60 ms —— 低于 `sent_windows` 的 `min_sil=0.25 s`，检不出来）。

> 为什么不直接删掉：硬拼两个句段会在非零样本上切一刀，有爆音风险。
> 留 60 ms 既消掉了"停顿"，又留了接缝。

被压掉的那部分时间**不进 atempo 拉回** —— 拉回 = 把有声段加速，而 sil
偏高正是要靠减少静音来修的，拉回就白削了（与 r15 对 reshuffle 加长部分的
处理同一套道理）。

顺带留了 `pause_scale`（所有停顿等比 × f，F 严格不变）作为备选旋钮，
实测不如"压条数"，默认不用。

## 3. dur −2.3%：成品时长从来没对准过案例语速

五例**全部**偏短。原因：PBA 的 atempo 只负责把「被 α 压掉的静音」拉回原
时长，模型原生多快、成品就多快，从来没对准过案例。

改成按案例库 `Σ字数 / Σ时长` 反推目标时长（男 **8.330 字/s**、女 7.440 字/s），
仍用同一档 atempo 实现。atempo 是整体等比缩放 → **静音占比 / F / A / E 全部
不变，只动 dur 一项**，所以是零风险改动（顺带把"听着赶"也修了：我们的有声段
比案例快 5.0%）。

## 5. 🔴 新踩的坑：离线试算不能用 librosa 做变速

试算里 `durfix` 那一路（把总时长拉到目标）**全线崩 −6 ~ −9 个点**，
静音占比从 7.8% 直接跳到 20%+。一开始以为是"时长对齐"这个思路有问题。

真因：`librosa.effects.time_stretch` 是**相位声码器**，会把瞬态横向抹开，
静音缝里被填进拖尾能量 → VAD 的门限被整体抬高 → 检出的静剧增。

线上用的是 ffmpeg `atempo`（WSOLA，时域拼接），**不会**产生这个artifact。
所以这一路结论无效，时长对齐仍按 §3 上线，以线上实测量为准。

> **测量陷阱 #22**：离线试算里凡是涉及"变速"的步骤，必须和线上用**同一个**
> 实现（ffmpeg atempo ≠ librosa time_stretch），否则结论会完全相反。

## 7. r23 补丁：峰值定点（`app/peakfit.py`）

CF 涨了 1.6~3.4 dB，峰值偏差均值 16.68% → 18.68%（−0.12 个点），
其中 ba24c0 单项就从 6.7% 崩到 36.7%（**−1.8 个点**）。

实测结论（重要，别再试）：
- ffmpeg 的 `alimiter=limit=X` 在这个版本里**是纯增益** `output = input / X`
  （输入 0.771 / 0.386 / 0.154 输出一律 +2.05 dB），只在超过 0 dBFS 时硬夹。
  **改 limit 只是整体改电平，响度闭环会 1:1 补回来，CF 一点不变。**
- 硬缩放 `x *= target/peak` 同理，也是纯增益。
- 所以只能用**非线性**：阈值 t 以下线性、以上 tanh 渐进压向 1.0，
  t 由「输入峰值 P、目标峰值 Q」二分反解。目标 = 案例库 `peak_dbfs` 的
  性别中位数（男 −2.3 / 女 −2.4）。
- 🔴 安全阀 `KNEE_MIN=0.35`：压不到目标时就用"允许的最狠档"而不是放弃，
  但**永不在 −9 dBFS 以下动刀** —— 再往下就是整体压扁，会重演 r21
  「压包络 → 音色恶化」的翻车。
