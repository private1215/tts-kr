# UI 改版设计：让员工少点几下

> 日期：2026-09-30
> 背景：7 人团队、日产约 80 条韩语语音。当前生成一条要走 7~8 步，
> 其中 5 步是每天重复不变的设置。

---

## 1. 现状：一条语音的操作步骤

| # | 操作 | 是否每天重复 | 可否省掉 |
|---|---|---|---|
| 1 | 填「语音标题」 | 每次不同 | 可自动填 |
| 2 | 粘贴正文文案 | 每次不同 | **必须** |
| 3 | 切换 tab（预设音色 / 录入音色克隆） | 基本固定 | ✅ 可记忆 |
| 4 | 选音色（speaker / voice） | 基本固定 | ✅ 可记忆 |
| 5 | 选语言（Korean） | **完全固定** | ✅ 可记忆 |
| 6 | 选情感（平稳 / 亲切…） | 基本固定 | ✅ 可记忆 |
| 7 | 选语速 | 基本固定 | ✅ 可记忆 |
| 8 | 点「提交生成」 | — | **必须** |

**结论：8 步里有 5 步是可以不用点的。** 真正必要的只有「粘文案」和「提交」。

---

## 2. 改版方案（按优先级）

### P0-1 参数记忆：下次打开自动恢复上次设置

用 `localStorage` 记住 `mode(预设/克隆)`、`speaker`、`voice`、`language`、`emotion`、`speed`。
首次进入仍按系统语言给默认值，之后**以员工最后一次选择为准**。

- 改动位置：`index.html` 里读取 `#speaker/#voice/#language/#emotion/#speed` 的初始化处，
  加一层 `loadPref()` / `savePref()`（在 submit 时存、init 时读）
- 效果：员工每天只需「粘文案 → 提交」两步
- 注意：记忆要**按账号隔离**（key 带用户名），避免共用电脑时串了

### P0-2 批量提交：一次粘贴多条文案

员工手里往往是**一整批**稿子（一天 80 条）。现在只能一条一条粘。

- 文案框支持分隔符分段：空行 或 `---`
- 提交时自动拆成 N 个任务排队，标题自动编号（`标题-1`、`标题-2`…）
- 界面显示「将拆分为 N 条任务」确认一下，防止误提交
- 改动位置：submit 处理函数，拆 text → 循环 `POST /api/jobs`

### P0-3 队列批量下载

现在生成完要一条一条点下载。

- 队列列表每条加复选框，支持全选已完成任务
- 「下载所选」打包成 ZIP（服务端加一个打包接口，或前端用 JSZip 拼）
- 效果：80 条从点 80 次变成点 2 次

### P1-1 字数 → 预估时长 / 预估等待

现在 `#count` 只显示「0」。

- 显示字数、**预计音频时长**、**预计等待时间**
- 用本项目实测模型：`audio_seconds = 字数 / 6.15`（韩语），
  `gen_seconds = 8.40 + 0.07374 × 字数`
- 例：2000 字 → 约 325 秒音频、约 156 秒生成

### P1-2 默认语速改成 0.9（**直接提升质量**）

2026-09-30 全量实测（男 1999 字 / 女 1773 字）：
当前默认 1.0 生成的语速比案例原声**快 11.5~11.9%**，改成 0.9 后偏差缩到 **+0.4% / +0.7%**。

- 改动：`#speed` 默认选中 0.9
- 这是目前唯一被全量验证有效、且零成本的提升

### P1-3 最近使用的音色置顶

音色下拉里把最近用过的前 3 个提到顶部并标注「最近使用」，
避免每次在长列表里找。

### P2（可选）

- `Ctrl+Enter` 提交
- 任务完成浏览器提醒（Notification API）
- 常用文案模板（开场白 / 结尾固定话术，一键插入）
- 生成失败一键「用同样参数重试」

---

## 3. 与"语调不像"相关的 UI 补充

员工反馈「语调不行、太假」。已验证的部分靠后端解决，但 UI 上要**堵住误用**：

1. **韩语场景的音色引导**：语言选 Korean 时，音色列表把适用的排在前面，
   并对明显不合适的标注提示（避免拿中文/英文音色念韩语带入母语语调）
2. **给员工一个"A/B 试听"入口**：同一段文案可快速生成 2 个语速/情感版本对比，
   避免凭感觉反复提交

---

## 4. 落地顺序建议

| 批次 | 内容 | 风险 | 收益 |
|---|---|---|---|
| 第 1 批 | P0-1 参数记忆 + P1-2 默认语速 0.9 | 极低 | 每天省 5 步 × 80 条；质量直接提升 |
| 第 2 批 | P0-2 批量提交 + P0-3 批量下载 | 低（需后端配合打包） | 批量场景省 80% 点击 |
| 第 3 批 | P1-1 预估时长 + P1-3 最近音色 | 低 | 体验优化 |

第 1 批只改前端 `index.html`、不动后端，**可以立刻做**。
