# 韩语 TTS 韵律回归验证流程

> 建立日期：2026-09-30
> 用途：**每次改动代码后**，用同一套文案生成男声 + 女声，与案例原声对比，
> 判断改动是变好还是变坏。避免再出现"凭小样本感觉调参"的情况。

---

## 0. 为什么必须有这套流程

2026-09-30 用同一份代码做了两次测量，结论自相矛盾：

| 测量方式 | 男声 F0 均值偏差 | 句内动态偏差 | 结论 |
|---|---|---|---|
| 292 字片段（13 句） | **−13.2%** | 达标 | "音高是主因" |
| 1999 字全量（80 句） | **+1.2%** | **−28.4%** | "音高没问题，动态和语速才是主因" |

**小样本结论是错的。** 13 句的统计量根本不稳，据此调参会调错方向。
所以回归必须用**案例音频实际覆盖的完整文案**，不能图快截一小段。

---

## 1. 固定测试用例（不要随意改）

案例音频只覆盖文案的前半部分（由 ASR 转写定位）：

| 用例 | 源文案 | 案例音频覆盖 | 案例音频时长 | 音色来源 |
|---|---|---|---|---|
| 男声 | `docs/男声韩语和文案/nan.txt`（4091 字） | 前 **1999** 字 | 261.5 s | 同目录 `1.mp3` |
| 女声 | `docs/女声韩语和文案/아모텍tts.txt`（3431 字） | 前 **1773** 字 | 251.3 s | 同目录 `아모텍1.mp3` |

> 覆盖字数由 `tr.py`（ASR 转写案例音频）得到，转写文本长度即覆盖字数。
> 换案例音频时要重跑一次 ASR 重新定位，不要沿用旧数字。

## 2. 跑一次回归

脚本在服务器 `/tmp/regress.py`（也保存在本文件同目录备查）。
**全程走生产 API**（`POST /api/voices` → `POST /api/jobs`），不绕过任何业务代码，
所以测到的就是员工真实会拿到的结果。

```bash
# 基线：当前代码自动裁剪参考音频 + warm + speed 1.0
python3 /tmp/regress.py --round 1

# 对比：换成指定音色 / 改语速
python3 /tmp/regress.py --round 2 --vm EL_male_dyn --vf EL_female_dyn --speed 0.9

# 只跑一个性别
python3 /tmp/regress.py --round 3 --only male --speed 0.9
```

参数：
- `--round N`：轮次标签，决定输出文件名与音色名（`REG_male_r1`…）
- `--vm / --vf`：覆盖男/女声音色（测不同参考音频时必用）
- `--speed`：语速（CosyVoice3 是模型级插值，不是 atempo）
- `--only`：只跑 male 或 female

产出：
- `/tmp/regress/{male,female}_r{N}.wav` 生成结果
- `/tmp/regress/gt_{male,female}.wav` 案例原声（16 kHz）
- `/tmp/regress/history.json` 历轮结果，自动追加

## 3. 看哪些指标

`pros.py` 统一口径（pyin F0 + librosa 分句），与案例原声逐项比：

| 指标 | 含义 | 员工吐槽对应 |
|---|---|---|
| `f0_mean` | 整段平均音高 | 声音像不像这个人 |
| `onset_f0` | 每句起句音高 | **"起句没力气"** |
| `sent_dyn` | 句内音高起伏（半音） | **"语调平/假"** |
| `global_dyn` | 全段音高跨度 | 整体表现力 |
| `sent_dur` | 平均句长 | **"断句碎"** |
| `n_sent` | 句数 | 同上 |
| `onset_delta` | 相邻句起步落差 | **"越听越泄气"** |
| `ap_density` | 韵律单元密度 | 节奏感 |
| `cps` | 语速（字/秒） | **"说得太快"** |
| `CER` | ASR 回检错字率 | 内容有没有跑飞 |

⚠️ 判定纪律：
1. **只在同文本、同长度下比**。跨长度比较必错（本项目已踩 5 次）。
2. **CER 要先减噪声底**：faster-whisper-small 对案例原声自己就是 0.10~0.22，
   生成侧 0.07~0.27 都在噪声底附近，别当成发音差。
3. **指标只能排除明显退化，1:1 与否最终靠人耳盲听。**

→ **任何"换参考音频"的结论，必须在全量文案上复测才能算数。**

## 10. 维护注意事项

- **推送脚本后必须核对 md5**：`scpp.py` 曾静默丢包，导致服务器跑旧版脚本，
  白等 7 分钟还拿到错结论。
- **改 `.py` 后必须重启服务**：CPython 不热重载。重启后用
  `systemctl show <svc> -p ActiveEnterTimestamp` 确认启动时间晚于文件 mtime。
- 回归脚本会往 `voices.json` 注册 `REG_*_r*` 音色，积累多了记得清理。
