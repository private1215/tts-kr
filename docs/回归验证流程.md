# 韩语 TTS 韵律回归验证流程

> 建立日期：2026-09-30
> 用途：**每次改动代码后**，用同一套文案生成男声 + 女声，与案例原声对比，
> 判断改动是变好还是变坏。避免再出现"凭小样本感觉调参"的情况。

---

## 0. 为什么必须有这套流程

2026-09-30 用同一份代码做了两次测量，结论自相矛盾：

| 测量方式 | 男声 F0 均值偏差 | 句内动态偏差 | 结论 |
|---|---|---|---|
| 292 字片段（13 句） | **−13.2%** | 达标 | "音高是主因" |
| 1999 字全量（80 句） | **+1.2%** | **−28.4%** | "音高没问题，动态和语速才是主因" |

**小样本结论是错的。** 13 句的统计量根本不稳，据此调参会调错方向。
所以回归必须用**案例音频实际覆盖的完整文案**，不能图快截一小段。

---

## 1. 固定测试用例（不要随意改）

案例音频只覆盖文案的前半部分（由 ASR 转写定位）：

| 用例 | 源文案 | 案例音频覆盖 | 案例音频时长 | 音色来源 |
|---|---|---|---|---|
| 男声 | `docs/男声韩语和文案/nan.txt`（4091 字） | 前 **1999** 字 | 261.5 s | 同目录 `1.mp3` |
| 女声 | `docs/女声韩语和文案/아모텍tts.txt`（3431 字） | 前 **1773** 字 | 251.3 s | 同目录 `아모텍1.mp3` |

> 覆盖字数由 `tr.py`（ASR 转写案例音频）得到，转写文本长度即覆盖字数。
> 换案例音频时要重跑一次 ASR 重新定位，不要沿用旧数字。

## 2. 跑一次回归

脚本在服务器 `/tmp/regress.py`（也保存在本文件同目录备查）。
**全程走生产 API**（`POST /api/voices` → `POST /api/jobs`），不绕过任何业务代码，
所以测到的就是员工真实会拿到的结果。

```bash
# 基线：当前代码自动裁剪参考音频 + warm + speed 1.0
python3 /tmp/regress.py --round 1

# 对比：换成指定音色 / 改语速
python3 /tmp/regress.py --round 2 --vm EL_male_dyn --vf EL_female_dyn --speed 0.9

# 只跑一个性别
python3 /tmp/regress.py --round 3 --only male --speed 0.9
```

参数：
- `--round N`：轮次标签，决定输出文件名与音色名（`REG_male_r1`…）
- `--vm / --vf`：覆盖男/女声音色（测不同参考音频时必用）
- `--speed`：语速（CosyVoice3 是模型级插值，不是 atempo）
- `--only`：只跑 male 或 female

产出：
- `/tmp/regress/{male,female}_r{N}.wav` 生成结果
- `/tmp/regress/gt_{male,female}.wav` 案例原声（16 kHz）
- `/tmp/regress/history.json` 历轮结果，自动追加

## 3. 看哪些指标

`pros.py` 统一口径（pyin F0 + librosa 分句），与案例原声逐项比：

| 指标 | 含义 | 员工吐槽对应 |
|---|---|---|
| `f0_mean` | 整段平均音高 | 声音像不像这个人 |
| `onset_f0` | 每句起句音高 | **"起句没力气"** |
| `sent_dyn` | 句内音高起伏（半音） | **"语调平/假"** |
| `global_dyn` | 全段音高跨度 | 整体表现力 |
| `sent_dur` | 平均句长 | **"断句碎"** |
| `n_sent` | 句数 | 同上 |
| `onset_delta` | 相邻句起步落差 | **"越听越泄气"** |
| `ap_density` | 韵律单元密度 | 节奏感 |
| `cps` | 语速（字/秒） | **"说得太快"** |
| `CER` | ASR 回检错字率 | 内容有没有跑飞 |

⚠️ 判定纪律：
1. **只在同文本、同长度下比**。跨长度比较必错（本项目已踩 5 次）。
2. **CER 要先减噪声底**：faster-whisper-small 对案例原声自己就是 0.10~0.22，
   生成侧 0.07~0.27 都在噪声底附近，别当成发音差。
3. **指标只能排除明显退化，1:1 与否最终靠人耳盲听。**

保序分位映射：按对数正态把停顿长度重新分布，**原来偏长的映射后依然偏长**，

男 3.44 s → **0.414 s（要 +25%）**，女 9.65 s → **0.325 s（+0.3%，不用动）**。
→ **用一个公式自动只修男声**，这正是不能写死停顿倍数的原因。
裁短时保留能量最低的那一段（真正的静音核心），补长时重复最安静的 20 ms。

| 项 | ElevenLabs | 我们 | 差距 |
|---|---|---|---|
| 单请求字数上限 | v3 **5,000**（≈5 min）<br>multilingual v2 10,000（≈10 min）<br>flash 40,000 | 2,600 | 我们更保守，安全 |

| 跨块一致性 | v4 有 **context stitching**：跨请求保持语速/语气一致 | ❌ **没有**，两块独立生成，可能语气漂移 | ⭐ 下一步 |

（把上一块尾部 1~2 句作为下一块的 prompt / 或固定 seed）。

## ⚠️ 测量陷阱（必读）

### 陷阱一：librosa 版本

同一个 `gt_male.wav`，**qwen 环境（librosa 1.0.0）**测出 f0_mean 186.5 /
ap_density 3.65，**cosy 环境（librosa 0.10.2）**测出 183.4 / 4.07。
同一环境连测 3 次完全一致（可复现），所以是 pyin 实现差异，不是随机误差。
VAD 类指标（n_sent / sent_dur / cps）不受影响，**只有 F0 类指标受影响**。

→ **回归固定用 qwen 环境跑**（`source /mnt/tts/projects/qwen3-tts/venv/bin/activate`），
   手工对比也必须用同一个环境，否则数字对不上会误判。

### ⚠️ 陷阱二：24 kHz 的成品量不了 11 kHz 以上（2026-09-30，代价 30 dB）

lame 在 **24 kHz 输出时会把 11.2 kHz 以上一刀切掉**。拿这种文件量高频会得到
「−133 dB = 砖墙」的假象，真实值（出 44.1 kHz 成品）是 **−44.8 dB**。
r7 就是照着假象去补，线上过量 30 dB。

→ **凡是要量 11 kHz 以上，必须先出 44.1 kHz 成品**
  （`TTS_OUT_SR=44100`，或用 `systemctl set-environment TTS_AIR=0` 拿未处理版本）。

### ⚠️ 陷阱三：停顿判句是刀刃指标

我们的停顿普遍只有 0.26~0.29 s，紧贴 `GAP=0.25` 阈值。任何让停顿底噪 +1 dB
或峰值 +0.5 dB 的后处理，都会让若干停顿被判成有声（女声一次掉了 3 句）。
→ 判断"后处理是否破坏了断句"，要看 `sil_ratio` / `gap_rate` 是否同步变化，
  不要只看 `n_sent` 一个数。

### ⚠️ 陷阱四：调制谱的「相对占比」会互相挤占，必须同时看绝对 dB（2026-09-30）

`ms.py` 报的是**归一化占比**（某频段能量 / 0.5~20 Hz 总能量）。把 fast 带
（8~16 Hz）提上去，slow 带（0.5~4 Hz）的占比**会自己掉下来**，看起来像
「顿挫也修好了」，其实一点没动。r9 就差点被这个假象骗过去
（1~4 Hz 占比 0.5546→0.4703，绝对 dB 却只从 −42.46 到 −42.89）。

→ **凡是比较调制谱，必须同时看 `modabs.py` 的绝对调制深度（dB）**。
  且绝对 dB 也只在同文本、同长度、同响度之间可比（沿用第 4 节的铁律）。
