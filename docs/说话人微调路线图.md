# 说话人微调路线图（案例积累 → SFT）

> 背景：后处理只能**逼近统计量**（六维韵律 + LTAS + 响度），r18 后真实还原度是
> 男 94.48% / 女 96.45%，剩下的差距（静音分布、句尾多样性、能量动态）是**模型级**的。
> 要让模型**内化这个说话人 + 韩语金融广播场景**，只能微调。
> 本文是可执行的路线图：**员工不断加案例 → 数据量够了就训练 → 训练完回灌线上**。

---

## 1. 为什么选 CosyVoice3 而不是 Qwen3-TTS

| | 训练代码 | 现状 |
|---|---|---|
| **CosyVoice3** | ✅ 官方自带（`examples/libritts/cosyvoice2/run.sh` + `tools/`） | 已跑通、锁 3090、服务 active |
| Qwen3-TTS | ❌ **只有推理包**（`site-packages/qwen_tts`） | 自写 LoRA，风险高 |

**结论：微调走 CosyVoice3。** 微调后的 CosyVoice3 仍是「第二个引擎」，按 voice profile 路由，员工零感知。

## 3. ✅ Step 0：说话人身份核验 —— **已通过（2026-10-07 实测）**

脚本 `/tmp/spkchk.py`（campplus 嵌入 + 余弦相似度）。
⚠️ 坑：campplus 吃的是 **kaldi fbank(80 mel)**，不是波形，直接喂波形会 rank 报错。

| | 标杆男 `1a6c20` | 标杆女 `00b6a4` | `ba24c0` | `6cdd25` | `8197d9` |
|---|---|---|---|---|---|
| 标杆男 `1a6c20` | 1.000 | 0.328 | **0.935** | **0.943** | **0.924** |
| 标杆女 `00b6a4` | 0.328 | 1.000 | 0.309 | 0.321 | 0.319 |
| `ba24c0` | 0.935 | 0.309 | 1.000 | **0.971** | **0.957** |
| `6cdd25` | 0.943 | 0.321 | 0.971 | 1.000 | **0.949** |
| `8197d9` | 0.924 | 0.319 | 0.957 | 0.949 | 1.000 |

判定：同人 **> 0.75** / 不同人 **< 0.55**。

### 三个结论
1. ✅ **4 个男声是同一个人**（0.924~0.971）→ **可以混在一起训**
2. 🔴 **推翻了 r15 的一段错误注释**：r15 写着「yohan 3 例是另一个音色」，
   那是凭 LUFS 差 0.7 dB **猜的，从没做过核验**。已按实测改正。
3. ✅ **男声同人数据已达 ~34 分钟**（483.8 + 528.7 + 509.0 + 536.4 s），
   **够 §4 的「正式 SFT」门槛**。女声只有 7.65 分钟，还差 3 例左右。

> 以后每新增一例，都重跑一遍 `/tmp/spkchk.py`，低于 0.75 的**单独成组**、不混训。

## 4. 数据门槛（分阶段，别在数据不够时硬训）

| 单一说话人有效时长 | 建议动作 |
|---|---|
| **< 15 分钟** | ❌ 不训。过拟合会把模型训成只会念这几句 |
| **15 ~ 30 分钟** | 🟠 可试：LoRA / 小 lr（`5e-6`）+ 少 epoch（< 10）+ **必须留独立验证集** |
| **30 ~ 60 分钟** | ✅ 正式 SFT：`lr=1e-5`、`scheduler=constantlr`（官方 sft 推荐值） |
| **> 60 分钟** | ✅ 可加训 `flow` / `hifigan`，进一步提升音质与稳定性 |

⚠️ 「有效时长」= 去掉首尾静音、去掉 ASR 回检失败（CER > 0.30）的片段之后的时长。
⚠️ CER > 0.30 的片段说明对齐不可靠，**必须剔除**，否则会教模型念错。

## 5. 数据准备（命令级，照 run.sh 的 stage 0~3）

```bash
cd /mnt/tts/projects/cosy/repo/examples/libritts/cosyvoice2

# stage 0: 生成 wav.scp / text / utt2spk / spk2utt
#   每条 utt 建议切到 5~15 秒（按 ASR 词时间戳切到句末，别硬切）
python local/prepare_data.py --src_dir <切好的目录> --des_dir data/ko_male

# stage 1: 说话人嵌入
tools/extract_embedding.py --dir data/ko_male \
  --onnx_path /mnt/tts/models/Fun-CosyVoice3-0.5B/campplus.onnx

# stage 2: 离散 speech token
tools/extract_speech_token.py --dir data/ko_male \
  --onnx_path /mnt/tts/models/Fun-CosyVoice3-0.5B/speech_tokenizer_v3.onnx

# stage 3: 转 parquet
tools/make_parquet_list.py --num_utts_per_parquet 1000 \
  --num_processes 10 --src_dir data/ko_male --des_dir data/ko_male/parquet
```

⚠️ **切分必须用 ASR 词时间戳切到句末**，不能用固定长度硬切（记忆 §11：硬切会差 10 个百分点）。
⚠️ 文案里若有阿拉伯数字，先过 `normalize_ko_numbers()` 转成韩语读法再写进 `text`。

## 6. 训练（stage 5，只训 llm 即可）

```bash
export CUDA_VISIBLE_DEVICES="1"          # 锁 3090，别撞 3060 上的 Qwen 主服务
torchrun --nnodes=1 --nproc_per_node=1 \
    --rdzv_id=1986 --rdzv_backend="c10d" --rdzv_endpoint="localhost:1234" \
  ../../../cosyvoice/bin/train.py \
  --train_engine torch_ddp \
  --config conf/cosyvoice3.yaml \
  --train_data data/train.data.list \
  --cv_data data/dev.data.list \
  --qwen_pretrain_path /mnt/tts/models/Fun-CosyVoice3-0.5B/CosyVoice-BlankEN \
  --onnx_path /mnt/tts/models/Fun-CosyVoice3-0.5B \
  --model llm \
  --checkpoint /mnt/tts/models/Fun-CosyVoice3-0.5B/llm.pt \
  --model_dir exp/cosyvoice3/ko_male \
  --tensorboard_dir tensorboard/cosyvoice3/ko_male
```

⚠️ `conf/cosyvoice2.yaml` 里已经写了 sft 该改的两处（`lr: 1e-5`、`scheduler: constantlr`），
确认用的是 sft 值而不是 pretrain 值。
⚠️ 训练时**先把 `cosy-tts` 服务停掉**（都抢 3090，实测 OOM）。

## 7. 验收（不能只看 loss）

1. **留一验证集**：至少一个完整案例（~8 分钟）不进训练集，用来生成后跑还原度
2. **还原度必须回升**：用 `fidelity3.py` 对比「微调前 / 微调后」同一个案例
   - 目标：男 ≥ 96%、女 ≥ 97%（比 r18 的 94.48 / 96.45 各 +2 个点以上才算有效）
3. **CER 必须不退化**：> 0.30 说明模型被训坏了
4. **耳朵验收**：统计量涨了但听着怪，一样不能上线
