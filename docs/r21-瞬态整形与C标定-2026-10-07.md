## 2. 峰值/CF：为什么不能用「抬增益」修

成品峰值比案例低，最直觉的做法是补增益。但**响度归一会把 LUFS 拉回目标值**：

    补 +0.6 dB → LUFS 也 +0.6 → 闭环再缩 −0.6 → 峰值回到原处

1:1 抵消，白干。真正要修的是**峰值因数 CF = 峰值 − LUFS**：

| 案例 | 案例 CF | 我们 CF | 差 |
|---|---|---|---|
| 标杆男 1a6c20 | 22.60 | 22.00 | 0.60 dB |
| 标杆女 00b6a4 | 20.50 | **18.70** | **1.80 dB** |
| 대한광통신 ba24c0 | 22.10 | 22.10 | 0.00 |
| 세미파이브 8197d9 | 22.10 | 22.00 | 0.10 |

女声亏得比男声多 3 倍。根因推断：**女声 F0 高 → PROSO/PSOLA 的基频周期短 →
重叠相加平均得更狠 → 波形更平**。这与「女声 PROSO 后 RTF +26%（处理更重）」
完全吻合。CF 小 = 波形平 = 听感上就是员工说的「糊」。

### ❌ compand 向上扩展（已证伪）

`/tmp/trypost.py`：把中等以上电平再放大几 dB。

    base      峰值 −2.30
    eqd+exp   峰值 −2.60     ← 更差
    eqd+exp2  峰值 −4.30     ← 更差

原因：抬中电平会抬 RMS → 响度归一再整体缩回 → 峰值反而更低。

### ✅ 瞬态整形（transient shaper）

只抬**上升沿**、不动慢包络，所以 RMS 几乎不变、LUFS 不被吃掉：

    drive = clamp(fast_env − slow_env, 0, ∞) / slow_env
    y = x · (1 + amount · drive)

`fast_env` 攻击 1ms（跟得上辅音起音），`slow_env` 攻击 30ms / 释放 120ms
（代表「这段有多响」），两者之差只在能量上升时为正。

离线扫描（`/tmp/tshaper.py`，标杆女，同一把尺子）：

| amount | 峰值 dBFS | CF | C 偏差 | 总分 |
|---|---|---|---|---|
| 0.0 | −4.20 | 18.70 | 6.4% | 94.19 |
| 0.1 | −3.40 | 19.50 | 7.9% | 95.27 |
| **0.2** | **−2.40** | **20.50** | 10.0% | **95.80** |
| 0.3 | −2.00 | 21.00 | 12.1% | 94.55 |
| 0.5 | −1.90 | 21.00 | 15.1% | 95.36 |

amount=0.20 时 **CF 20.50 与案例 20.50 精确相等**，峰值也正好 −2.40 = 案例 −2.40。
男声 CF 只差 0.60 dB，按线性外推取 amount = 0.06。

## 3. 🔴 第一次上线失败：离线试算的**位置**必须与线上一致

第一版把整形放在整条编码链**之前**（24k 裸 wav 上，numpy 处理完再交给 ffmpeg）。
五案例实测**反效果**：

| 案例 | r20 峰值 | r21b 峰值 | |
|---|---|---|---|
| 标杆女 | −4.20 | **−5.10** | 更差 0.9 dB |
| 리노yohan | 0.0% 偏差 | **36.7%** | 崩 |
| 标杆男 | −2.90 | −3.10 | 略差 |

而离线明明是 +1.80 dB。差别只有一个变量：**离线叠在成品上（EQ / 空气感 /
响度归一全走完），线上叠在进链之前** —— 后面的 EQ、重采样到 44.1k、aexciter、
响度闭环把刚抬起来的瞬态又抹回去了。

✅ 修法（r21c）：把编码拆成两段

    第一段 ffmpeg：atempo → EQ → 重采样 44.1k → aexciter → 空气感 EQ  → pre_wav
    numpy：在 44.1k 的 pre_wav 上做瞬态整形
    第二段 ffmpeg：volume → 限幅 → mp3（响度闭环只重跑这一段，pre_wav 复用）

代价是每块多一次 wav 中转（几秒），换来「整形结果不被后级抹掉」。
冒烟验证：`瞬态整形 amount=0.06 峰值 −3.85 → −3.05 dBFS（44100 Hz）`。

### 🔴 但改对位置仍然不兑现（r21c 实测）

| 案例 | r20 峰值 | r21（错位置） | r21b（只留整形） | r21c（EQ 之后） |
|---|---|---|---|---|
| 标杆女 | −4.20 | −5.10 | −5.10 | **−5.00** |
| 标杆男 | −2.90 | −3.00 | −3.10 | −3.10 |
| 리노yohan | 0.0% 偏差 | 36.7% | 36.7% | 38.3% |

五案例均值：r20 **93.52%** / r21 93.21% / r21b 93.13% / r21c 93.32%。
三轮全部 ≤ r20，且**标杆女的峰值一次都没回到 −4.20**。

根因（这才是最贵的一条）：**离线标定量的是整形后的 wav，线上成品是 mp3**。
链尾还有 `libmp3lame`（以及验收时再解码回 24k）这一道，它把峰值基本重新定了一遍：
我们在 44.1k wav 上抬起来的 0.8 dB，到成品 mp3 里只剩 0.1 dB。

> 📌 沉淀为测量陷阱 #17：**离线试算的叠加位置必须等于线上实际位置**，
> 否则「离线有效、上线反效果」，而且看起来像随机噪声，极难排查。
> 📌 #18：**凡是「抬峰值 / CF」类的改动，必须在成品口径（mp3）上标定**，
> 在中间 wav 上量出来的收益不能外推。

## 4. ❌ 压 dyn 来修 C（证伪，已回退）

C 系统性 +8.2%，而 `dyn.py` 就是管 C 的模块。但它的 `k = clip(k, 1.0, 2.0)`
**只能扩不能压**，于是先放开到 `[0.70, 2.0]`，并把目标从 14.4/15.1 压到
12.7/13.6（= 案例中位 − 后级抬高量 − 整形抬升量）。

五案例实测：

| | r20 | r21（压 dyn + 整形@错位置） |
|---|---|---|
| C 能量动态 | +8.2% | **0.0%**（带符号）✅ |
| 标杆女峰值 | −4.20 | **−5.10** ❌ |
| 리노yohan 峰值偏差 | 0.0% | **36.7%** ❌ |
| 男声音色 LTAS | 5.2 / 9.8 / 6.1 / 9.1 % | 10.4 / 14.0 / 6.8 / 12.0 % ❌ |
| **均值** | **93.52%** | 93.21% ❌ |

根因：**压缩慢包络 = 把响的那部分真压下去，而峰值本来就长在响帧里**。
C 与 CF 在 dyn 这个模块里是**此消彼长**，两头都要 = 两头都拿不到。

🔑 教训写进代码注释：**别为了让一个指标好看而牺牲另一个更重的因果关系**。
C 的 +8.2% 是已知、可接受、不值得用 CF 去换的偏差。已回退到 14.4 / 15.1。

## 5. 已确认「不可修」的两项（别再花时间）

### A 句内音高动态（权重 0.10）

PROSO 只能打**一个**中位目标（男 Praat A = 9.956），而 4 个男声案例自己的
pyin A 是 8.362 / 8.833 / 9.100 / 9.565（中位 8.966）。我们的成品落在 8.95~9.26，
**已经在中位**；逐例 ±3~7% 是「用一个标量去拟合一个分布」的固有代价。
除非能按案例动态选目标（生成时并不知道要对标哪个案例），否则不可修。

### 峰值（部分）

案例之间峰值本身就差 2.2 dB（−0.90 ~ −3.10），LUFS 目标取中位后，
个别案例必然有 0.6~0.9 dB 的固有偏差。这部分不是缺陷。
