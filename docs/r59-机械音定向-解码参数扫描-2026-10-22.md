# r59：机械音定向 —— OmniVoice 解码参数（2026-10-22）

## 一句话结论
联网核对推翻了前一个前提：**OmniVoice 不是自回归 codec LM，而是掩码扩散模型（Diffusion LM）**。
那么"机械音"的主要可疑点不在声码器/音色，而在**解码参数**——而现役链这些参数**从未扫过，一直在用默认值**。
r59 扫描了 9 个变体 × 男女 × 3 次重复，找到 4 个方向（1 个已排除），并已把「可切换解码参数」做进服务端（默认行为不变），
z40 盲听素材已备好待装。

## 1. 联网核对：模型性质被记错了
论文 *OmniVoice: Towards Omnilingual Zero-Shot Text-to-Speech with Diffusion Language Models*（arXiv 2604.00688）：
**非自回归掩码扩散**（全码本随机 masking），0.8B，不是自回归 RVQ 逐帧生成。
→ 之前「codec LM → 换声码器封死 → 只能换引擎」的推论要收窄：**解码侧的 num_step / cfg / t_shift /
denoise / class_temperature 都是可调的**，而它们的默认值未必是"最自然"的那组。

## 2. 现役链现状（扫描前）
`omni_server.py:217` 只发 `text/ref_audio/ref_text` → 全部走 `OmniVoiceGenerationConfig` 默认值：

| 参数 | 默认 | 社区 ComfyUI 包基线 | 含义 |
|---|---|---|---|
| `num_step` | 32 | 28 | 扩散步数 |
| `guidance_scale` (cfg) | **2.0** | **3.0** | 条件引导强度 |
| `t_shift` | **0.1** | **1.0** | mask 时间表偏移 |
| `denoise` | **True** | **off** | 插 `<|denoise|>` 风格 token（不是滤波器！） |
| `class_temperature` | **0.0** | — | **0 = 纯 argmax（贪心）** |
| `postprocess_output` | True | — | 去静音 + 淡入淡出 + 补边 |

两个重点：
- `denoise` 的实现是 `style_text += "<|denoise|>"`（`omnivoice.py:1223`）——**它是让模型"把参考当噪声去处理"的指令**。
  我们的 EL 参考是干净录音，默认却一直在告诉模型"去噪" → 过度平滑。
- `class_temperature=0.0` → `log_probs.argmax(dim=-1)`（`:1448`）；>0 才走 top-k(ratio 0.1)+Gumbel 采样。
  **默认即完全确定性采样**，输出最"平均化"，是机械音的经典成因。

### 高频细节（4–12k / 0.2–3k 能量比；EL 男标杆锚点 = 0.0176）
| 变体 | HF 比 | 与 EL 的差 |
|---|---|---|
| base（现役） | 0.0142 | **−19%** |
| denoise_off | 0.0153 | −13% |
| cfg 1.5 | 0.0162 | −8% |

→ **现役参数下的高频细节比 EL 少 19%**，这是"闷/机械/不自然"的一个可测对应量；
`cfg=3.0` 把它补回 EL 水平，`denoise=False` 次之。

## 4. 优化点清单（按优先级）
| # | 优化点 | 依据 | 状态 |
|---|---|---|---|
| 1 | **`denoise=False`** | 参考是干净录音却让模型去噪；CER 持平、HF +8% | 待盲听（z40 候选 B） |
| 2 | **`guidance_scale=3.0`** | HF 补回 EL 水平（−2%）；与社区基线一致 | 待盲听（z40 候选 C） |
| 3 | **`class_temperature=0.6` + `denoise=False`** | 打破纯贪心采样；男 CER 最优 0.136、HF −6% | 待盲听（z40 候选 D） |
| 4 | `num_step` 48 / 16 | 32 已是最优（48 反而 CER 0.201、16 无收益） | 不动 |
| 5 | `t_shift` | 1.0 对韩语灾难（CER 0.38/0.83）；**t_shift 保持 0.1** | ❌ 已排除 |
| 6 | `postprocess_output=False` | 去静音会削掉自然停顿；CER 持平，待测 | 待盲听（二期） |
| 7 | 参考音频加长（15s→30s） | 官方/社区均提到"参考越长越有表现力" | 二期 |

## 5. 已做的实现（默认行为不变）
`omni_server.py`（备份 `.bak-before-genpar55`）：
- 新增 `_gen_keys` / `_gen_env_default()` / `_gen_overrides()`，支持键
  `denoise / guidance_scale / class_temperature / num_step / t_shift / position_temperature /
  layer_penalty_factor / postprocess_output`。
- 优先级：请求体 `gen` > 环境（`TTS_OMNI_DENOISE` / `TTS_OMNI_CFG` / `TTS_OMNI_CLASS_T` /
  `TTS_OMNI_STEPS` / `TTS_OMNI_TSHIFT`）> 默认。**全留空 = 行为与 v3.9 完全一致**。
- 日志加 `gen=` 字段，一眼看出这单用了什么参数。
- L1 实测：默认调用日志 `gen=-`；带 `gen` 调用日志 `gen={'denoise': False, 'class_temperature': 0.6}`；
  两次产物 md5 不同 → 覆盖确实生效。
- 上线方式：drop-in conf 写 `Environment=TTS_OMNI_DENOISE=0` + daemon-reload + 重启 omni-tts；
  回退 = 删 drop-in。
