# r25 还原度验收与峰值修复（2026-10-08）

结论先行：

1. **C（PROSO 全局 f0 基线平移）有害，已关闭**（`TTS_PROSO_MED=0`）。
   它把 tone（音色）从 14.9~26.8 推到 24.7~34.6，单项净亏 ≈ 0.83 分，
   而它想修的 f0 基线**并不进评分项**（B 量的是音高跨度，不是基线）。
2. **B（slowdyn 慢尺度能量轮廓）与基线持平**（−0.20，在噪声内），但它在
   可解释维度上确实改进了慢变结构，且标杆女 +1.88，**保留**。
3. **peak 是最大的可修单项**，新算法（分位数拐点 + 反解渐近上限）离线实测
   **+2.19 分，且 E/F/C/tone/LUFS 全部纹丝不动** —— 修好了 r24 的失败。
4. 顺带修掉两个度量/配置问题：响度闭环死区 0.5→0.15 dB；
   实测推翻「lame 过冲 +1.5 dB」（实为 **−0.2~−0.3 dB**）。

## 2. peak 修复：r24 失败根因 + 新算法

### 2.1 r24 为什么崩

旧公式渐近上限**固定为 1.0**，靠二分反解**拐点 t** 去凑目标峰值：

```
y = t + (1 - t) * tanh((|x| - t) / (1 - t))
```

要把峰值从 ~0.93 压到 ~0.76，反解出的 t 必然掉到安全阀下界
`KNEE_MIN = 0.35`（**−9 dBFS 以上全被压**）。真实语音 −9 dBFS 以上的样本
占比可达 5~15% → 能量分布上端被大面积改动 → 验收的 VAD 是相对阈值
`帧电平 < p25 + 6 dB`，p25 跟着动 → **判句/停顿检出整体漂移**。

实测 r24-1a6c20：94.34 → **92.77**，E 3.2→14.97、F 2.6→12.14，peak 只赚 +0.20。

**这是"改了度量基准"而不是"改好了音频"。**

### 2.2 新算法（`app/peakfit.py`）

反过来做：**拐点由样本分位数直接指定**，拿**渐近上限**当自由度去凑目标：

```
t = min(quantile(|x|, 0.999), 0.97 * q)      # 拐点：只碰最响的 0.1%
y = t + (a - t) * tanh((|x| - t) / (a - t))   # a 由 solve_asym() 二分反解
```

| | 旧（r24） | 新（r25） |
|---|---|---|
| 拐点来源 | 反解的副产品，必然掉到 0.35 | **样本分位数**（默认 p99.9） |
| 被压样本占比 | 5~15%（不可控） | **0.1%（可控）** |
| 能否命中目标 | 够不到，只降一点点 | **精确命中** |
| RMS 变化 | — | **−0.0045 dB**（LUFS 不动，闭环不补增益） |

### 2.3 离线试算（`tools/try_clip.py --mode q`，r25c 产物，成品口径）

| 案例 | base | 削峰后 | 变化 |
|---|---|---|---|
| 标杆女 | 94.42 | **96.32** | **+1.90** |
| 대한광통신 | 94.01 | **96.51** | **+2.50** |
| **均值** | 94.22 | **96.41** | **+2.19** |

逐项（括号是 base）：

| | peak 偏差 | E | F | C | tone | LUFS |
|---|---|---|---|---|---|---|
| 标杆女 | 31.7 → **0.0** | 1.7→1.6 | 4.6→4.6 | 3.5→3.5 | 27.2→27.2 | −23.00→−23.00 |
| 대한 | 41.7 → **0.0** | 1.3→1.3 | 2.3→2.3 | 6.5→6.5 | 18.1→18.2 | −25.00→−25.00 |

🔴 **E/F/C/tone/LUFS 全部纹丝不动** —— r24 的 VAD 漂移**没有重现**。

⚠️ 试算里目标用的是「案例自己的峰值」，线上只能用案例库**中位数**
（`peak_target()`，L1 最优）。所以真实收益会小于 +2.19，理论约 +1.0~1.5。

### 2.4 实测推翻「lame 过冲 +1.5 dB」

旧结论（陷阱 #7）说 mp3 编码会 +1.5 dB 过冲。这次实测：

```
wav -2.7 -> mp3 -2.9    过冲 -0.2 dB
wav -2.3 -> mp3 -2.6    过冲 -0.3 dB
```

**方向是反的**：mp3 峰值比源 wav 更低。所以 `OVERSHOOT_DB` 默认改为 **−0.25**
（wav 域目标 = 成品目标 + 0.25 dB）。

⚠️ 注意测法：必须测「wav → 编码 mp3」，不能测「mp3 → 解码 wav」
（后者是恒等式，测出来永远是 0）。

## 3. 响度闭环死区 0.5 → 0.15

`server.py` 的闭环是「编完成品 mp3 实测 LUFS，偏差超阈值才补增益重编」。
阈值硬编码 0.5 dB 太松：slowdyn / f0 平移引入的 0.3~0.5 dB 偏差正好落在死区里
被放过。改成常量 `LOUD_TOL`（env `TTS_LOUD_TOL`，默认 **0.15**）。

## 4. 口径说明：lufs 项没有恶化（别被两套数字骗了）

`eval5.py` 输出的是 `_dbdev` 折算失分（`|ΔdB| / 6 × 100`），
`tools/dump_cmp.py` 输出的是**带符号相对偏差**（`Δ / |case|`）。两者单位不同。

r25a 与 r25c 的成品 LUFS 实测值几乎一致：

| 案例 | r25a 成品/案例 | r25c 成品/案例 |
|---|---|---|
| 标杆男 | −24.7 / −24.3 | −24.7 / −24.3 |
| 标杆女 | −22.7 / −22.9 | −22.7 / −22.9 |
| 대한광통신 | −24.8 / −25.2 | −24.6 / −25.2 |

所以 lufs 偏差是「案例库目标中位数 vs 单个案例」的固有差异，**不是 B 引入的**。

## 5. 当前线上配置

| 开关 | 值 | 理由 |
|---|---|---|
| `TTS_SLOWDYN` | 1 | B，与基线持平且标杆女 +1.88，保留 |
| `TTS_PROSO_MED` | **0** | C 有害（tone 恶化），关闭 |
| `TTS_PEAK_FIT` | **1** | 新算法，实测 +2.19（离线），见 §2.3 |
| `TTS_LOUD_TOL` | 0.15 | 收紧响度闭环死区 |
| `TTS_PROSO` | 1 | 原有韵律移植，不动 |

已写入 `deploy/qwen-tts.service`（持久化，重启不丢）。回退方法：

```bash
systemctl set-environment TTS_PEAK_FIT=0    # 关削峰
systemctl set-environment TTS_SLOWDYN=0     # 关慢尺度轮廓
systemctl restart qwen-tts
```
