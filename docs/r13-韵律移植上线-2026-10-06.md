## 3. 原理：为什么 `k = target / cur` 一步到位，不需要迭代

F0 重映射用的是**单调缩放**：

```
semi' = center + (semi − center) × k
```

- 句内音高**宽度**（A）：`(semi_max − semi_min)' = (semi_max − semi_min) × k` → **精确乘 k**
- 句尾**斜率**（E）：`d(semi')/dt = k × d(semi)/dt` → **精确乘 k**

所以 A、E 与 k 是**严格线性**关系，`k = target / cur` 一次算完即可。
（与 `app/dyn.py` 的能量扩展同源，同一套思路。）

- A：绕**句中位数**缩放 → 只改句内起伏幅度，不改整体音高
- E：在**句尾 0.35 s** 额外叠 `k_tail`，用 smoothstep 权重 0→1 过渡，避免句尾突变
- 安全边界：`k ∈ [0.75, 1.35]`、整体音高位移限幅 4 半音
- `ae_of()` 用 Praat 量 A/E：20 s 段 0.02 s、240 s 段约 10 s
  （pyin 要 1~2 分钟，**这是能上生产的前提**）

## 4. Praat / parselmouth API 备忘（下次别再踩）

parselmouth **0.4.7 没有 `Manipulation` 类**，必须走 `praat.call` 底层命令：

```python
manip = praat.call(snd, "To Manipulation", 0.01, fmin, fmax)
pt    = praat.call(manip, "Extract pitch tier")      # ⚠️ 无参数，传 1 会 "not available"
praat.call(pt, "Remove points between", 0, dur)      # 清空
praat.call(pt, "Add point", t, f0)                   # 逐个加（没有 Set value at index）
praat.call([manip, pt], "Replace pitch tier")        # ⚠️ 多对象必须传 list，否则 ValueError
out   = praat.call(manip, "Get resynthesis (overlap-add)")   # ⚠️ 无参数
```

实测：20 s 段 0.02 s、240 s 段约 10 s，**长度保持、RMS 稳定**。

## 5. 已知偏差：男声 A/E 为什么没到位（原理已清楚）

proso **用 Praat 口径算 k**，验收**用 pyin 口径**（`prosody_report.py`）。
两个口径对同一段音频读数不同：

| | 案例 | 我们（PSOLA 后） |
|---|---|---|
| A：Praat / pyin | 9.495 / 8.362 | 9.495 / 9.395 |
| **两口径比值** | **1.136** | **1.011** |

比值对不上 —— **PSOLA 重合成让 pyin 读得更高**（重合成后 F0 轨迹更平滑，
pyin 的 voicing 判定更稳，极值更极端）。所以按比例换算失效，
按 Praat 目标 fit 完，pyin 一量就偏高。

**修法：按本轮实测反推校准目标值（下一轮）**

| | 目标 pyin | 实测 pyin | 需要 | 新的 Praat 目标 |
|---|---|---|---|---|
| 男 A | 8.362 | 9.395 | ×0.890 | 9.495 × 0.890 = **8.45** |
| 男 E | 34.559 | 29.025 | ×1.191 | 45.493 × 1.191 = **54.2** |
| 女 A | 9.470 | 9.565 | ×0.990 | 9.498 × 0.990 = **9.40** |
| 女 E | 34.410 | 33.059 | ×1.041 | 33.511 × 1.041 = **34.9** |

⚠️ 男 E 要放大到 k_tail ≈ 1.38~1.43，**可能过头**。
**必须先让耳朵验过女声那版没问题再动**，否则先只改 A。
**不要改成迭代求解** —— 比例换算是常数，迭代会绕回同一个坑。

## 6. 顺带修好：`fit_edges` 为什么线上「日志说修好了、实测没变」

排查过程（前两个猜测都被**推翻**，留档避免重走）：

1. ❌ **猜部署时序**（改完没重启）→ 加探针后推翻：日志 `head 0.020->0.060` 证明函数正常
2. ❌ **猜编码链 filter**（mp3/atempo/aresample/EQ/volume 改了边界）→ 逐个 filter 验证推翻，
   head 全程保持 0.04~0.06
3. ✅ **真根因：绝对阈值没做电平补偿**
   `sil_edges` / `fit_edges` 用 `-45 dB` 判「响」。
   pre-encode 判「响」的 −40 dB 弱起振段，经 `volume −6.2 dB`
   （`OUT_GAIN_DB −4.5` + 男声性别偏移 −1.7）后掉到 −45 以下 →
   成品量出来 head 还是 0.22。
   **修法**：`sil_db = EDGE_SIL_DB − gain_db`（−45 → ≈ −38.8），`_gain_db` 计算提前。

### 剩余：尾部 tail 仍差 0.12 s，不是 bug

日志 `tail 0.020->0.100（目标 0.227）` 看着没达标，但算下来是对的：
fit_edges 在 −38.8 口径下把 tail 修到 0.227，而诊断用 −45 口径量得 0.100，
差值是 **−38.8 ~ −45 dB 之间的弱余振**。
即：**我们的句尾是缓慢渐弱，案例是干净收尾**，同一个阈值量出来自然不同。
要真对齐得做**尾部包络锐化**（优先级排在 EQ 和响度后面）。

## 7. 顺带查出（本轮**没改**）：音色 EQ 低频方向是反的

方法：长时平均谱（LTAS）—— 两边重采样到 24 kHz、只比 60 Hz~11 kHz
（11.2 kHz 以上是 lame 的刀，不可比）、只取有声帧（帧 RMS 高于该段 p35）、
每段先按总能量归一化（响度差异单独用 LUFS 处理，避免把「整体轻 5 dB」
