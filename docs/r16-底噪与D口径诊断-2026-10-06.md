# r16 底噪与 D 口径诊断（2026-10-06）

## 结论先行

1. **🔴 发现一个真实的保真度缺陷（不是指标问题）**：ElevenLabs 案例的「停顿」
   不是静音，是 **−53 ~ −65 dB 的房间底噪（room tone）**；我们的停顿是
   **−120 dB 的数字真零**，差 50~67 dB。案例一帧真零都没有，我们有 2.0~8.3%。
   → 已做出「铺底噪」版本供耳朵验收：`docs/试听-r16-2026-10-06/试听对比.html`
2. **男声 D 语速CV +25.8% 是度量口径问题，不建议为它改音频**。按有声时间归一化后
   （D_voiced）我们男女都已**优于**案例（男 0.119 vs 0.129、女 0.123 vs 0.137）。
   且女声 D 反而比案例低 14%，男女方向不一致 → 非系统性缺陷。
3. **女声 pauses +28.6% 的两种修法都已试算，都会砸 E**，需耳朵拍板（见下）。
4. **CosyVoice3 本轮打通**（原以为卡在 openai-whisper，实际卡的是一串小依赖），
   韩语 ASR 回检通过；剩一个数字被念成英文的硬伤，修法已确定。

## 一、底噪：案例的停顿不是静音

帧级能量（50ms 窗 / 25ms hop）对比：

| 样本 | p25 | p50 | 底噪(p10 以下均值) | 最小 | 真零帧(<-100dB)占比 |
|---|---|---|---|---|---|
| 案例-男 | −38.0 | −28.8 | **−64.7 dB** | −92.9 | **0.000** |
| r15-男 | −42.3 | −28.6 | **−115.0 dB** | −120.0 | **0.083** |
| 案例-女 | −37.0 | −26.6 | **−53.0 dB** | −69.3 | **0.000** |
| r15-女 | −38.7 | −27.4 | **−77.3 dB** | −120.0 | **0.020** |

中位数能量几乎一样（−28.8 / −28.6），差的是**低能量那一端**。
案例是真实录音（带房间声、换气、句尾衰减），我们是合成真零。

**试算**：把案例静音段的真实 room tone 循环铺到成品上（电平按能量相加对齐案例底噪）
→ `docs/试听-r16-2026-10-06/` 的 `r16-*-铺底噪.mp3`。

⚠️ **铺底噪不改变 D**（实测 0.161 → 0.161，sil_mu 0.282 → 0.283）。
所以它不解决指标，只解决听感 —— 这正是需要耳朵判断的部分。

## 二、D 语速CV：根因是度量口径，不是语速不均

D = 3 秒窗 onset（音节）密度的变异系数。展开看：

| 样本 | D | **D_voiced**（按有声时间归一） | corr(rate, 窗内静音占比) | sil_mu |
|---|---|---|---|---|
| 案例-男 | 0.128 | 0.129 | −0.45 | 0.366 |
| r15-男 | **0.161** | **0.119** ✅ | **−0.68** | 0.282 |
| 案例-女 | 0.150 | 0.137 | −0.50 | 0.360 |
| r15-女 | 0.129 | 0.123 | −0.47 | 0.337 |

- **D_voiced 我们男女都优于案例** → 有声段语速其实更均匀，不是「忽快忽慢」。
- 男声 D 与 sil_mu 呈完美单调（5 次重跑：sil 0.282→D 0.161、sil 0.342→D 0.137、
  案例 sil 0.366→D 0.128），即 D 完全由「帧级低能量占比」决定。
- 根因：**合成音频能量分布双峰**（要么很响要么真零），真人录音有大量中间态低能量帧。
  同一个相对阈值 `percentile(edb,25)+6` 在两边切出的静音比例差 0.02~0.08。
- **5 次同配置重跑的 D 分布**：0.137 / 0.142 / 0.143 / 0.147 / 0.152 / 0.161
  （中位 0.147，案例 0.128）→ 是系统性偏差，但根因在口径。
- 另：C 能量动态我们比案例**高** 4.5%(男)/7.5%(女)，不是「能量动态不足」。

**处理**：把 D_voiced 提为主指标、D 降为参考，并在报告中注明跨「合成 vs 真人录音」可比性限制。
不为 D 改音频（强行对齐需要往有声段塞低能量帧，会引入"虚/气声"，反更假，且会牺牲 C）。

## 三、女声 pauses +28.6%：两种修法都会砸 E（需拍板）

离线在 r15 成品上试算（pauses 目标取案例值：男 162 / 女 147）：

### 方案 A：合并最短的 K 个停顿（两侧有声段直接相接）
| | segs | pauses | D | **E** | F |
|---|---|---|---|---|---|
| 案例-男 | 154 | 162 | 0.128 | 34.56 | 0.886 |
| r15-男 | 166 | 175 | 0.161 | 32.55 | 0.919 |
| **合并后-男** | 157 | **164** ✅ | 0.148 | **28.42** ❌ | 0.976 |
| 案例-女 | 138 | 147 | 0.150 | 34.41 | 0.782 |
| r15-女 | 157 | 189 | 0.129 | 37.65 | 0.818 |
| **合并后-女** | **137** ✅ | **149** ✅ | 0.146 | **29.97** ❌(−12.9%) | 0.763 |

### 方案 B：压短到 0.20~0.275s（不停顿删掉，只是不再计入 ≥0.28s 口径）
| | segs | pauses | D | **E** | F |
|---|---|---|---|---|---|
| **压短后-男** | 158 | **164** ✅ | 0.151 | **27.92** ❌(−19.2%) | 0.967 |
| **压短后-女** | 149 | **156** | 0.137 | **31.67** ❌(−8.0%) | **0.817** ✅ |

已排除的干扰：截断位置（保留开头/结尾/中间）实测 E = 27.92 / 27.54 / 27.54，
**与截断方式无关** → E 的跌幅是真实的，不是试算手法的假象。

**为什么 E 必然跟着动**：我们的 E 有一部分来自「句内微停顿前的收尾」，
案例没有句内停顿、E 全部来自真句尾 —— **两边的 E 不是同一个东西**。
动停顿 = 动 E，无法只改一个。

⚠️ 暂不上线：这是听感方向的取舍（"碎" vs "尾声一个调"），只有耳朵能判。

## 四、CosyVoice3：本轮打通

### 卡点真相
旧记录「卡在 openai-whisper 没有 py3.12 wheel」**已不成立** —— 装的是 20250625，
`log_mel_spectrogram` 正常。真正缺的是一串小依赖：

|---|---|

| `loguru` / `einx` / `frozendict` / `torch_einops_utils` / `rotary-embedding-torch` / `einx` | DiT 依赖 |

启动方式（必须带 PYTHONPATH，否则 `No module named 'cosyvoice'`）：
```

PYTHONPATH=/mnt/tts/projects/cosy/repo:/mnt/tts/projects/cosy/repo/third_party/Matcha-TTS \
CUDA_VISIBLE_DEVICES=1 venv/bin/python ...
```

### 冒烟测试结果
- 模型加载成功，`AutoModel(model_dir=/mnt/tts/models/Fun-CosyVoice3-0.5B)`
- 韩语零样本克隆出声（7.68s 音频 / 生成 11.2s，含 warmup）
- **显存峰值 3.57 GiB** → 3090 24G 完全够，与 3060 上的 Qwen 物理隔离，不必串行
- ASR 回检（faster-whisper-small, ko）：
  - 原文：`오늘 코스피는 외국인 매수세에 힘입어 전 거래일보다 12포인트 오른 2,610선에서 마감했습니다.`
  - 转出：`오늘 코스피는 외국인 매소스의 힘입어 전 거래일보다 12포인트홀은 2,6 한자된 텐션에서 마감했습니다.`
  - 主体正确 → **韩语可用** ✅（对比 IndexTTS-2 的 CER 0.97 是天壤之别）

### 唯一硬伤：数字被念成英文
`cosyvoice/cli/frontend.py` 的 `text_normalize()`：
```python
if contains_chinese(text):   -> 中文路径
else:                        -> 英文路径
    if self.text_frontend == 'wetext': text = self.en_tn_model.normalize(text)
    text = spell_out_number(text, self.inflect_parser)   # ← 元凶，与 wetext 无关
```
韩语不含中文字符 → 走英文路径 → `12`→`twelve`、`2,610`→`two,six hundred and ten`。
金融播报全是数字，必须先修。

**修法（已确定）**：走官方 generator 通道 ——
```python
if isinstance(text, Generator):
    logging.info('get tts_text generator, will skip text_normalize!')
    return [text]
```
即：我们自己分句 + 自己把数字转成韩语读法，用 generator 传给
`inference_zero_shot()`，完全绕过 TN 和英文分句规则。
