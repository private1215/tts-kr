# r54 · 模型层突破方案：为什么换不了声码器，以及能做什么

日期：2026-10-21　背景：z37 盲听「我们全部判 C=明显是机器，EL 全部判 A=像真人」

## 一、先回答「能不能换个更好的声码器」——❌ 不能，架构不允许

`models/OmniVoice/config.json` 实测：

```json
"architectures": ["OmniVoice"],
"audio_codebook_weights": [8, 8, 6, 6, 4, 4, 2, 2],   ← 8 层 RVQ
"audio_vocab_size": 1025, "audio_mask_id": 1024,
"llm_config": { "architectures": ["Qwen3ForCausalLM"] }
```

外加 `audio_tokenizer/` 子目录 → **OmniVoice 是 codec LM（VALL-E 类）**，
模型输出的是 **codec token**，波形由**内置的 codec decoder** 还原。

- 业界的高保真声码器（BigVGAN / Vocos / BemaGANv2 / RingFormer）**吃的是 mel 谱**，
  不是 codec token → **接不上**。
- 要换，只能重训 codec decoder 并与模型重新对齐 = **等于重训半个模型**。

> 参考（联网）：MUSHRA 排行 BigVGAN 4.61 > Pupu-Vocoder 4.58 > Vocos 4.55 >
> HiFi-GAN 4.38；BemaGANv2 长音频 MOS 3.46 超 BigVGAN 3.07。
> 但这条路的收益我们**拿不到**——omni 不是 mel+声码器架构。

**结论：声码器这条路封死。差距要从「模型本身」和「引擎选型」上找。**

## 五、🔴 联网搜到的实操坑（开跑前必看）

来自 `instavar.com/research/tts/qwen3-tts-lora-finetuning`（24GB 实测）：

1. **官方 `sft_12hz.py` 有两个 bug**：缺 `text_projection` 调用；**double label-shift
   导致语音渐进性加速**。→ 别把「epoch 10 最佳」当真理，先打补丁。
2. **学习率**：官方默认 2e-5 太高，**1.7B 用 2e-6**。
3. **LoRA scale 是部署旋钮**：scale 1.0 会**过冲出噪声**；上线前必须扫
   0.2 / 0.3 / 0.35 / 0.5，**0.3~0.35 最稳**。
4. **数据必须 24 kHz**：codec 预处理遇到 16k/44.1k/48k 会直接
   `AssertionError: Only support 24kHz audio`，且是在训练深处才崩。
5. 🔴🔴 **「No-prompt generation gave the best naturalness — Prompted inference
   copied prompt room noise into the output」**
   → **我们现役 omni 正是用参考音频（prompt）的**，可能一直在把参考音频的房间噪声
   复制进输出。这一条**必须单独做对照实验**（无 prompt vs 有 prompt）。
