## 1. 结论先行

员工反馈的两个问题，**都能量化定位，且都不是"模型跑飞"**：

| 问题 | 量化结论 | 根因 |
|---|---|---|
| **AI 味（机器味/发闷）** | 频谱质心 **862Hz（男）/725Hz（女）** vs ElevenLabs **1029Hz/813Hz**；2-4kHz 能量占比 **8.19%/5.39%** vs **12.95%/6.53%** | 我们 1:1 复刻了**原始素材本来就暗**的频谱；ElevenLabs 在输出侧做了「播报级提亮」 |
| **一个调（语调平淡）** | **不是**句内没升降——句尾降调平台 88.2% > El 84.0%，句内半音范围平台 18.10 > El 16.20，都正常。真正的差距是**段落级**：20 秒窗口间 F0 中位数标准差，男声 15.4/9.4 vs El 19.0/12.9，女声 13.0/11.3 vs El 19.3，**低 22%~37%** | 每段独立生成 + **所有段共用同一个 seed** + Base 模型没有 instruct 通道，导致缺少跨段落的音高布局 |
| **语速调节** | `generate_voice_clone` **没有 speed/pitch 参数**（源码 + 官方 README 双重核验） | 硬约束，只能做后处理变速 |

一句话：**AI 味 = 缺 2-4kHz；一个调 = 缺段落级音高布局。两者都在生成之后可修，不涉及模型改动。**

## 2. 证据

### 2.1 频谱：AI 味的客观来源

方法： librosa STFT，统计长时平均功率谱的质心与分频段能量占比。

| 文件 | 说明 | 质心(Hz) | 2-4kHz 占比% | 有效带宽(kHz) |
|---|---|---|---|---|
| 原始男声素材 `1.mp3` | 源录音 | 838 | 8.58 | 5.3 |
| `builtin_male.wav` | 14.5s 参考片段 | 843 | 8.71 | 5.9 |
| **plat_male1** | **平台成品** | **862** | **8.19** | 6.2 |
| `21.mp3` | **ElevenLabs 男声** | **1029** | **12.95** | 5.9 |
| 原始女声素材 `아모텍1.mp3` | 源录音 | 809 | 6.40 | 5.5 |
| `builtin_female.wav` | 14.6s 参考片段 | 724 | 5.80 | 5.8 |
| **plat_female1** | **平台成品** | **725** | **5.39** | 5.6 |
| `1와이씨.mp3` | **ElevenLabs 女声** | **813** | **6.53** | 5.6 |

**读法**：
- 平台成品质心（862 / 725）≈ 源录音质心（838 / 809）→ **我们完整复刻了素材的"暗"**。
- ElevenLabs（1029 / 813）**比源素材还亮 23%** → 它在输出侧主动加了 presence。
- 2-4kHz 是人耳最敏感的"清晰度/临场感"频段。缺这个频段，听感就是**发闷、像电话、像机器**。

> 这与项目既有文档一致：`app/voice_match.py` 头部注释已经写明
> 「Qwen3-TTS 克隆出来的语音相对真人原声**系统性缺 2~4kHz 能量**」。

**为什么现有的「保真增强」没能解决？**

`voice_match.py` 的做法是把成品 LTAS 对齐到**音色源录音的 LTAS**。
它的目标就是素材本身，所以**天花板 = 素材亮度**，只能做到"和素材一样暗"，无法超越素材达到 ElevenLabs 的水平。

而且这次两个 builtin 音色 `.wav` 对应的 `sources/` 目录是**空的**（只剩一个已删除音色 요한 쿡 的孤儿文件 25s.wav），
`get_target()` 只能退回到 14.5 秒的参考片段去算 LTAS——用 14.5 秒估计一条长时平均谱，统计代表性本就不足。

任务侧确认（`jobs.json`）：两个任务 `enhance=None`（提交时未显式传），但服务端默认开了增强，
`voice_matched` = 71/71 和 48/48，**每段都跑了匹配**，所以确实用了上面那条偏暗的目标曲线。

### 2.2 韵律：到底哪里"一个调"

逐层排查，把"平淡"拆成四个层次看：

| 层次 | 指标 | 平台 | ElevenLabs | 判定 |
|---|---|---|---|---|
| 句尾语调 | 句尾降调占比 | 88.2% / 87.5% | 84.0% / 85.7% | 平台**更好**，正常 |
| 句内动态 | 半音范围 p5-p95 | 18.10 / 14.50 | 16.20 / 14.50 | 平台**不低于**，正常 |
| 局部抖动 | jitter | 2.46 / 2.17 | 2.25 / 2.07 | 平台**更抖**，不是"过于平滑" |
| **段落级布局** | **20 秒窗口间 F0 中位数的标准差** | 男 15.4 / 9.4；女 13.0 / 11.3 | 男 19.0 / 12.9；女 19.3 | **平台低 22%~37%，唯一系统性差距** |

**这是本次分析最重要的发现**：
员工的"全程一个调"，不是句子没有升降（句尾降调反而是我们更足），
而是**听了 5 分钟，基准音高几乎不移动**——没有"开场定调 → 中段推进 → 高潮强调 → 收尾放缓"的宏观起伏。
ElevenLabs 的模型会做这种段落级的音高布局，我们没有。

**结构性原因（三个叠加）**：

1. **每段独立生成**：`server.py` 按 2600 字分块，每块内再按 60 字切段（`max_chars=60`），
   每段约 20 秒、**各自独立**合成，段与段之间没有任何韵律继承关系。
2. **所有块共用同一个 seed**（新发现，见 `server.py:424`）：
   ```python
   for ci, chunk_text in enumerate(chunks):
       for attempt in range(ASR_MAX_RETRY + 1):
           seed = base_seed + attempt * 7919   # ← 只有 attempt 变，ci 不参与
   ```
   `seed` 只在重试时变，**块的序号 `ci` 完全没参与**。所有块用同一个采样起点，
   在相似的句式/长度上会放大"同一套随机性模式"，是"复读感"的直接放大器。
3. **Base 模型没有 instruct 通道**（硬约束，已核验）：
   - 远端源码：`/mnt/tts/projects/qwen3-tts/venv/lib/python3.12/site-packages/qwen_tts/inference/qwen3_tts_model.py:470`
     `generate_voice_clone(...)` 的参数里**没有 instruct**。
   - 官方 README 模型能力表：`Qwen3-TTS-12Hz-1.7B-Base` 的 **Instruction Control 列为空**；
     只有 `1.7B-CustomVoice` 和 `1.7B-VoiceDesign` 是 ✅。
   - CustomVoice 虽然支持 instruct，但它**不接受 ref_audio**，只能在官方 9 个预设音色里选，
     **会丢掉员工的克隆音色**——这条路线与项目目标冲突，不采用。

### 2.3 语速：核验结论

- 远端源码与官方 README 双重确认：`generate_voice_clone(text, language, ref_audio, ref_text, voice_clone_prompt, x_vector_only_mode, **generation_kwargs)`
  **没有 `speed` / `pitch` / `emotion` 参数**。
- 网上有些文章写了 `speed=1.0, pitch=1.0, emotion="neutral"`，那是**幻觉**，不是官方 API，不能照抄。
- 结论：**模型侧无法控速，唯一路径是生成后的变速处理**。

## 3. 方案（待复审）

### 问题一：AI 味 → 输出侧「播报提亮」EQ

**做法**：在现有 `voice_match` 之后，再叠加一条固定的 presence 曲线：
- 2~4kHz 提升 **+4~6 dB**（补清晰度）
- 轻微高频 shelf（>6kHz）+2 dB（补空气感）
- <150Hz 轻微 -2 dB（去浑浊）

**为什么可行**：完全在后处理，不碰模型、不吃 GPU、不影响生成时长和 ASR 内容正确性。
`voice_match.py` 已有 `CLAMP_DB` 限幅和 mel 轴平滑（`SMOOTH=9`）机制，复用即可避免金属味/嘶声。

**量化验收目标**：质心 862→≈1000 Hz（男）、725→≈800 Hz（女）；2-4kHz 占比 8.19%→≈12%。
即逼近 ElevenLabs 的水平，而 **CER 必须保持 0.0000**（内容不能被 EQ 破坏，用 ASR 复核）。

**风险与兜底**：提升过头会有嘶声。做法是把强度做成环境变量可调，先用「弱 / 中 / 强」三档出样品让员工盲听选。

### 问题二：一个调 → 三招叠加

| 方案 | 内容 | 改动量 | 风险 |
|---|---|---|---|
| **A. seed 按块递增**（推荐先做） | `seed = base_seed + ci*104729 + attempt*7919` | 1 行 | 极低，可回滚；不改变内容，只改变采样随机性。已有 ASR 内容回检兜底 |
| **B. 宏观韵律整形**（主力） | 按段在全文中的相对位置，给每段一个缓变的 **pitch offset（±1.5 半音）+ 能量 offset**，构造"起→承→强调→收"的曲线 | 新增一个后处理模块 | 中；需要听测确认不引入 artifacts，建议先离线出样品 |
| **C. 换更起伏的参考片段** | 重新为女声挑语调动态更大的 15 秒片段 | 重跑 make_builtin | 低；但女声素材本身半音范围只有 ~14，天花板有限 |

**建议顺序**：A 先上（零风险） → B 出样品盲听 → C 视女声改善程度决定。

> B 的实现注意：Base 模型不支持 instruct，**不要试图用"请用更有感情的语气朗读"这类指令**，
> 在 Base 上无效。这条路要从波形/韵律层面做，或者换模型（会丢克隆音色，不采纳）。

### 问题三：语速调节

- 位置：生成完成、写 mp3 **之前**插值处理。
- 实现：`ffmpeg -filter:a atempo=<rate>`（变速**不变调**），ffmpeg 已在链路里，无新依赖。
  若追求更高质量可换 Rubber Band（需装二进制，暂不必要）。
- UI：语速下拉 `0.9 / 1.0（默认）/ 1.1 / 1.2`，提交任务时作为参数传入。
- 取舍：atempo 在 0.5~2.0 区间质量很好，1.0~1.2 完全无感；
  变速会让成品时长按倍率线性缩短（1.2 倍 ≈ 缩短 17%），这是预期行为。
- 注意：**语速参数要写进 job 记录**，方便复跑和追溯。

## 附：分析方法

- 韵律：`librosa.pyin` 提取 F0（fmin=65, fmax=2100），统计半音范围、句尾斜率、20 秒窗口间 F0 中位数标准差。
  基频数值用**谐波积谱（HPS）交叉验证**过，排除八度误判（pyin 与 HPS 结果一致量级）。
- 频谱：4096 点 STFT 长时平均功率谱，质心 = Σ(f·P)/ΣP，累积能量 99.5% 处为有效带宽。
- 样本：各文件统一截取前 100 秒（宏观分析取前 200 秒），统一 16kHz 单声道后比较。
- 平台成品来源：服务端 `/mnt/tts/output/` 下两个任务的 mp3，下载到 `/tmp/cmp/plat/` 后统一分析。
