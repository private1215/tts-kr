# 员工使用手册：怎么生成最贴近标杆（ElevenLabs）的韩语语音

> 版本对应 **r14**（2026-10-06）。服务器：局域网 `http://192.168.1.101:8000`、
> 远程 `http://100.89.104.29:8000`。
>
> 一句话：**员工要操心的只有两件事——文案干净、参考音频的字稿完整。**
> 响度、频谱、韵律移植、断句这些全部由后端自动完成，不需要也不应该手动调。

---

## 一、标准流程（三步）

| 步骤 | 操作 | 要点 |
|---|---|---|
| 1 | 首屏「文案」填标题 + 粘贴正文 | 标题是日后检索的唯一依据，别留空 |
| 2 | 「声音」页签选 **录入音色克隆** → 选已录入的音色 | 想用内置音色选「预设音色」，但克隆才对标案例 |
| 3 | 其余**全部保持默认** → 提交生成 | 见下方逐项说明 |

`Ctrl/Cmd + Enter` 可直接提交。提交后不用盯着，任务队列会显示排队位置和预计时间。

---

## 二、每个选项该怎么选（附实测依据）

| 选项 | 推荐值 | 为什么 / 改了会怎样 |
|---|---|---|
| **语言** | Korean | 首次进入跟随系统语言，**手动选过之后永远以你的选择为准** |
| **声音模式** | 录入音色克隆 | 对标 ElevenLabs 的场景一律用克隆 |
| **情感** | **平稳（standard）** | ⚠️ 见下方红字：**现在选其它三项得到的成品和「平稳」完全一样** |
| **语速** | **1.0** | 变速不变调，不影响音色和清晰度。1.1/1.2 只在你确认要更快时用 |
| **分段字数** | 60（默认） | 后端按显存自动收敛，**调大无效**（会被压回 60） |
| **批量大小** | 8（默认） | 同上，调大只会被压回，**不会更快** |
| **标题** | 必填 | 成品文件名和日后检索都靠它 |

### ⚠️ 关于「情感」：现在只有「平稳」是真的

实测（2026-10-06）：选 激昂 / 亲切 / 严肃 时，后端会尝试切到 CosyVoice3，
但 **CosyVoice3 目前还没部署上线**，于是任务静默降级回 Qwen：

```
emotion=excited  -> done  engine=qwen  fallback_from=cosyvoice3
emotion=warm     -> done  engine=qwen  fallback_from=cosyvoice3
emotion=serious  -> done  engine=qwen  fallback_from=cosyvoice3
```

- **不会报错、不会失败**，所以很容易被误以为"换情感成功了"；
- 但成品和「平稳」逐字节等价 —— **白等一轮排队时间**；
- CosyVoice3 部署完成前，请一律选 **平稳**。

## 三、录入参考音频（决定克隆像不像，唯一需要认真做的一步）

入口：右侧「录入声音（声音克隆用）」。

| 项目 | 要求 | 说明 |
|---|---|---|
| 音频 | 整段录音直接传，**不用自己剪** | 超 30 秒系统会挑音质最好的约 **15 秒**（详见下） |
| 文字稿 | **必填**，这段录音的**完整逐字稿** | 空了会直接被拦住，不会污染音色库 |
| 字数参考 | 15 秒音频配 **75~105 字** 最稳 | 后端校验 4.5~12 字/秒；超出会弹警告 |
| 格式 | wav / mp3 / m4a / flac 均可 | 单声道立体声都行，代码会自己转 |

### 为什么是 15 秒

我们实测过一整轮：**参考音频 15 秒是甜点**。它是 ICL（上下文学习）模式，
参考越长不代表越像 —— 显存按 batch 倍数涨，收益却迅速饱和。
30 秒以上交给代码自动截取，它挑的是**句内 F0 动态最大的那一段**（= 语调最自然的 15 秒），
比人工乱剪更稳。

### 文字稿为什么必须完整

模型是从这段 (音频, 文字) 配对里学语速和发音的。字稿对不上，模型会学到**错的语速**：

> 实测：130 字配 10.5 秒（12.4 字/秒）时，生成语速崩到 **2.44 字/秒**
> （正常 6.15），耗时涨 5.6 倍、音频长 2.5 倍。

所以后端在录入时就校验 4.5~12 字/秒，超了会警告。

## 四、后端替你做了什么（不用管，但要知道）

| 环节 | 效果（r14 实测，vs ElevenLabs 标杆） |
|---|---|
| **响度归一** | 成品 −24.2 / −22.9 LUFS，与案例差 **≤0.1 dB**（r13 时还差 7.0 / 4.3 dB） |
| **限幅对齐峰值** | 成品峰值 −1.9 / −2.6 dBFS，与案例 −1.7 / −2.4 差 **0.2 dB** |
| **音色 EQ** | 男声频谱平均偏差 **0.58 dB** |
| **韵律移植（PROSO）** | 句内动态 / 句尾多样性拉到案例值 |
| **停顿压缩与重排** | 修"He spoke... 一顿一顿"和"像节拍器" |
| **首尾换气对齐** | 段间 0.28 秒，落进案例的 0.25~0.36 秒区间 |
| **内容回检** | 每段 ASR 转写比对原文，CER > 0.35 自动**换种子重出**，最多 3 次取最好的 |

最后一条是关键：**"说着说着跑飞""念错字"会被自动拦下重试**，员工不用自己听出来再返工。

## 五、出问题怎么办

| 现象 | 原因 | 应对 |
|---|---|---|
| 提交后一直"排队中" | 任务是串行的，前面还有人的活 | 队列会显示"前面还有 N 个任务"，等即可 |
| 音色显示"不可用" | ref_text 为空，或时长 > 30 秒 | 重录，务必填完整文字稿 |
| 录入时警告"文字稿与音频时长对不上" | 字太多或太少 | 核对字稿，让 15 秒配 75~105 字 |
| 成品某一句听着别扭 | 模型固有随机性（官方已知缺陷） | 见下方 **已知缺口** |
| 想重录某个音色 | 在「已录入音色」里删除后重录 | 内置音色不可删（团队共用） |

## 六、⚠️ 已知缺口（现阶段还做不到，别浪费时间重试）

1. **单次结果有随机波动。** 韵律指标单次测量波动可达 **±5 个百分点**。
   同一段你认为"这次不好"，很可能只是这一次的运气。要复现/对比请跑 3 次取中位数。
2. **"重试"按钮不会换个说法。** 当前 `/retry` 会连种子一起复制，所以重跑出的是
   **逐字节相同**的音频。想换一个版本只能改标题或微调文案重新提交。
3. **CosyVoice3 未上线**，情感选项暂时无效（见第二节）。
4. **男声的句尾多样性还差 13.6%**、**句段数仍偏多 8~13%**（略显碎）。
   这两项在下一轮修，现阶段属于已知上限。

## 七、给管理员：建议调整的前端选项

按「投入 / 收益」排序，供决策：

| # | 建议 | 现状问题 | 改动量 |
|---|---|---|---|
| 1 | **情感下拉暂时只显示「平稳」**，其余置灰并标"即将支持" | 员工选了其它三项，白等一轮排队，拿到完全一样的成品 | 小（前端判断 + i18n） |
| 2 | **任务上加「换个版本」按钮**（用新种子重出，不是现在的 retry） | retry 复制种子 = 出同样的音频，等于没有 | 中（后端 retry 加 `new_seed` 参数，前端加按钮） |
| 3 | **重试 / 换个版本时显示是否已换种子** | 员工无法区分"重跑"和"重出一样的" | 小 |
| 4 | 录入音色时**实时显示"字数 / 秒"** | 现在只能提交后才知道超了 | 小（前端已有时长，加个实时除法） |
| 5 | 队列里的预计等待时间**按排队人数累加** | 现在只算自己这一单 | 中 |

> 这些都不影响员工当下出片，做完 1 和 2 体验提升最明显。
> 要不要动、先动哪个，请老板定。
