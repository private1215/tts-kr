## 0. 一句话结论

**男女声的病是同一种病（相对 EL 的 click 基线都是 ~2.6 倍），但死的部位不同：**

| | 裸输出 click（相对 EL 倍数） | 成品 click（相对 EL 倍数） | 后处理干了什么 | 结论 |
|---|---|---|---|---|
| 男声 voxcpm | 1.10/s（**2.5×** EL 0.44） | 4.37/s（**9.9×**） | **放大 4.0 倍** | 病在后处理，**可修** |
| 女声 omnivoice | 0.781/s（**2.7×** EL 0.288） | 0.576/s（**2.0×**） | 略改善（×0.74） | 病在模型，后处理已到头 |

**两个引擎的裸输出「相对 EL 的 click 倍数」几乎一样（2.5× vs 2.7×）——
差距 100% 来自后处理。男声跑 567 行 `fix_chain`，女声 v1.1 起走极简（只响度对齐）。**
这是女声 1.5 分、男声 0.5 分的直接解释，也是本计划的主轴。

## 1. 两次审视的结论整合

### 1.1 男声（第51轮主审视，全篇口径 456.9s）

根因链（裸输出对照 + 单步施加拆解）：

```
裸输出 voxcpm 原生   1.10 次/秒
  1 +atempo 变速     1.82  (+65%)   <- 时域重采样
  2 +asetrate 变调   1.32  (+20%)
  3 +EQ 男声四段     2.54  (+92%)   <- 90Hz +7.5 / 350Hz +3 / 1400Hz +3（w=1.1 窄带）
  4 +loudnorm        2.00
 完整链成品          4.37 次/秒     <- 切窗 / 停顿清洗继续贡献
```

- **放大来源排序：EQ(+92%) > atempo(+65%) > 变调(+20%) > 其余**。
- 🔴 **变调只占 +20%，不是主要矛盾** —— 推翻「男声 click 是变调害的」这个直觉。
- 频谱（全篇）：裸 1869 → 成品 1704，EL 1714 → **EQ 是有正面作用的**（把过亮的裸输出压回 EL）。
  ⚠️ 我自己在本轮又踩了一次片段口径坑：25s 片段判「发闷 -14.5%」，全篇只有 0.6%。已记入记忆。

### 1.2 女声（第51轮补审视，全篇口径 453s）

| | click/秒 | 停顿中位 | 停顿 CV | 相对 EL |
|---|---|---|---|---|
| 裸输出 | 0.781 | 0.23s | 0.59 | 2.7× / 1.4× |
| 成品（OMNI_MINIMAL） | 0.576 | 0.22s | 0.58 | 2.0× |
| EL | 0.288 | 0.16s | **0.71** | 1.0× |

- 裸输出的停顿直方图**就有** 0.3~0.6s「多余平台」（EL 是单调递减）→ 模型固有韵律。
- z21 两位员工一致判女声「断句处有异声」→ 大概率就是**这个平台**，不是后处理引入。
- `omni_server.py` 的 `generate(text, ref_audio, ref_text)` **没有任何质量参数可调**。

| 旧记录 | 现状 | 应改写为 |

## 3. 优化方案

### 3.1 男声（主轴，四步逐步收窄）

#### M1 · voxcpm 引擎参数提质 🅰 配置级

**现状**（`deploy/vox_server.py:49-51`，三个都是环境变量，重启生效）：

```
CHUNK_CHARS = VOX_CHUNK_CHARS 默认 600   <- 官方 MAX_TEXT_LENGTH = 500，超了
CFG         = VOX_CFG         默认 2.0    <- 官方长篇建议 1.5~2.0「更自然」
STEPS       = VOX_STEPS       默认 10     <- 官方默认10，高质量 20-30，最高 40+
```

**动作**：先**离线网格**（不改生产），同一段男声文本跑
`STEPS ∈ {10, 20, 30} × CFG ∈ {2.0, 1.5}` 共 6 组**裸输出**，测
click/秒、停顿中位+CV、质心、cps、RTF。选出 click 最低且频谱不跑偏的一组。

**预期（S4 改前写死）**：男声裸输出 click 从 **1.10/s → ≤0.80/s**（≤1.8×EL）；
RTF 上升（测试阶段可接受，正式上线前需单独评估产能）。

**风险**：STEPS 翻倍 → 推理耗时翻倍；`CHUNK_CHARS` 减到 500 会增加块数（拼接点变多）。
→ 网格里同时看这两项，任一恶化就锁回原值。

**回退**：改回 systemd drop-in 原值 + `sudo systemctl restart vox-tts`，10 秒完成。

#### M2 · 放宽 cps 容差，让 atempo 少介入 🅰 配置级

**理由**：现役男声 cps 8.36，EL 8.23，**只差 1.6%**。
为一个耳朵听不出的 1.6% 语速差付 65% 的 click 增长，是笔烂交易。

**动作**：放宽 `fix_chain` 的 cps 目标容差带，使 |Δ| < 3% 时不触发 atempo。

**预期**：成品 click 再降 **15~20%**；cps 落在 8.2~8.5（仍贴 EL 8.23）。

#### M3 · 男声 EQ 温和化（撤激进窄带 boost）🅲 代码级

**现状**（`app/fix_chain.py:75-99`）：

```python
EQ_MALE_TMPL = ("highpass=f=110:poles=2,"
                "equalizer=f=90:t=q:w=1.1:g=7.5,"    # +7.5dB 窄带
                "equalizer=f=350:t=q:w=1.1:g=3,"     # +3dB 窄带
                "equalizer=f=1400:t=q:w=1.1:g=3,"    # +3dB 窄带
                "equalizer=f=250:t=q:w=1.1:g=0.45,"  # 补丁：抵消上面抬过头的 150~300Hz
                "highshelf=f=4000:g=%g,lowpass=f=14000")
```

**动作**：三道 `w=1.1` 窄带 boost → 改**宽带 + 小增益**（记忆教训：窄带会摧毁频谱平坦度）；
boost 撤掉后 250Hz 补丁失去存在理由，**同步撤掉**（这才是「治本」而非「加补丁盖补丁」）。

**预期**：click 再降 **~40%**；质心维持 **1700±80**（EL 1714），
🔴 底线是不能退回到裸输出的 1869 —— **频谱对齐与 click 必须同时看，只降 click 而频谱跑偏 = 没修好**。

#### M4 · 男声「半极简」后处理（终态）🅲 代码级

对齐 v1.1 女声成功经验，但**保留变调**（男声裸 F0 167 → 目标 188，确实需要）：

```
保留：变调（asetrate+atempo 组合） + M3 温和 EQ + 响度对齐（-22.6 LUFS）
砍掉：切窗 / 停顿清洗 / 呼吸 / roomtone / peakfit
开关：TTS_VOX_MINIMAL=1（一键回退，对齐 TTS_OMNI_MINIMAL 的写法）
```

**预期**：成品 click **≤1.5/s（≤3.4×EL）**；音色 ≥0.87 不降；静音段 4-8k 杂音不恶化。

**几条不可绕过的硬规矩：**

- 🔴🔴 **L3（≥3~5 分钟全篇）是唯一质量验收**。片段只用来判「改动有没有生效」。
  （第47轮栽过两次：片段改善、全篇变差。）
- 🔴 每次改动改前写「预期：指标 X 从 a 变到 b」，对不上就是没修好，回退重来。
- 🔴 click 一律 **峰值归一到 0.70 + 无条件重采样到 16k** 后再判（口径不统一就作废）。
- 🔴 涉及 `atempo` 的改动，验收**必须同时看静音段杂音**（加速会触发自适应 EQ 反向补高频 → 嘶声爆炸）。
- 🔴 版本号**只能**由 `tools/release_version.py --bump minor|major` 写；
  上线后必查 `GET /api/version` 的 `consistent == true`。
- 🔴 A 级最容易漏：改任何环境变量，**必须同时在当日记忆里写一行**。
