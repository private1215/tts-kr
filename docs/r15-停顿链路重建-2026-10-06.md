# r15：停顿链路重建 + 分性别 EQ（2026-10-06）

## 一句话结论

「句段偏碎、听着赶」的真正原因不是模型，是**我们把停顿目标定错了 24%~34%**——
而且这个错源于 `prosody_report` 一个 480 倍的换算 bug。修掉后男声静音占比
从 9.2% 提到 20.6%（案例 18.8%），停顿熵 F 从 −9.4% 到 +2.6%，
句尾多样性 E 从 −13.6% 回到 ±3%，频谱残差分性别迭代后降到 0.5~0.7 dB。

## 二、挖出的四个根因（每一个都足以让「1:1」无从谈起）

### 根因 1：`prosody_report.measure` 的停顿换算多乘了一次 hop

```python
runs = np.array([(j - i) * hop / sr for i, j in cuts])   # ❌
```

`sent_windows` 返回的 `cuts` **已经是样本索引**（内部存的是 `i*hop`），
所以 24 kHz 下整体放大 **480 倍**。

- 对 **F（停顿熵）无影响**：直方图 8 桶按 min~max 均分，整体线性缩放不改变
  归一化熵 → 历史上所有基于 F 的结论**仍然成立**。
- 但 **均值/sd/CV 全错**，`runs >= 0.28` 的过滤也形同虚设（放大后全部通过）。

### 根因 2：停顿目标 `mu` 是从那个 bug 的数据拟合出来的

| | 旧目标 | 案例真值 | 偏差 |
|---|---|---|---|
| 男 | 0.414 s | **0.547 s**（162 个） | −24% |
| 女 | 0.325 s | **0.491 s**（147 个） | −34% |

`mu = 0.463 − 0.0143×句均时长` → 修正为 `0.5725 − 0.00769×句均时长`；
有案例样本时**直接用案例实测均值**（真 1:1），回归只作 fallback。
交叉验证：新回归男声给出 0.537~0.541，案例均值 0.547，吻合。

**静音占比 我们 9.2% vs 案例 15.7%** —— 这才是「偏碎、听着赶」的量化根因。

### 根因 3：处理与验收用了两套 VAD 口径

| 口径 | 检出停顿数（男声） |
|---|---|
| `pba._intervals`（librosa `effects.split`） | 51~98 |
| `prosody_report.sent_windows`（RMS 分位阈值） | 169~172 |

案例样本和验收指标 F 都是 sent_windows 口径，却拿去改 _intervals 口径的停顿，
**只改到 57% 的样本**，F 卡在 −9.4% 一动不动。改成同源后 F 立刻 +2.6%。

> 反过来说：`_intervals` 是 α 的标定口径，换它要重新验 α。

### 根因 4：reshuffle 加长的时长被 atempo 拉回，等于白做

`_atempo = _pba_ratio` 会把总时长拉回原值。停顿加长后再拉回 = 把有声段
**加速 9.2%**（4.21→4.60 字/s），与「修听着赶」完全抵消。
改为只有 align 压缩的部分拉回，reshuffle 增量不拉回。

### 关于分性别：为什么原先「男女共用一套」不行

共用时只能取「男女同向的**保守值**」，结果女声 1480 Hz 的 3.26 dB 缺口
**只补了 0.72 dB**，EQ 残差 1.7 dB 下不去。而「同向」这个约束本来只是
「一套参数服务两个性别」的妥协——分性别后就不需要了。方向相反的频段
（65/262/370/740 Hz…）是男女音色本身的差异，不是误差。

### EQ 为什么必须迭代求解

LTAS 是**按总能量归一化**的，是零和游戏：提升某几段会压低其他段。
实测补 +1.8 dB 只兑现 1.07 dB（效率约 60%），一次性补偿必然不到位。
`/tmp/eqsolve.py` 迭代 3 轮、步长 0.7：女 1.74→**0.66 dB**、男 1.7→**0.50 dB**。

## 四、本轮两起事故（都记进记忆了）

### P0：案例停顿样本换算漏改 → 成品被拉成 4.7 小时

```
PBA reshuffle: 均值 0.497s->171.855s  目标 mu=172.523
              时长 232.90s -> 16854.56s (ratio 72.37)
```

- 我只改了 `recase.py`，没改 `server.py` 的 `_analyze_case`（同样是 `* _hop`）。
  原有 2 个案例是用 recase.py 补的所以是对的；**员工新上传的 3 个「yohan」
  案例走 `_analyze_case`，写入了 480 倍的脏数据**（max 470/480 秒）。
- 修了三层：`_analyze_case` 换算 → `pause_targets` 只收 0.1~5 s →
  `reshuffle` 再加 `mean ≤ 2.0` 才采信。
- 教训：**修换算 bug 要全局搜同名模式**；分布类参数必须有物理范围兜底，
  上游脏数据不能让整单报废。

### 标杆被稀释：员工的案例混进了中位数

3 个「yohan」案例同样是 male + elevenlabs（LUFS −25.0/−25.2，而标杆是 −24.3），

停顿样本也从 162 涨到 688，把原音色的节奏搅了。
改法：标杆只认带 `标杆` tag 的案例（原案例入库时本来就打了这个 tag）。
