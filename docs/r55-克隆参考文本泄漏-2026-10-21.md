# r55 · 克隆「参考文本泄漏」：另一引擎一直被自己的 prompt 拖累

日期：2026-10-21　背景：z38「多引擎横向盲听」素材生成时踩到

---

## 一、症状

用另一引擎（Qwen3-TTS 1.7B Base）克隆同一段 154 字韩语文案，输出 **32.6 秒**，
而现役链路同文案 **23.1 秒**。ASR 转写出现整句重复 4 次：

```
1,000원 깨지면 비중 축소부터 생각하셔요 고점 근처라고 불나방처럼 내동매매 하지 마시고요
1,000원 깨지면 비중 축소부터 생각하셔요 … (×4，插在每句之间)
```

这句话**不在本次文案里**——它是该音色 `ref_text`（参考音频的转写稿）的开头。

女声更直白：`ref_text` 结尾是 `…캔들 위아래로`，输出里 `끄지면서 캔들 위아래로`
被插在每一个句子前面。

> 不是 ASR 幻觉。时长本身就是证据：32.6 s vs 23.1 s，音频真的多念了 ~20 秒。

## 二、根因

`app/tts_engine.py::_get_clone_prompt` 固定走 **ICL 模式**：

```python
prompts = self.model.create_voice_clone_prompt(
    ref_audio=ref_audio, ref_text=ref_text, x_vector_only_mode=False)
```

`ref_text` 是**整段 160 字**的参考音频文稿。模型看到「长 prompt + 目标文本」，
会把 prompt 里的句子当成正文继续念——即 prompt leakage。

## 三、三路对照（同文案、同 seed 42、3090）

| 变体 | ref_text | 时长 | 语速 | CER | 现象 |
|---|---|---|---|---|---|
| **a_icl**（现网做法） | 全文 160 字 | 29.28s | 4.92 | **0.431** | 开头两句被当正文复读 |
| **b_xvec**（无 prompt 文本） | 不给 | **22.88s** | **6.29** | **0.083** | 干净，逐句对齐 |
| d_short | 截到首句 40 字 | 11.92s | 12.08 | **0.958** | 反而漏读大半 |
| c_lora（b + LoRA 0.35） | 不给 | 60.48s | 2.55 | — | 跑飞，不可用 |

女声同口径：`b_xvec` 24.40s / CER **0.137**；`d_short` 16.24s / CER 0.973。

**结论：只有「完全不给 ref_text」（x_vec_only_mode=True）可用。**
截短 ref_text 不但没治好复读，还把模型带进漏读——prompt 长度对这个模型是敏感旋钮，
不是可调参数。

## 四、代价：音色掉了一点（campplus 余弦，对照各自音色参考音频）

| | 现役链 | qwen ICL | qwen xvec |
|---|---|---|---|
| 男 | **0.9052** | 0.8637 | 0.7829 |
| 女 | **0.8431** | — | 0.8120 |

xvec 仍 > 0.75（同人阈值），但男声掉了 0.08。
即：**治好复读的代价是音色不像一点**；这是个真实权衡，不是免费修复。

## 五、为什么这件事重要（不只是这次的实验）

1. **历史结论可能被污染**：10-13 那轮「VoxCPM2/OmniVoice 胜出」是**A/B 择优**；
   另一引擎当时如果就是这套 ICL 克隆，它是在「会把参考稿当正文念」的状态下参赛的。
   **它从未在公平条件下被评过。** z38 是它第一次干净出场。
2. **体检指标看不见它**：现网的语速体检用「输入字数 / 时长」，
   复读会让这个值变**小**（4.92 字/秒），落在正常区间内，不会触发拒绝采样。
   → 要抓这类故障，必须做 ASR 复核（CER 或「输出字数 vs 输入字数」）。
3. **LoRA 前的必修课**：训练数据、推理参数都得绕开这个缺陷，否则训完也白搭。

## 六、LoRA（yohan）首次评估：不可用

`/mnt/tts/data/lora/yohan/ckpt/best`，xvec 模式 + scale 0.35：

**60.48 秒 / 2.55 字每秒** —— 典型退化循环（不吐 EOS，一路跑到上限）。

与联网资料一致：LoRA scale 1.0 会过冲出噪声，0.2~0.35 才稳；而 0.35 在这里已经跑飞。
另一个已知坑是官方 `sft_12hz.py` 的 **double label-shift**（语速渐进加快）——
这个 ckpt 是 10-09 训的，是否打了补丁未确认。

→ 结论：**adapter 现状不可上线**。要么重训（先打 label-shift 补丁、LR 2e-6、24 kHz 数据），
要么先把 scale 扫到 0.1~0.2 看是否只是过冲。
