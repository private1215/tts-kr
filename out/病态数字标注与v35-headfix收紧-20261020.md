# 病态数字自动标注 + v3.5 headfix 收紧（2026-10-20）

## 一、用户的问题与结论（先给答案）

> 「文案里的病态数字是否可以自动识别标注出来 —— 这类可以识别标注出来即可，
> 不是强制修改的，看下应该如何快捷优化，有没有好的方式，**是不是发音以及
> 怪音的原因触发之一**」

### 结论 1：可以自动标注，已上线（v3.5）

`tools/numcheck53.py` + 生产侧接入，**只标注、不改文案、不拦任务、不动音频**。
合成前扫 `job["text"]`，命中写 `job["num_warnings"]`（含 pos/expr/rule/sev/why/suggest）
并打 `log.warning`。回退开关 `TTS_NUMCHECK=0`。

### 结论 2：病态数字**不是**起音怪音的触发源

15 单对照实验（同音色 EL_female、数字表达式一律放在**句首**、3 seed × 5 变体）：

| 变体 | 文案开头 | 起音碎片触发 | ASR |
|---|---|---|---|
| A_mixpatho | `한 사쩜사퍼센트`（病态） | **0/3** | `한 4.4% 정도…` |
| B_sinolegal | `사쩜사 퍼센트`（合法 4.4%） | 0/3 | `4.4% 정도…` |
| C_sinoint | `일점사 퍼센트`（合法 1.4%） | 0/3 | `1.4% 정도…` |
| D_hanctrl | `한 퍼센트`（合法，首字同为 한） | 1/3 | `한 퍼센트…` |
| E_clean | `반갑습니다`（已知干净基线） | 1/3 | `반갑습니다…` |

- 病态数字 **0/3**，合法数字 **0/3**，反而「干净」基线 **1/3** 触发。
- A 在 headfix 开/关两态下时长完全一致（4.92s），从不触发切除。
- → 起音碎片是**引擎固有的随机现象**（与首词时长/停顿分布有关），
  与数字是否病态**无关**。

**但病态数字确实是「发音错误」的源**：ASR 证明 TTS 忠实念出
「한 사쩜사 퍼센트」（= 韩语里不通的「一个 4.4%」），员工听到的就是错音。
这是**文案问题不是合成缺陷** —— 所以正确的做法是标注给人改，而不是改链路。

## 二、numcheck53 检测器

### 规则（两级：INVALID 必须改 / WARN 建议改）

| 规则 | 判据 | 级别 | 例子 |
|---|---|---|---|
| R1 | native + Sino 混排 | INVALID | `한 사쩜사퍼센트` |
| R1b | native + 阿拉伯混排 | INVALID | `한 4.4%` |
| R2 | native + 大单位（한 → WARN） | INVALID/WARN | `세 억원` / `한 만 원` |
| R3 | 小数点残缺 / 双点 / 小数+大单位 | INVALID | `사쩜` `쩜사` `사쩜사쩜사` `사쩜사만` `4.4만` |
| R4 | 百分号倒置 | INVALID | `퍼센트 사점사` |
| R7 | 双数混排 | INVALID | `사쩜사 한 퍼센트` |
| R5 | native + 百分号 | WARN | `다섯 퍼센트` |
| R8 | 小数被空格拆开 | WARN | `사쩜 사` |

### 防误报设计（宁漏勿误）

- **native 数词 + 原生量词合法**：두 달 / 세 시 / 두 명 / 네 권 / 두 배 —— 不报
- **「이」既是 Sino 2 也是主语词尾**：`수익이 두 배` 不报（数 token 须 ≥2 字符）
- **「한」既是数词 1 也是冠形词尾**：`상승한 2,450선` 不报（한 紧跟前一韩字音节）
- **句末 `.` 不是小数点**：`.` 只在右侧紧跟数字/Sino 字时才算；`쩜` 无歧义
- **「점」多义**：只认 `X점Y`/`X쩜Y` 三元组；`이 점`(这点) 不报
- **单位后接韩字即非数字**：`네 조각`(조=块) / `두 프로젝트`(프로) 不报；
  `조/만/억` 后跟 `원` 或系词 `이다/입니다/이에요` 才算数
- **名词闸门**：`한 일이 있어서요`（일=事/日 名词）不报

### 测试

`tools/test_numcheck53.py` —— **解析闭环 29/29 + 检出 40/40 + 写实冒烟 22/22 零误报**。

过程中修掉三个潜伏 bug（都是「测试只查检出数、没查数值」漏掉的）：
1. `SINO_DIGIT.index(c)` 是 0 起索引 → `사` 算成 3（应为 4）
2. `_parse_sino_int` 的 `sec += sec*10` → `이십` 算成 22、`삼십오` 算成 5
3. `_sino_int` 的 `_ONES[q]` 在 q≥10 越界（`사십사만` 的 q=44）
4. `_parse_sino_value` 剥单位词时把数值成分 `십/백/천/만/억/조` 一起剥掉
   （`사십` → 4）

## 三、v3.5：headfix 判据收紧（修 v3.4 误切实词）

### 问题

对照实验里 `D_hanctrl`(한 퍼센트) seed42 触发了切除，ASR 丢了「한」。

**决定性证据**：`TTS_HEADFIX=0` 重跑同一条 → dur **4.4s** 且 ASR 完整含「한」；
开启态 dur **4.18s** 且「한」消失。→ v3.4 把实词「한」当碎片切掉了。

### 新阈值怎么定的

在 headrepro-1019 十条（v3.4 之前的未切除原始产物）+ 实验 6 单上量
每个头部语音段的 (时长, 间隙)：

| 类别 | 样本 |
|---|---|
| 真碎片（该切） | 20ms/510ms、20ms/490ms、60ms/270ms、70ms/560ms、150ms/630ms、30ms/410ms、20ms/260ms |
| 真实首词（不该切） | 90ms/120ms、100ms/140ms、150ms/170ms、170ms/150ms、50ms/190ms、110ms/50ms、130ms/40ms |

→ **间隙时长**是唯一干净的分界（真碎片 ≥260ms，真实首词 ≤190ms）。
碎片时长单独用会误伤；间隙底噪 dB 无区分度（两边都是 -52dB 左右）。

**改动**：间隙 150ms → **250ms**，碎片组上限 350ms → **200ms**（双重保险）。
其余三项（恰好 1 组 / 起点 <0.30s / 切点后 400ms 恢复语音）不变。

### 验收（9 单）

| 变体 | 切除 | 时长 vs 未切基准 | 首词 |
|---|---|---|---|
| D_han（한 퍼센트） | **0/3** | -0.03 / 0.00 / 0.00 | 3/3 在 |
| P_l3f（반갑습니다, 아모텍…） | **2/3** | -0.28 / 0.00 / -0.28 | 3/3 在 |
| A_mix（病态数字） | 0/3 | 0.00 / 0.00 / 0.00 | 3/3 在 |

→ 误切修掉了，真碎片照样切，首词一个没丢。

## 五、#7 型起音崩坏研究（生产普查）

34 条最近产物的头部形态分布：

| 形态 | 占比 | headfix 处理 |
|---|---|---|
| normal | 68% | — |
| A 单组碎片 | 21% | ✅ v3.5 切（间隙 ≥250ms 的那部分） |
| **#7 多组崩坏** | **9%** | ❌ 保守不切 |
| B 词内断裂 | 3% | ❌ 切了吃字，v3.4 就已排除 |

3 个 #7 样本的头**都是**幻觉级垃圾（`오 반갑습니다` 的多余「오」、
`로보티즈` 前的碎片群），切掉是对的。

**但暂不扩判据**，风险点：短首句（如「네. 반갑습니다…」）会产生
多个音节组 + 句间停顿 ≥250ms，会被判成 #7 而**整句吃掉**。
本轮所有测试文案的首句都不短，**没验证过这个风险**。

若要扩，建议判据：头部组数 ≥3 **且**每组 ≤120ms **且**头部总长 ≤500ms
**且**间隙 ≥250ms，并先补 10+ 条含短首句的样本验证。
