杂音（卡音）根因诊断

一句话结论

杂音 = 波形不连续（click/爆音）。不是引擎造的，是后处理链 app/fix_chain.py 造的。 OmniVoice 引擎裸输出干净（0.21%，与 EL 的 0.16% 同水平），跑完 fix_chain 就变成 0.54%。 能清除干净，且已有现成的干净路线（GS 微调 click = 0.00%）。

3. 根因：fix_chain 引入了实质波形损伤

把「引擎裸输出只做重采样 + 同增益」与「fix_chain 产物」逐样本相减：

指标实测含义
残差 SNR12.03 dB残差占信号能量 25%，不是细微处理
残差频谱质心421 Hz62% 堆在 300Hz 以下（信号本身只有 16% 在那）
互相关最佳延迟0 样本不是时间偏移造成的假残差
仍未闭环：fix_chain 内部具体哪一行造成这 12 dB 残差还在定位。 已排除变速 / 变调 / EQ / 清洗 / 拼接 / 重采样，下一步查 sf.write ↔ sf.read 往返的默认 subtype 与「响度二次校正」。 但这不影响结论——整条 fix_chain 是损伤源这一点已由「裸输出 0.21% → 产物 0.54%」坐实。

依据：裸输出语速 [8.1, 8.05, 8.48] 字/秒 vs 目标 8.5， fix_chain 自己算出的窗口系数全为 1.0 —— 本来就不该变速，白揉一遍还引入咔哒声。

路线 B（更优，顺带提升音色）click → 0.00%

⚠️ 但 GS 目前被套在 legacy 老链上（atempo 0.93 拉慢 7%），上线前需先让它与现役走同一条快路径， 否则对照不公平。

5. 口径陷阱（本轮自己踩的坑，记下来）

|Δ| ≥ 0.3 是绝对阈值，对整体电平极度敏感。同一条素材： 24k→16k 重采样后 0.27%（峰值 0.7196）， 仅仅 +1.4 dB 静态增益就变 0.71%（峰值 0.8455），loudnorm 后更是 6.29%。 不归一电平就横向比较，等于在比「谁声音大」，不是在比「谁有咔哒声」。
→ 统一用 deploy/peaknorm47.py（归一到峰值 0.70 再判）。 本轮之前所有未归一的 click 数字全部作废。

7. 二次修正：女声 EQ 改成「撤低频窄带、留高频压制」

先按第 4 节「完全撤 EQ」上线后，员工报「滋滋滋声音存在」。复查发现被撤掉的 EQ 里 有两道高频压制（6500Hz −2dB + lowpass=14000）。 同口径（200.2s、同一条文本）复测：

女声 EQ 方案click静音段 4–8kHz
EL 标杆 seg0—11.98

C 6500Hz−2dB + lowpass140000.26%11.56

结论修正：click 的真凶是低频窄带三道（150Hz +4 / 350Hz −2 / 600Hz −2） —— 只留 350/600 纯衰减 click 就 0.49%；而高频两道完全无害（0.26~0.27%）。 最终定为撤低频窄带、留高频压制，两项指标都最优。已上线（fix_chain 现读配置，不需重启）。
