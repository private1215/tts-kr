## Q1. 模版自身比成品还脏，是什么情况？

### 结论：那 7 处 click 全部是**测量伪影**，模版音频本身是干净的

| 测法 | 模版 click 数 |
|---|---|
| **原生 24 kHz**（不重采样） | **0 处** |
| 重采样到 16 kHz 后测 | 7 处（t=2.444 / 2.469 / 2.474 / 6.459 / 14.556 / 14.557 / 14.561） |

24k→16k 是 2:3 非整数比，ffmpeg 重采样器在这些位置制造了样本级跳变，
|Δ| 刚好过 0.30 阈值。**同一个文件，采样率不同，结论相反**——这是典型的
「测量制造了被测对象」。现役 clickfix 口径（峰值归一到 0.70、|Δ|≥0.30）
对 24 kHz 素材必须先说明重采样影响，否则不能下结论。

### 为什么「模版比成品脏」是必然的、正常的

1. **模版是 EL 的原始产出，我们从不对它做任何后处理**。
   `voices.json` 里 EL_female：`path=/mnt/tts/data/voices/EL_female.wav`，
   `sr=24000`，`dur=15.08`，`src_dur=15.08`（未被切短），
   文件建于 10/5，`origin/src_case/clip` 全为 None。
   `cut_voice53b.py` 只往 voices.json 补条目，不切音频。
   后处理链（响度闭环 / 窄带 EQ / clickfix）**只作用于我们自己的成品**。
2. **EL 自己就有 click**。同口径下 EL 女声长文本标杆
   `merged.wav`（459.1 s）有 **119 处** click 事件（其中 0.2~0.9 s 文件头
   就集中了约 20 处）；我们的成品全篇 **0 处**。
   拿「未处理的 EL 素材」比「处理过的我们成品」，脏是应该的。
3. **模版的 2 个句末粘连嗯是真的**（原生 24 kHz 复测依然 2 个，
   7.96/分），不是重采样伪影——但这只说明 EL 原始素材有这个现象，
   而我们的成品严口径 2.15/分、宽口径 6.24/分，**都低于 EL 标杆**
   （3.40 / 10.32 分，见 Q3）。
4. **「15 s 换算成每分钟」统计上不成立**：click 和句末嗯是离散事件，
   15.08 s 窗口里 2 个事件折算 7.96/分，Poisson 95% 置信区间约
   0.96~28.7/分——这个数字没有意义。模版短，只能回答「有/无」，
   不能回答「密度」。

### 对结论的影响
员工/此前「模版比成品脏 ⇒ 模版有问题 ⇒ 成品缺陷源自模版」的推理链
**不成立**。模版 ref_text 与音频 ASR 回读相似度 1.000、24 kHz 下
0 click、起音平滑（0.19 s 直接进入 −40 dB 浊音、0.26 s 进正常音量），
是一条合格的参考音频。

## Q2. 先确保「数字念对」，再谈吐字

### 2.1 方法：两侧都归一到整数再比对

whisper 会把韩语口述数字转写成阿拉伯数字，字符级 diff 会因此制造大量
假 insert/delete。写了汉字词数字解析器（`diag/q2_num_audit3.py`）：
- 汉字词体系（已联网确认标准读法）：일이삼사오육칠팔구 + 십/백/천/만/억/조；
  100=백（非 일백）、1000=천、10000=만；
  `사십사만`=44만=440000、`삼십만오백`=300500、`백퍼센트`=100%。
- 单位感知：先剥尾部单位再解析数字（`이일`=2日 而非 2+1；
  `사십사만주`=440000주）。
- 不规则读法：시월=10月、유월=6月、열한=11。
- `한` 作强调词时不计数（「한 육천오백원」≈ 6500，不是 1+6500）。
- ASR 侧用同一套「大数/小数两级」算法解析
  （`30만 9천 500원`=309500、`3천만원`=30000000）。

### 2.3 对照实验：证明 `삼십일만육천원 → 30일 16,000원` 是 ASR 听错

用同音色、同模式单独合成一条只含争议数字的短文案
（`diag/q2_control.py`，产物 `numctrl-1019`），ASR 结果：

```
원본：  로보티즈 장중 고점이 삼십일만육천원 찍고…
ASR：   로보티즈 장준고점이 30일 16,000원 찍고…
原 job：…장중 고점이 삼십일만육천원…
ASR：   …장중 고점이 30일 16,000원…
```

**干净单句里同样听错** → 与长音频、与上下文无关，是 whisper 对
`삼십일만` 的系统性误解析（听成「30일만」= 只有 30 天）。
同一条在长音频别处还被正确听成 `31만6000원`，进一步证明是
ASR 的不稳定性，不是音频缺陷。同类伪影还有
`장중→장준`、`쌍봉→쌍복`、`유월→6월`（这个是对的）。

**员工报的 29s/44s/64s/115s「吃字/没音」全部在此类伪影里销账。**

### 2.4 唯一的真问题：文案里的病态数字

原文：`전일 대비 한 사쩜사퍼센트 정도 띄워주고 있습니다`

`한`（1）与 `사쩜사`（4.4）无法组成一个合法数值——对照实验里
TTS 忠实念出「한 사쩜사 퍼센트」，ASR 如实转写「한 4.4%」。
**这是文案写错，不是合成缺陷**。从股价上下文推断
（309,500 开盘 300,500 / 高点 316,000），作者大概率想写
`4.4%` 或 `1.4%`，误写成了 `한 사쩜사퍼센트`。
→ **建议改文案，不需动链路。**

### 2.5 时长反推（佐证「字都在」）

对每个数字表达，用 ASR 词级时间戳取音频区间，算局部语速：
全篇 7.50 字/s 下，48 个表达里只有 1 个明显偏慢
（`삼십사분` 0.78 s / 3 音节 = 3.85 字/s，是「11시 34분」报时处的
自然放慢），其余都在 0.65~1.35 倍区间内 → 没有系统性多字/漏字。

## Q3. 句末「嗯」：能清吗？是什么？EL 为什么舒服？

### 3.1 先修正一个口径 bug——上一轮的结论反了

上一轮报告说「我们 56 个 = 5.99/分 vs EL 36 个 = 3.89/分 = 1.55×」，
用的是**宽口径**（缺「该段之后还要有 >0.05 s 静音」这个条件，
把句中换气的小段也当成了句末）。本轮三文件同口径重测：

| 口径 | 我们成品 | EL 标杆 | 模版 EL_female |
|---|---|---|---|
| **严口径**（后接 >0.05 s 静音，真是句末） | 21 个 = **2.15/分** | 26 个 = **3.40/分** | 2 个 = 7.96/分 |
| **宽口径**（紧贴浊音段的小段都算） | 61 个 = **6.24/分** | 79 个 = **10.32/分** | 6 个 = 23.87/分 |

**两个口径下我们都比 EL 少**（宽口径 EL 比我们还多 65%）。
「我们比 EL 差 1.55×」是口径造成的假象，**作废**。

### 3.2 它是杂音还是吐字尾音？——是吐字尾音（浊音自然衰减）

四项证据：

1. **基频延续**：对能测到基频的段，我们 3/4、EL 4/7 尾音基频与前段
   末尾基频比值在 0.82~1.30（延续）；我们 67% 能量衰减、**0% 能量上升**，
   EL 50% 衰减 / 50% 上升。我们的是**纯衰减尾巴**，更干净。
2. **物理上不可闻为独立音节**：中位 5 ms、−33 dB——比周围语音低 30 dB 以上，
   且远短于一个韩语音节的最短可辨时长（~80 ms）。
3. **频谱是浊音不是噪声**：300 Hz 以下能量占比中位 0.68（我们）/
   0.64（EL），zcr<0.15；>30 ms 的段自相关谐波度 0.67~0.81（明显谐波）。
4. **前段时长与 EL 一致**：我们中位 0.235 s vs EL 0.245 s
   （p10/p90/min 都相同）→ 不是「把字截短了拿尾音补」。

### 3.3 能处理干净吗？——能，但不该清

- 保采样率清理链（`tailclean53b2`/`53c2`）实测可把宽口径从 6.24/分
  清到 0.64/分，**技术上做得到**。
- **但不该做**，四条理由：
  1. 这些段 5 ms/−33 dB，物理上不作为独立音节可闻，清了也提升不了听感；
  2. EL 同现象更密（宽 10.32 > 我们 6.24；严 3.40 > 我们 2.15），
     清到零会让我们**比 EL 还「干净」**，反而偏离「员工听不出差别」的目标；
  3. 规范 §1.2 严禁清零；
  4. 清理要动浊音尾巴，有音色损伤风险（tailclean 历史上栽在
     firequalizer 输出比输入长 320 样本上）。

### 3.4 EL 也有，为什么整体听着舒服？

**数据给出的答案是：这件事跟「舒服」没有因果关系。**

- EL 宽口径 10.32/分 比我们 6.24/分**高 65%**，员工却认为 EL 舒服、
  我们是「机器」→ 句末嗯的密度不是听感的决定因素。
- 我们 67% 衰减 / 0% 上升 vs EL 50%/50% → 若要区分，我们的尾巴
  反而更「纯衰减」。
- EL 的舒服来自音色、韵律、停顿分布等其他维度（客观指标上我们已全部
  对齐：click 0.00×、质心 0.98、中频 0.97、停顿 1.00、杂音 1.49×
  在 EL 自身方差内）。
- 员工听到的「吐字后嗯的尾音」如果确实存在且只在我们音频里突兀，
  更可能的来源是**下一节的文件头孤立段那类结构性缺陷**，
  而不是这 5 ms 级残留。建议用裁决题定位，不要继续在后处理上使劲。

## 新缺陷：文件头孤立段，复现率 40%（对应员工「0 秒 开头 怪音」）

同文案、同音色、同模式连跑 10 条（`diag/head_repro.py`），
逐条测文件头 1 s：

| # | 起音 | 起音后 >150 ms 近静音断口 |
|---|---|---|
| 1 | 0.25 s | 无 |
| 2 | 0.12 s | **有 0.27–0.43** |
| 3 | 0.16 s | **有 0.51–0.67** |
| 4 | 0.50 s | **有 1.08–1.38**（起音就晚） |
| 5 | 0.15 s | 无 |
| 6 | 0.16 s | 无 |
| 7 | 0.11 s | 无 |
| 8 | 0.13 s | 无 |
| 9 | 0.18 s | 无 |
| 10 | 0.13 s | **有 0.29–0.50** |

**复现率 4/10 = 40%**。形态：起音后先出一个弱段/短段，随即掉到
近静音（>150 ms，−48~−75 dB），然后才进正常语音。EL 模版与 EL 标杆
都是直接平滑起音（0.08~0.25 s 进浊音，无断口）。

这是**高频偶发链路缺陷，不是模版问题**（模版起音干净），
与员工「0 秒 开头 怪音」的反馈直接对应。

**建议修法（按规范，先出裁决题再上生产）**：起音后 1 s 内检测
>150 ms 近静音断口，若断口前是一个 <100 ms、峰值 <−20 dB 的孤立段，
将其切除并把后续语音前移；对头 100 ms 做淡入削突兀感。
风险：可能切掉真实起音（#4 起音在 0.50 s，需按断口而非固定时刻判定）。

## 汇总：本轮三个问题的答案

1. **模版比成品脏** = 测量伪影（24 kHz 原生 0 click）+ 拿未处理的 EL
   素材比处理过的成品。模版没问题。
2. **数字念读**：48 个数字表达 40 个数值全对；29/44/64/115 s 的「漏字」
   全是 whisper 数字规范化伪影（对照实验已证）；唯一真问题是文案里
   `한 사쩜사퍼센트` 这个病态数字，**改文案即可**。
3. **句末「嗯」**：是浊音自然衰减残留（基频延续、低频为主、纯衰减），
   不是杂音；物理上不可闻；我们密度比 EL 还低；能清但不该清；
   EL 舒服与这项无因果关系。
4. **附带发现**：文件头孤立段 40% 复现，是员工「0 秒 怪音」的真来源，
   修法已给出，待裁决题。
