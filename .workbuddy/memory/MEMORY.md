# tts-kr 项目索引（精简版）

## 核心目标
替代 ElevenLabs（**EL**）省钱。验收：同一条韩语文案，我们 vs EL，员工听不出差别。
- 案例库 36 条**全是 EL 生成**，不是真人录音。
- `EL_male`/`EL_female` = 从 EL 提取的 15s 标杆参考。**音色源 == 质量标杆**，别拆开找。
- 实际只有 2 个声音：SOLA 女 22 条 / yohan 男 13 条。
- 员工只做：上传文案 + 选男/女。零调参。
- 持续目标：自检→修复→验证→更新题库→同步服务端并核对→Git 提交。不承诺指标=1；不用开卷（`1a6c20a60481`/`00b6a45ad6aa`）替代跨文案验收；实验配置与已验收生产分开。

## 🔴🔴🔴 分级验证铁律（用户两次纠正后定案，最高优先级）
> 「短文案语音肯定都漂亮，长文案语音稳定才是实力」
> 「可以短片先过关，然后优化长篇，直接上长篇不合理」

| 级 | 长度 | 成本 | 能判什么 |
|---|---|---|---|
| **L1 快筛** | 15~30s | 几秒 | 改动**有没有生效**、链路通不通（每次改动都跑） |
| **L2 短篇** | 60~120s | 十几秒 | 方向筛查（跑 3 次取中位） |
| **L3 长篇** | ≥3 分钟，最好 ≥5 分钟 | 7 分钟+ | ✅ **唯一可信的质量验收** |

- **验收只用长篇；调试先用短片筛。禁止跳级。**
- L1 正确用法 = **A/B 相对比较看中位数**，不是比单次绝对分。
- 短片不能当验收的实测依据：同配置 18 秒连跑 7 次 Σz² = 190~**753**（波动 4 倍）；
  且短片 4k~8k 只有 0.0034~0.0070，EL 0.0129（低 40~60%），长篇 496s = 0.0145。
  🔴 拿短片调高频 = 照假数据改。
- 闸门工具 `tools/gate_l1.py`：时长 8~120s / Σz² 中位<4000 / 4k~8k 比值>0.45 / N 次散布<3.0。
  实测拦下过（散布 6.39 倍 → 判「先别上长篇」）。🔴 闸门不是摆设。
- 长篇看**一致性**不看点值：`probe_g.py --segments`（跨 30s 窗极差%/CV%/跨窗 Σz²，跳过首尾 5%）。
  `probe_g` 默认 `--full`，`--head60` 复现旧口径，<180s 会打警告。

## 🔴 分析前强制顺序（血的教训，动手前必读）
1. **先量语速（字/秒）** —— 最便宜、最能证伪。锚点 EL：女 **7.45** / 男 **8.37**。
2. 🔴 **字数与时长必须取自同一条 job 记录**（`GET /api/jobs/{id}` → `chunks[].chars` 与 `chunks[].seconds`），**绝不能手拼**。
   我曾 2018 字(seg0) ÷ 496 秒(full.txt) = 4.07 → 误判「偏慢 51%」；
   正确值 4143/495.82 = **8.36**（与 EL 8.37 几乎一致）。→ **员工的耳朵是对的，机器的口径是错的。**
3. **至少 2 篇不同文案**（防样本级异常）。
4. **至少 1 篇 ≥5 分钟真长文**。
5. 才谈频谱/韵律。
🔴 语速口径已犯两次相反方向的错（一次没量、一次算错），务必按 1~2 条来。

## 样本与尺子的历史坑（引用旧数字时必须标注口径）
- 🔴 **8197d9ac8a35 是异常样本**：全批次 11.5~11.75 字/秒（EL 8.37，超 37%），
  2037 字只有 173~185s。据此推出的"asetrate 搬走低频"不成立。
  只能用于「变调/漂移」这类相对比较，不能当频谱基准。
- 🔴 **`probe_g.py` 曾硬编码 `y[:60*16000]`**：历史上所有 Σz² 都是「前 60s」口径，
  同一份成品换切片 Σz² 在 **211~877**（4 倍）。**凡引用历史 Σz² 必须标注口径。**
- 🔴 **目标不是 Σz²→0**：EL 标杆自己就是 17~240（中位 59.6）。正确目标是**落进 EL 分布**（`--ref`）。
- 🔴 **σ 会被离群值撑大 9.6~26.8 倍**：门槛一律用 `MAD×1.4826`（`sd_robust`），`--sigma naive` 切回。
- 🔴 **自洽性硬门槛**：同配置同文案连跑 3 次看散布；**散布 > 改动收益时，任何单次对比都不该下结论**。
- 🔴 flat 只有一种合法口径 = `tools/probe_g.py`（ffmpeg 转 16k + 前 60s + hop256）；
  自写脚本数值差 30%（0.0372 vs 0.0487），只配做分段定位。

## 已定案的技术结论（别再试）
- **F0 必须单独验收**，campplus 看不见音高（变调前后只差 0.004）。
  VoxCPM2/Qwen 男声 F0 系统低 15%（168~172 vs EL 197.7）；女声正常（277 vs 271~282）。
  基线 `DEFAULT_F0 = {"f":276.0,"m":197.7}`（pyin/16k）。诊断 `deploy/naturalness.py`。
- 🔴 **F0 要按沿时间轴的曲线**：VoxCPM2 长篇往上漂 +11%（170→193），EL 是平的（极差 13~19Hz）。
  全局变调会让后半段被抬到 222~233Hz（发尖/发假）→ **必须分窗变调**（每窗按自己 F0 算比例、1:2:1 平滑），成品极差 12.5Hz。
  参考音频无罪（prompt_yohan 自身 196.1=EL），是引擎压低 13.5%，别换参考切片。工具 `deploy/f0_drift.py`。
- 🔴 评估分窗处理，测量必须全篇或中段，**不能只测前 60s**（前 60s 恰是最坏样本，会完全掩盖收益）。
- 🔴 **变调只用 `asetrate+aresample+atempo`，禁用 rubberband**（rubberband 压掉平坦度 0.050→0.035 发假；
  formant=preserved 更糟 0.015 发闷）。三步缺一不可，漏 atempo → 时长被压短 1/R。
- 🔴 语速锚点**只用字/秒**，不许用「音节核/秒」；`--el` 逐窗对齐跨引擎不可用（实测快 6.8%）。
  一律 `fix_chain.py --target-cps <值> --chars <字数>`。
- 🔴 **60–150Hz 变调后补不回来，EQ 无解**（任何 lowshelf/peaking 都连带抬 150~300Hz 40%+，那里已偏多）。
- 现役男声 EQ：`equalizer=f=800:w=1.2:g=-2, highshelf=1500:+2.5, highshelf=2500:-1.5, highshelf=4000:-9.5, lowpass=14000`（未变调时 4000 档用 -4）。
- 候选 EQ（+262Hz）**已决定不上线**：离线 Σz² 683→108，但员工在开头/中后段给出相反答案 → 听不出。
- 🔴 女声成品只生成文案前 1500 字（`gen_female_prod.py`）；别拿它跟 EL 全篇比时长。
- 🔴 女声变调保持 asetrate，不要换 PSOLA（pitch tier 覆盖率不足，Σz² 35 差于 26）。
- 🔴 韩语数字不能用 whisper-small 当证据（同一句三版全被读成「3600원」，一次「4만 600원」只是抖动）。
- 🔴 分块背锅已证伪：1 块 vs 2 块成品互相似 0.9947，只涨 +0.0125。
- **女声房间底噪已改 −62dB**（`TTS_ROOMTONE_DB_FEMALE=-62`）：原 −50dB 粉噪是女声 flat +4.73σ 唯一真凶；男声 −56 不动。
- 「闷」不在静态频谱轴上：HNR/质心/F1/F2 全部落在 EL 分布内。真问题是**时域组织**（断句停顿、长文一致性）与整体质感。
  长文跨窗极差%：4k~8k 我们 94.9% vs EL 31.9%（最严重）；150~300 我们 31.6% vs EL 11.9%；跨窗 Σz² 中位 783 vs 50。

## 🔴 卡顿/硬切（2026-10-15 第28~30轮，当前主战场）
**根因**：停顿处电平接近数字零（−85 ~ −146 dBFS）→ 听感「咔」。
真实停顿是低电平**但有环境声**。
| | 最陡落差 | 硬切(>60dB) | 全零帧 |
|---|---|---|---|
| EL 标杆(wav) | −25.3 dB | **0** | 0 |
| OmniVoice 1块 | −101.3 | 10 | 2 |
| 旧 VoxCPM | −183.9 | **22** | 64 |
→ 是编码链路系统性问题，不是换引擎引入的。
- ❌ 走过的弯路：填"严格为 0 的样本"、填"整帧绝对零" → 硬切反而不变/+1（因为硬切处是**极低但非零**）。
- ✅ `app/declick.py`（已上线）：对 <−72dB 的连续段（≥2ms）补粉噪，1ms sin 淡入淡出，**不改时长**。
  硬切 10→0、最陡 −101.3→−30.7dB（EL −25.3）、Σz² 166.0→149.7。
- 🔴 **插入位置必须在 `if _rt_db is None:` 之前**（OmniVoice 属 `NEW_ENGINES` → `_legacy_post=False` → 走快路径绕开 roomtone）。v1 插错位置导致完全没生效。
- 🔴 **mp3 会抹掉硬切**（-154.9dB → -41.1dB 经 libmp3lame）→ 验证/给员工听的 A/B 素材必须 **wav**。
- 🔴 **「响度归一会把硬切抹平」是错的**（第30轮实测纠正）：`emit()` 用的是**静态**
  `volume=XdB`，只改整体增益、相对落差不变。实测归一后旧源仍是 `硬切5/真零29/最陡−209.3dB`。
  真凶是 mp3。**对照题既要 wav 又要归一**，否则员工会按「哪个声音大」选。
- **第二来源：停顿起伏不足**（换引擎引入）。σ（10ms 帧电平）：EL 6.83~7.84、旧 VoxCPM 7.84（=EL）、**OmniVoice 2.87**（掉到 1/3）。
  整体分布：处理前 14.20 / EL 13.19 / 当前 declick 后 **7.99** ← 仍偏低，待精调。
- 🔴 **起伏不能用慢调制**：慢周期 0.55~2.9s，而停顿段中位只有 **0.07s**，装不下 → 必须用宽带随机噪声。
- 🔴 EL「σ=13.19dB」是**帧与帧之间的总分布宽度**（5%=−89.6 → 95%=−46.6，跨度 43dB），不是段内慢起伏。别再按段内起伏去设计。
- 填充电平校准史：−70 太轻（无贡献）→ −57 太重（压掉原有起伏，σ 掉到 5~6）→ 现 −66。
  **下一步（进行中）：只补真正接近数字零的样本点，不做整段替换**（用逐样本幅度下限 `max(|原|,|噪|)`），保住原有 14.20 的起伏。

## 反馈台出题：三道闸 + 自检链（用户三次纠正后定案）
> 「反馈的目的是为了更好的优化语音，不要为了反馈而反馈」
> 「结合每一轮的题录，员工反馈后都要对应调整，更新题库，再让员工反馈，形成闭环」

**三道闸**：
1. ❌ 不许有兜底选项（"以上都不像"/"说不上来"当唯一出口）。实测：第23轮 3/3 全选兜底 = 信号作废；第24轮换成具体现象 → 立刻拿到 2/2 具体答案。
2. ❌ 不许有纯文字题（既无选项音频也无 ref）= 废题。`mk_*.py` 完整性自检会拦。
3. 🔴 不许有「答完不知道要改什么」的题。**每题先自问「拿到答案我要改什么？」，答不出来就别出。**
   据此删过：差距大不大 / 哪个引擎最接近 EL / 多引擎排序。
4. 🔴 A/B「有没有」型题必须提供「两个都有」「两个都没有」（第29轮员工写了「都卡顿」却没这选项）。
5. 🔴 同维度 A/B 语义必须一致（A 恒为"我们的"）。
6. 🔴 定位类题给员工听的必须是**当前线上原状**，不能是未上线的候选版。

**自检链（固定顺序）**：
0. 动作闸（每题要改什么）
1. md5 自检 —— 撞车就是废题（控制题除外，靠 `-metadata title=` 分字节）
2. LUFS 回读 —— `volume=%gdB` 不是 `%gdBB`（多一个 B = +18dB，全爆表）
3. 题目完整性
4. `GET /api/fb/where` 看 `missing` 必须为空

**统计**：取每人最新一条 + 累计题数（有人分两次提交）；未答完的不算有效；
控制题答非 C → 整份作废。控制题措辞「这两段听起来有区别吗」已连续 2 轮 2/2 正确；
旧的「哪段念得更快」2/4 答错，别再用。
✅ 保留「能否直接发客户」验收基线题作长期锚点：**连续三轮 13 张票全选 EL**，哪天出现「我们也能发」才算真进展。
`tools/fb_loop.py` 闭环台账（`--archive <suf>` 存 `items_round{n..v}.json`）。
