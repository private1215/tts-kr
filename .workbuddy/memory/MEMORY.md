# tts-kr 项目索引（精简版）

## 核心目标
替代 ElevenLabs（**EL**）省钱。验收：同一条韩语文案，我们 vs EL，员工听不出差别。
- 案例库 36 条**全是 EL 生成**，不是真人录音。仅 2 个声音：SOLA 女 22 / yohan 男 13。
- `EL_male`/`EL_female` = 从 EL 提取的 15s 标杆参考。**音色源 == 质量标杆**，别拆开找。
- 员工只做：上传文案 + 选男/女。零调参。
- 循环：自检→修复→验证→更新题库→同步服务端并核对→Git 提交。不承诺指标=1；不用开卷（`1a6c20a60481`/`00b6a45ad6aa`）替代跨文案验收；实验配置与已验收生产分开。

## 🔴🔴🔴 分级验证铁律（用户两次纠正后定案）
> 「短文案语音肯定都漂亮，长文案语音稳定才是实力」/「先短片过关，再优化长篇，直接上长篇不合理」

| 级 | 长度 | 能判什么 |
|---|---|---|
| **L1 快筛** | 15~30s | 改动**有没有生效**、链路通不通（每次改动都跑） |
| **L2 短篇** | 60~120s | 方向筛查（跑 3 次取中位） |
| **L3 长篇** | ≥3 分钟，最好 ≥5 分钟 | ✅ **唯一可信的质量验收** |

- **验收只用长篇；调试先用短片筛。禁止跳级。** L1 = A/B 相对比较看中位数，不是单次绝对分。
- 短片不能当验收依据：同配置 18s 连跑 7 次 Σz² = 190~**753**（波动 4 倍）。🔴 拿短片调高频 = 照假数据改。
- 闸门 `tools/gate_l1.py`：时长 8~120s / Σz² 中位<4000 / 4k~8k 比值>0.45 / N 次散布<3.0。实测拦下过。🔴 不是摆设。
- 长篇看**一致性**不看点值：`probe_g.py --segments`（跨 30s 窗极差%/CV%/跨窗 Σz²，跳过首尾 5%）。默认 `--full`，`--head60` 复现旧口径，<180s 会警告。

## 🔴 分析前强制顺序（动手前必读）
1. **先量语速（字/秒）** —— 最便宜、最能证伪。锚点 EL：女 **7.45** / 男 **8.37**。
2. 🔴 **字数与时长必须取自同一条 job 记录**（`GET /api/jobs/{id}` → `chunks[].chars`/`seconds`），**绝不能手拼**。
   曾 2018 字(seg0) ÷ 496 秒(full.txt) = 4.07 → 误判「偏慢 51%」；正确 4143/495.82 = **8.36**。
   → **员工的耳朵是对的，机器的口径是错的。**
3. 至少 2 篇不同文案（防样本级异常）。4. 至少 1 篇 ≥5 分钟真长文。5. 才谈频谱/韵律。

## 样本与尺子的历史坑（引用旧数字必须标注口径）
- 🔴 **8197d9ac8a35 是异常样本**：11.5~11.75 字/秒（EL 8.37，超 37%）。只能用于变调/漂移这类相对比较，不能当频谱基准。
- 🔴 `probe_g.py` 曾硬编码 `y[:60*16000]` → 历史 Σz² 全是「前 60s」口径，同一成品换切片 211~877（4 倍）。
- 🔴 **目标不是 Σz²→0**：EL 自己就是 17~240（中位 59.6）。目标是**落进 EL 分布**（`--ref`）。
- 🔴 **σ 会被离群值撑大 9.6~26.8 倍**：一律用 `MAD×1.4826`（`sd_robust`），`--sigma naive` 切回。
- 🔴 flat 只有一种合法口径 = `tools/probe_g.py`（ffmpeg 转 16k + hop256 + n_fft2048）；自写脚本差 30%，只配做分段定位。
- 🔴 **平坦度必须标注「前 60s」还是「全篇」**：前 60s 对我们是最坏窗（我们 0.0358<全篇 0.0387；EL 0.0493>全篇 0.0433）→ 前 60s 放大差距。全篇只差 1.12 倍。
- 🔴 `t_cur.wav` 是 **553.6s 旧版**，不是 496s 生产版。别拿它比。

## 已定案的技术结论（别再试）
- **F0 必须单独验收**，campplus 看不见音高。基线 `DEFAULT_F0={"f":276.0,"m":197.7}`（pyin/16k）。诊断 `deploy/naturalness.py`。
- 🔴 **F0 按时间轴分窗变调**（默认 `--pitch-win 15.0`）：引擎长篇上漂 +11%，全局变调会把后半段抬到 222~233Hz（发尖）。参考音频无罪（prompt_yohan 自身 196.1=EL），是引擎压低 13.5%。工具 `deploy/f0_drift.py`。
- 🔴 评估分窗处理，**测量必须全篇或中段**，不能只测前 60s（会完全掩盖收益）。
- 🔴 **变调只用 `asetrate+aresample+atempo`，禁用 rubberband**（压平坦度 0.050→0.035 发假；formant=preserved 更糟 0.015）。三步缺一不可，漏 atempo → 时长被压短 1/R。
- 🔴 语速锚点**只用字/秒**，不许用「音节核/秒」；`--el` 逐窗对齐跨引擎不可用（快 6.8%）。一律 `fix_chain.py --target-cps <值> --chars <字数>`。
- 🔴 **60–150Hz 变调后补不回来，EQ 无解**（任何 lowshelf/peaking 都连带抬 150~300Hz 40%+）。
- 🔴 女声成品只生成文案前 1500 字（`gen_female_prod.py`）；别跟 EL 全篇比时长。女声变调保持 asetrate，别换 PSOLA。
- 🔴 分块背锅已证伪：1 块 vs 2 块互相似 0.9947，只涨 +0.0125。
- 女声房间底噪 −62dB（`TTS_ROOMTONE_DB_FEMALE=-62`）；男声 −56 不动。
- 🔴 韩语数字不能用 whisper-small 当证据。

## 🔴 卡顿/硬切（第28~30轮）
**根因**：停顿处电平接近数字零（−85 ~ −146 dBFS）→ 听感「咔」。真实停顿是低电平**但有环境声**。
| | 最陡落差 | 硬切(>60dB) | 全零帧 |
|---|---|---|---|
| EL 标杆(wav) | −25.3 dB | **0** | 0 |
| OmniVoice 1块 | −101.3 | 10 | 2 |
| 旧 VoxCPM | −183.9 | **22** | 64 |
- ❌ 弯路：填"严格为 0 的样本"、填"整帧绝对零" → 硬切反而不变/+1（硬切处是**极低但非零**）。
- ✅ `app/declick.py`（已上线）：<−72dB 连续段（≥2ms）补粉噪，1ms sin 淡入淡出，**不改时长**。硬切 10→0、最陡 −101.3→−30.7dB。
- 🔴 **插入位置必须在 `if _rt_db is None:` 之前**（OmniVoice 属 `NEW_ENGINES` → `_legacy_post=False` → 快路径绕开 roomtone）。
- 🔴 **mp3 会抹掉硬切** → 验证/A/B 素材必须 **wav**。
- 🔴 「响度归一会把硬切抹平」是**错的**（第30轮纠正）：`emit()` 用静态 `volume=XdB`，相对落差不变。真凶是 mp3。**对照题既要 wav 又要归一**。
- **第二来源：停顿起伏不足**。σ（10ms 帧电平）：EL 6.83~7.84、旧 VoxCPM 7.84、**OmniVoice 2.87**。整体分布：处理前 14.20 / EL 13.19 / declick 后 **7.99** ← 仍偏低，待精调。
- 🔴 **起伏不能用慢调制**（慢周期 0.55~2.9s，停顿段中位只有 **0.07s**，装不下）→ 必须用宽带随机噪声。
- 🔴 EL「σ=13.19dB」是**帧间总分布宽度**（5%=−89.6→95%=−46.6），不是段内慢起伏。
- 填充电平校准史：−70 太轻 → −57 太重（σ 掉到 5~6）→ 现 −66。
  下一步：只补真正接近数字零的样本点（逐样本 `max(|原|,|噪|)`），保住原有 14.20 起伏。
- ✅ `app/pause_clean_v3.py` 已修：两处 `synth_tone` 曾共用 seed=42 → ~300 个停顿同一段噪声。已按位置派生 seed。

## 🔴🔴🔴 窄带滤波会摧毁「平坦度」（第31轮最贵的一条）
把 `MALE_250` 也做成自适应迭代后，平坦度 **0.0470 → 0.031（−33%）**，Σz² 23.9 → 29.7~36.8。已回退固定 −0.45dB。

- 机理：`平坦度=几何均值/算术均值`，几何均值对近零频点极敏感，陷波一深分子就塌。

## 反馈台出题：三道闸 + 自检链（用户三次纠正后定案）
> 「反馈的目的是为了更好的优化语音，不要为了反馈而反馈」
> 「员工反馈后都要对应调整，更新题库，再让员工反馈，形成闭环」

**三道闸**：
1. ❌ 不许有兜底选项（"以上都不像"/"说不上来"）。第23轮 3/3 全选兜底=信号作废；第24轮换具体现象→立刻 2/2。

3. 🔴 不许有「答完不知道要改什么」的题。**每题先自问「拿到答案我要改什么？」**。据此删过：差距大不大/哪个引擎最接近 EL/多引擎排序。
