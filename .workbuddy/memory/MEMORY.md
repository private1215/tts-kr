## 目标
替代 ElevenLabs（**EL**）。验收：同文案我们 vs EL，员工听不出差别。
- 案例库 36 条全是 EL 生成。`cases/<id>/merged.wav` = EL 原声（不是真人），**EL 基线一律取它**。
- 仅 2 个声音：SOLA 女 / yohan 男。员工只做上传文案+选男女，零调参。验收只看长篇。
- 🔴 物理上量到的差异 ≠ 员工能听到的差异（z44：13dB 改动，9 票仅 1 票指向修后）。
  **定根因前必须先出裁决题验证可闻性**。

## 测量口径（不统一就作废）
| 指标 | 铁律 |
|---|---|
| click | **先归一到峰值 0.70** 再判 `\|Δ\|>=0.30`（阈值绝对，不归一=比谁声音大）；🔴 **且必须无条件重采样到 16k**——`clickpos48.py` 曾写成「只对非 .wav 转码」，导致案例库 EL 的 `merged.wav`(24k/48k) 按原采样率算，click 次数只有 16k 口径的 1/13，据此前我误报「我们是 EL 的 26 倍」（真值 2.0 倍）。**跨格式比 click/频段类指标，一律先 `-ar 16000`** |
| 杂音（静音段 4-8k 占比） | **统一降到 16k** 再算 |
| 音色 | campplus 16k，同人阈值 **0.75**，同素材同长度、与 `merged.wav` 比 |
| cps | 字数与时长必须取自**同一条 job 记录**，绝不手拼 |
| 语速 | 用**含空格**原始字符数。EL 锚点：女 7.45 / 男 8.37（案例实测 8.23） |
- σ 一律 `MAD×1.4826`；测量必须全篇/中段，不能只测前 60s。
- 单次 min 值 / 单点 dB **不可作判据**，5ms 帧 RMS 才有意义。
- 🔴 反馈台路由：页面 `/feedback`、音频 `/fb-audio/{name}`、题目 `/api/fb/items`、
  自检 `/api/fb/where`（**不是** `/ui/feedback`、`/fb/{name}`）。
- 🔴 前端选项是**单选**（选中先清所有 .sel），做不了多选；
  且**每个有 file 的 option 都渲染一个播放器** → 只让第一个选项带 file。
- 🔴 语速/cps 一律用**含空格**字符数（`len(text)`）。用去空格会算出
  「GS 加速 35%」这种错误结论（实测含空格只有 +10~13%）。
- 🔴 `pkill -f "xxx"` 会连**自己的父 shell** 一起杀（bash -c 命令行含同样字符串）
  → ssh 断连、exit 255、后续命令无回显。用 `pkill -f "[x]xx"`。
- 🔴 脚本缓存文件名必须用**全路径 hash**（男女标杆都叫 `merged.wav`，否则男声被拿去比女声标杆）。
- 🔴 产物目录查找必须**优先精确匹配**：`glob(title+"*")` 会让 `gs48m_post` 匹配到 `gs48m_post2`。
- 🔴 **找「多出来的音」别用绝对 dB 阈值**：会卡在中间地带（实测 22.79s 的 −33.0 dB
  既不算发声也不算静音，三个检测器各漏各的）。且**我们与 EL 的能量分布几乎一致**
  （发声帧中位 −19.4 vs −19.0~−19.3；深静音 p5 −53~−54 vs −53~−56）
  → 差异在**时序结构**，不在响度/动态范围，别再往响度方向查。
  **能量包络目视 + 声谱图比自动检测器可靠。**

## 🔴🔴🔴 停顿节奏 = 最大的「机器感」来源（第51轮图谱法证）

用户质疑「只要吐字发音标准应该没问题」→ 拆图谱后发现**真正的差距在节奏，不在音质**：

| | 停顿数(全篇) | 中位s | 变异CV |
|---|---|---|---|
| EL 男 | 403 | **0.18** | **0.67** |
| EL 女 | 367 | **0.16** | **0.71** |
| GS 男 | **116** | 0.34 | 0.56 |
| GS 女 | 284 | 0.32 | 0.60 |

- EL：**短促 + 长短多变**；GS：**长 2 倍 + 更统一**，男声停顿次数少 71%
- 🔴 click / 音色 / 杂音 / CER **没有一项覆盖停顿结构** → 这就是 z20「GS 客观
  全面占优却被判 0 分」的答案。**CER 只衡量念对字没有，与像不像人无关。**
- GS 服务端 `SEG_GAP_SEC=0.30` 每段插 `np.zeros()` 是**次要**因素（去掉后时长
  -2.4s、消掉 0.66s 超长停顿，但句末仍有 0.36s vs EL 0.14s）——GS 模型本身韵律如此。
- 现役男声则相反：**停顿接近 EL，是音色发闷**（质心 1534 vs EL 1794，-14.5%；
  中频 1k-3k 占比 14.1% vs 21.7%，-35%）→ 员工 z21 选「机器音」与此吻合。
→ 工具：`tools/pauseforensics.py`（停顿法证）、`tools/z20_forensics.py`（频谱/F0/HNR）

## 已证伪（别再试第二遍）
**杂音/click**：mp3 编码（EL 压 192k 后 click 反而降）、亮度/同带宽、重采样 24k→16k、

（要求 `_legacy_post=True`，快路径没跑）、declick（click 100% 在发声中）、重复说话、

全篇变差）。真正生效的是整条极简后处理。
🔴 atempo **加速**会触发自适应 EQ 反向补高频 → 嘶声爆炸（男声 11.077→35.986）。
**断句异声**（员工三批都提，八条修复全败）：多念字、音高拔高、短音变多、局部顶起过多

句末淡出、元音起音柔化、分段压顶起、迭代压顶起、连续平滑增益、句末突起压制。

## 变调吃掉音色
EL 上限 0.9628 → 裸推理 0.8530 → 变调后 **0.6739**（损失 62%）。机理：asetrate 把 F0 和
**共振峰**一起搬，共振峰=说话人身份。变调只用 `asetrate+aresample+atempo`。
剩余缺口在**引擎** → 下个大动作 = GS 微调（36 条 EL 案例当 SFT 集，`GS_AUTO_TRAIN=1`
北京凌晨 3 点跑）。同文案全篇实测 GS 0.908 > 现役 0.858。

## GS 硬坑
1. **参考音频必须 3~10 秒**（15s 的 `EL_female.wav` 走 /api/jobs 一律 500）。
   ✅ 10s 的 `prompt_sola_00b6a45a.wav`（×EL_female 0.7953 同人）。
   ⚠️ `elara.wav` 0.3424 = 不同人，**绝不能当 SOLA 参考**。
   ⚠️ 加音色不影响员工侧：`BEST_CLONE` 写死 `{"male":"EL_male","female":"EL_female"}`。
2. **产物目录会被加 `-N` 后缀**（`_unique_dir`），按无后缀标题 glob 会抓空 → 用 `find_out_dir()`。
3. 🔴🔴 **参考音频与 ref_text 必须严格对齐、切在句边界**：
   **GS 输出语速 ≈ 参考音频隐含语速（ref_text 字数 ÷ 音频时长）**。
   16.0字/s→1.98；7.34→6.45；6.75→6.75；8.87→7.45。
   ref_text 比音频长 → 语速崩 + **把参考文本当正文反复念**（CER 0.66）= 员工报的
   「说话慢+乱说话」共同根因。✅ 男声定案 7.55s/51字/6.75字每秒（×EL_male 0.9134）；
   男声快版 `yohan_gs_f8` 6.20s/55字/8.87（0.9184）。
   🔴 epoch 必须 **≥40**（e10 男女声全崩 CER 0.66~0.69）。
4. 🔴🔴 **换 GS 上线必须先过「15 秒参考音频」这一关**：
   员工默认音色 `BEST_CLONE = EL_female(15.08s) / EL_male(14.98s)` **都超限** →
   默认引擎一切到 gptsovits 就是**全员 HTTP 500**。实测 15.08s→500、10.00s→200。
   ✅ 已修：`TTS_GS_REF_MAP=EL_female=SOLA_gs10,EL_male=yohan_gs_f8`
   （`deploy/patch_gsref50.py` + `deploy/qwen-tts-gsref.conf`，值是**音色名**不是路径，
   path+ref_text 都取自 voices.json，与实验素材逐字一致）。
   只在参考音频 >10s 时才换；不设该变量 = 行为与打补丁前一致。
   验证：`tools/verify_gsref50.py`（默认音色 + engine_force=gptsovits，女 CER 0.023 / 男 0.057）。
5. 🔴 **训完的新权重默认不会被加载**：`gs_serve.py` 的
   `pick_weight(spk, ep or EPOCH_DEFAULT)`，`GS_EPOCH=40` → 只要有 `*_e40_s*.pth`
   就**永远返回 e40**，新训的 e50 轮不上（训完必须改 GS_EPOCH 或移走旧 e40）。
   `save_every_epoch=10` → e52 只落盘成 e50。
   ✅ 按 epoch 对比的写法：`spk="yohan@50"`（`spk` 支持 `名字@epoch`）。

## CER 判读
whisper-small 会把韩语数字规范化 → **念对了但 CER 高**。CER ≥ 0.15 **必须 dump ASR diff**：
全是数字写法差异 = 通过；出现**大段 insert**（反复念参考文本）= 真乱说话。阈值 `TTS_ASR_CER=0.35`。
- 女声本篇 CER 0.0384 → 数字归一化补丁**实测收益 0.0000**（已上线但别指望提速）。
  真假错主力是 **영문약어（MLCC/AI/RD）和 전화번호**，补丁刻意不覆盖。
- 不转：시/분/초（钟点读法不定）、개/명/배（**固有数词**）、裸数字。
- 韩语月份异读：6월=유월、**10월=시월（不是 십월，用户纠正过）**、11/12월=십일/십이월。
- 慢 3 倍的真因是 **CER 重掷**（`ASR_MAX_RETRY=2`），不是归一化。

## 反馈台出题铁律
> 「反馈是为了更好优化语音，不要为了反馈而反馈」「形成闭环」
1. ❌ 兜底选项。2. ❌ 纯文字题。3. 🔴 每题先自问「拿到答案改什么」，无对应操作就不出。
4. A/B「有没有」题必须有「都有/都没有」。5. A 恒为我们的。6. 定位题必须当前线上原状。
7. 🔴🔴 **普通人原则**：不许让普通人在多段不同内容里排名。
8. 🔴🔴🔴 **盲听铁律**：选项**不许标「我们的/EL/标杆/参考/标准」**，身份只在服务端 `note` 记。
9. 跨成品 A/B **必须先按文本对齐**（`tools/alignchk48.py`，相似度 ≥0.55）。
10. 控制题：同一段放两次，选①或② → 本轮作废。
- 自检链：动作闸→md5→LUFS 回读（`volume=%gdB` 不是 `%gdBB`）→完整性→`/api/fb/where` missing 空。
- 🔴 `items.json` 必须是 `{"items":[...]}`，裸 list 会让 `/api/fb/where` 崩、**反馈台打不开**。
- 多批次：先落 `items_z<N>.json`，切换时再 cp，别覆盖还在收票的。
- 统计：取每人最新一条；控制题答错整份作废。
